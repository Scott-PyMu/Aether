## §1 总体结论

- **文档完整性**：决策（§2）/硬约束（§3）/实现落点（§4）/影响面（§5）/回退条件（§6）/验证（§7）齐备。缺口：无独立「主要风险/缓解措施」小节，风险表述散布于 §2.6/§3/§6（P2-1）。
- **一致性状态**：与设计文档 v1.17、需求文档、P1 计划、ADR-002 全部对齐；实现与 ADR 逐条一致；证据链（单测 → 夹具 → 真实 DSH E2E → 回归）完整可复核。
- **最大风险**：`session.create.system_prompt` 的**注入生效状态对核心不可观测**——侧信道写失败（磁盘异常/目录未初始化）时适配器静默继续（按 §2.3 设计），核心与测试无法区分「已下发+已生效」与「已下发+未生效」，且与 §6 回退 1「不得假装注入成功」口径存在张力（P1-1）。
- **结论**：有条件认可。整改项（§6）均为小步修订：ADR-027 就地升版 v1.1 + 适配器失效分支 payload 扩展，不涉及命令面/错误码/迁移/事件。

## §5 待确认问题与裁定（2026-10-20，产品/用户已逐项裁定）

| # | 原待确认 | 裁定 | 承接 |
|---|---|---|---|
| 1 | `has_system_prompt` 二态（仅表示已下发）还是三态（补生效位） | **三态**：保持 `has_system_prompt` 语义不变（向后兼容，既有 22 个适配器单测与 `m7_09_presets.rs` 断言不破坏）；新增 `system_prompt_effective?: boolean \| null`（null=未下发 / true=侧信道写入成功 / false=写入失败或目录未初始化）。属 D6 允许的 payload 只增字段（设计 D6 `:431`「跨 `v` 版本允许新增字段（只增不改语义）」），不新增命令/错误码/迁移 | §6-1 |
| 2 | 侧信道提示词明文副本是否会进入 DS-05 P1 自动备份范围 | **备份不覆盖该目录**（产品确认）。原评审中该项风险解除；ADR-027 §2.6「正文不进日志/审计/诊断包」口径自洽，无需与 ADR-020 联动 | §6-2（顺手留痕，非阻塞） |
| 3 | 配置了预设的会话启动/恢复时核心会重新下发提示词，启动清理（`clearPromptDir`）是否还需要 | **保留清理**。理由：① 无竞态——插件 `text` 为惰性读取（每次 assemble 才读文件），assemble 最早发生在首个 `session/prompt`，晚于 `session.create` 返回与文件重写（`dsh-adapter.ts:661-688`），「先清空 → 核心重新写入 → 再组装」时序安全；② 不清理才有害——dispose 失败/崩溃残留对应「本次不再恢复」或「同 id 恢复但未下发」两种情形，后者旧提示词会被静默注入，违反 D14 `:624`「禁止静默覆盖」；恢复路径的同 id 显式清理（`dsh-adapter.ts:684-687`）是防线，启动整目录清理是兜底；③ 唯一需调整场景为多 profile（见 P2-2）：清理作用域改 per-profile/per-instance，届时按 P1 计划 `:466` 惯例走评估记录/ADR | §6-2（登记检查项） |

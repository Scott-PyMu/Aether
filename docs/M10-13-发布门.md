## 2. 升级计划

1. **UI**：已升级（v0.21）。`contract_version === 2` 时使用 v2 进度文案；否则走旧 daemon 兼容分支。
2. **外部消费者**：发布说明要求升级到读取 `contract_version`、`planned_shards`、`skipped_shards`、`full_coverage`；只读旧字段的客户端保持可运行，但不得将 `state=ok` 解释为“8/8 全量通过”。
3. **CLI/API 文档**：OpenAPI/JSON Schema 已由 `aether-app`/`aether-daemon` 生成器同步（`pnpm verify:api-schema` diff=0）；不新增命令、事件、设置键、迁移。
4. **回退**：UI 可回退到旧 daemon 兼容分支（fixture 已覆盖）；daemon 侧 v2 字段为增量，不回退字段语义。若外部消费者无法升级，按其自身发布节奏声明“仅支持 v1 字段，不承诺全量判断”，不得声称 v2 能力。
5. **发布说明**：见 §4；G13 报告引用本节。

## 4. 发布说明（`health.storage_check` v2）

- `health.storage_check.contract_version = 2`；新字段为增量：`planned_shards`（本轮计划检查的分片数）、`skipped_shards`（未变化且本轮跳过的分片数）、`full_coverage`（本轮是否覆盖全部分片）。
- `checked_shards` / `total_shards` 仍保留，只表示**本轮实际完成**的分片数；`state=ok` 只表示本轮计划完成，**不等于全量覆盖**。
- 仅当 `full_coverage=true` 时才可宣称 8/8 全量通过；选择性启动（如 1/7、2/6）不得显示 8/8。
- 旧 daemon（无 `contract_version`）：客户端必须走兼容分支，不得显示“已跳过 N”，不得声称全量。
- 启动指标：`startupCheckCompletedAt` 仅用于**启动检查完成**（25s/30s 门禁）；`fullCoverageCheckCompletedAt` 为**后台/周期全量完成**，信息性，不与 25/30s 启动门禁混用。
- 设备边界：NVMe 8 并发参考矩阵全部通过；SATA SSD 4 并发 dirty8 冷 P95 39.95s、HDD 热 93.5s 作为支持边界，按 G13 裁定（见 `docs/M10-Gate-G13-报告.md` §5）。不得以 NVMe 结果替代低并发/HDD 结论。
- 命令面 87、`IpcErrorCode` 32、业务码 35、设置键 11、迁移 0014 均不变；无新事件/迁移。

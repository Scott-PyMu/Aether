## 1. 结论说明

### 1.1 已确认的部分

- ADR v0.3 已覆盖上一轮 P0×2/P1×7 的主要方向：应用级 token、无 legacy 回退、`provider_id` 必选、端点补全、仅 `tracing`、M7-10 登记、应用级 E2E DoD。
- 迁移 `0009` 不变；不新增 IPC 命令、事件、错误码；D4/D9 不变；信任边界措辞未把权限门误写成沙箱。
- §4 实现落点的“已落地/待整改”与当前代码基本一致。
- 用户已明确接受/裁定的 10 项问题，按 §2 记录；其中安全风险为“暂定接受”，正式发布前仍需产品/安全负责人签署。

### 1.2 仍未闭合的部分（P0）

1. **三文档基线未同步**：设计 v1.18 仍冻结 v0.2 语义（一次性 token、`provider_id` 缺省旧路径）；需求 v0.12 未登记多供应商；P1 计划 v0.7 仍标 M7-10“Phase 1 完成”。
2. **全运行时多供应商的新增设计工作**：用户裁定所有官方 Agent 都支持多供应商选择；Codex/DSH 的配置物化（Codex `CODEX_HOME/config.toml`、DSH profile）是进程级/全局配置，必须补充 per-session 方案，否则该裁定不可执行。
3. **应用级证据缺失**：`m7_10_provider_e2e.rs` 与 `docs/M7-10-证据.md` 不存在；现有证据为 adapter/broker 级，不能证明命令层双会话、fail-fast、轮换与只读语义。
4. **共享 token 仅为“暂定接受”**：需在 ADR §9 记录暂定接受事实、日期与触发 per-adapter token 的条件；正式发布前仍需有权人签署。

### 1.3 最大风险

- **范围风险**：从 Claude 单运行时扩展到三运行时，M7-10 的配置物化、并发隔离、E2E 工作量显著增加；不得沿用原“Claude 先行、Codex/DSH 后续”的口径。
- **基线风险**：设计 v1.18 与 ADR v0.3 双口径；修改者必须先落 v1.19/v0.13/v0.8，再改代码。
- **安全边界风险**：端点由用户输入、不做特殊保证，意味着 key 可能被发送到用户指定地址；必须在 ADR §2.3 作为已接受风险写明，不能继续宣称“密钥不泄露”为无条件保证。
- **设置键风险**：用户要求“记在现有设置项”，但现有 8 个键无供应商记忆语义；修改者必须明确新增第 9 键或复用 `ui.layout`，不能静默塞入。

## 3. 裁定后的设计口径（必须写入 v0.4）

### 3.1 全官方运行时多供应商

- 适用范围：Claude Code、Codex、DeepSeek Harness 三个官方运行时；第三方适配器仍按 P3 处理，不在本期。
- ADR §2.2 删除“不在本期实现 Codex/DSH 的 per-session provider 切换”；§2.1-5 从“Claude Code 先行”改为“三运行时同步支持”。
- **Codex/DSH 的配置物化必须先设计**：
  - Codex：`CODEX_HOME/config.toml` 当前是进程级物化；并发会话使用不同 provider 时，必须改为 per-session home/配置或等价 CLI 覆盖，避免并发写同一文件。
  - DSH：profile/provider 配置当前是进程级/启动级；必须验证 ACP `session/new` 是否支持 per-session provider，或采用 per-session profile 目录；不得让两个并发会话共享同一 profile。
  - 若上述在 P1 内不可行，修改者必须回到用户处重新裁定范围/工期，**不得静默退回“Claude 先行”**。
- M7-10 量级需重估：不得沿用原 L 量级不说明；若仍定 L，需在证据中说明三运行时 E2E 与配置隔离的工作量。

### 3.2 静态能力声明

- `multi_provider` 不再依赖 `hello`/runtime ready；在官方运行时静态清单或内置常量表中声明。
- 可选落点：
  - 扩展 `RuntimeManifest` 增加静态能力字段（需登记 ADR-015 增量）；或
  - 在核心内置常量表中按 `runtime_id` 声明（不改 manifest 结构）。
- 静态声明必须与适配器实现同批：不得先声明、后实现；否则 `session_create` 会要求 `provider_id`，但适配器无法消费。
- `hello` 可继续回显 `multi_provider`，但 `session_create` 的必选判定以静态声明为准；D6 line 429 的“判定时机 = runtime ready 后”需增加例外说明。

### 3.3 目录查询接口

- 新增非机密供应商目录查询接口，建议名称 `provider.catalog.get`（最终名称由 v0.4 D6 登记）。
- 方向：adapter → core 的 JSON-RPC 请求/响应；若实现者认为新增方向代价过高，可改为 core 在 `session.create` 中附带目录快照，但必须说明为何不满足“即时刷新”。
- 响应只含非机密字段：provider id/name/type/enabled、`endpoints`、model 清单；**不得含 `api_key`、`api_key_ref`、token**。
- D6 登记内容：方法名、方向、超时（建议 5s）、帧上限（沿用 D6）、错误映射（沿用 `invalid_value`/`core_not_ready`）；线协议 major 不变，命令面 63 不变，事件/错误码不变。
- ADR §5.4“D6 方法表不变”改为“新增一个只读目录查询方法；帧上限/artifact_ref 契约不变”。

### 3.4 供应商选择与记忆

- 所有官方运行时：`session_create.provider_id` 语义必填；DTO 可保持可选以兼容旧调用，但运行时必须拒绝缺失。
- 用户选择优先；全局记忆预填视为“已选择”，用户可直接创建或修改。**不再要求每次手动点选。**
- 记忆落点：settings 机制、全局共享（跨工作区）；建议按运行时分别记忆（`agent → provider`），否则同一 provider 无法同时适配三种协议。
- 供应商失效：**不自动清空**；保留记忆值，UI 标记失效，禁止创建/发送，由用户自行重选；不得自动回退到其他 provider。
- 旧会话无 `provider_id`：按“未选择供应商”处理；历史消息可查看，发送前要求用户补选并持久化到 `sessions.config.aether.provider_id`；不得自动选。

### 3.5 停用/删除后的会话只读

- provider 停用/删除后，既有会话进入只读：
  - `messages_page`/历史消息正常；
  - `session_send`、`run_retry`、`session_resume` 拒绝；
  - 不自动切换 provider；
  - UI 禁用输入区并提示。
- 错误码沿用既有 `invalid_value`（请求级）或 `core_not_ready`（broker 未接线）；**不新增错误码**。
- 进行中的 run 是否立即中止，用户未明确；建议“不中止当前 run，后续 send/retry/resume 拒绝”，由修改者在 v0.4 写明。

### 3.6 安全边界（按用户裁定）

- **共享 token**：暂定接受应用级共享 token；ADR §2.3 保留残余风险、补偿措施与 per-adapter token 触发条件；§9 记录“2026-10-22 用户暂定接受”。
- **端点**：不做 HTTPS/主机白名单/端点可信保证；保留 `http(s)`、长度、控制字符基本校验；ADR §2.3 明确“key 可能被发送至用户输入地址，网络传输风险由用户承担”；UI 增加风险提示。
- **仍需保留的安全要求**（用户未取消）：
  - broker 校验 provider→protocol，不返回不兼容 provider 的 key（P1-1）；
  - Windows named pipe DACL / Unix socket 权限（P1-6）；
  - 所有官方适配器 CLI/工具子进程剥离 `AETHER_CREDENTIAL_BROKER`（P1-7）；
  - 每次 run 取密钥、不缓存；broker 只写 tracing，不落库。
- **不得**因为“端点由用户输入”而放弃上述 broker/子进程边界。

### 3.7 密钥扫描口径

- 扫描对象：
  - 非测试源码（排除 `tests/`、`*.test.ts`、`*.test.tsx` 等测试代码）；
  - 运行日志、诊断包、导出文件、证据产物；
  - 不得出现真实供应商 key、JWT、PEM 私钥。
- 合成/假测试密钥：
  - 仅测试代码/夹具可使用；
  - 使用可识别前缀/固定值，纳入显式白名单；
  - 白名单文件本身不得含真实 key。
- 证据文件记录扫描命令、排除项、白名单、0 命中输出。

### 3.8 UI 与文档登记

- 新增锚点（建议）：
  - `session-provider-select`（新建会话供应商选择，三运行时均显示）；
  - `provider-required-notice`（未选择/失效提示，创建按钮禁用）；
  - `provider-endpoint-preview`（供应商页端点解析预览）；
  - `session-provider-current`（会话当前供应商回显）；
  - `session-provider-readonly`（停用/删除后的只读提示）。
- UI-UX §7.3 计数从 15 组增至 20 组；§2.3 新建会话表单补供应商选择；§5 文案补 4 条；§8 P1 行更新。
- AGENTS §1 基线版本、P1 计划 line 8 的“直接实施项 M7-07/08/09”同步更新。

## 7. 遗留风险与需修改者明确事项

1. **设置键冲突**：用户要求“记在现有设置项”，但现有 8 键无供应商记忆语义。修改者必须在 v0.4 明确：
   - **方案 A（推荐）**：新增第 9 键 `ui.provider_selection`（string JSON，全局，按运行时映射 provider id）；同步 ADR-018 附录 A-6 与 ADR-028 §5.4“设置键 8→9”。
   - **方案 B**：复用 `ui.layout` JSON 增加 `providerSelection` 子字段；需定义 schema/兼容/大小上限，避免污染布局契约。
   - **方案 C**：WebView localStorage；不符合“现有设置项”裁定，不建议。
2. **目录查询接口形态**：方法名/方向/超时/错误映射由 v0.4 D6 登记；若采用 adapter→core 请求，需确认现有线协议是否支持该方向；否则退回 core 在 `session.create` 附目录快照，并说明“即时刷新”是否可接受。
3. **Codex/DSH 配置物化可行性**：若 per-session 隔离在 P1 内不可行，必须回到用户重新裁定范围/工期；不得静默退回 Claude 单运行时。
4. **进行中的 run**：provider 停用/删除时，是否中止当前 run？建议不中止、仅拒绝后续 send/retry/resume；需在 v0.4 写明。
5. **共享 token 正式签认**：本次为“暂定接受”；正式发布前仍需产品/安全负责人签署，或按触发条件转 per-adapter token ADR。
6. **“所有 Agent”边界**：本裁定按“三个官方运行时”执行；第三方适配器仍 P3，不纳入本期；若用户意图包含第三方，需另立 ADR/调整阶段。

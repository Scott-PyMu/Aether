## 2. DoD 逐条证据

### DoD1 策略矩阵断言

```
$ cargo test -p aether-security --lib
test result: ok. 50 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.10s

$ cargo test -p aether-control --test m2_03_permission
test policy_matrix_allow_deny_ask ... ok
```

覆盖断言：
- `fs.read`：工作区内 allow（canonical 前缀校验通过）；工作区外 deny；`..` 逃逸 deny；
- `fs.write`：工作区内 ask（进入 pending → `once` 授权 allow，scope=once）；工作区外 deny；
- `exec` / `net`：恒 deny（MVP 无执行/网络通道）；
- 记忆文件白名单：3 个文件名 `content_bytes = 1MB` allow、`1MB+1` deny；
- 审计动作齐备：`permission.allowed_by_policy` / `permission.denied_by_policy` /
  `permission.requested` / `permission.resolved`。

### DoD2 路径逃逸样本集 100% deny + 审计（T7）

```
$ cargo test -p aether-control --test m2_03_permission -- --nocapture
[m2-03-t7] textual=20 denied=20 audited=20 fs_samples=1 fs_denied=1 skipped=["symlink 创建不可用: 客户端没有所需的特权。 (os error 1314)"] denied_ratio=100%

```

检查分层（GitHub CI 首轮暴露后修正，见 §6）：
- **输入形态检查**（对原始 target 全量执行）：NUL/控制字符、UNC 与扩展前缀、ADS、
  drive-relative；
- **组件形态检查**（8.3 短名、保留设备名、尾随点/空格）：仅作用于 canonical 目标的
  「工作区内相对段」；工作区祖先路径中的短名（如 CI 临时目录 `RUNNER~1`）属可信环境，
  不误伤。

样本分类（`T7_TEXTUAL_SAMPLES`，全平台执行，本机 20/20 deny + 20/20 审计）：
`..` 穿越（绝对/相对/正斜杠）、UNC（`\\server\share`、`//server/share`）、扩展/设备前缀
（`\\?\`、`\\.\`）、8.3 短名（`PROGRA~1`、`DOCUME~1`）、ADS（`file.txt:stream`、
`file.txt::$DATA`）、尾随点、尾随空格、保留设备名（`CON`/`con.txt`/`COM1.log`/`LPT9`/
`NUL.txt`）、drive-relative（`C:secret.txt`）、NUL 字节。

文件系统样本（动态创建，逃逸目标为工作区外目录）：
- Junction（Windows `mklink /J`，无特权可建）→ 1/1 deny（本机执行）；
- 软链接：本机（Windows 未启用开发者模式）创建失败 → 显式记录
  `skipped=["symlink 创建不可用: 客户端没有所需的特权。 (os error 1314)"]`；
  在 Unix CI（`cargo test --workspace`，ubuntu）由 `std::os::unix::fs::symlink` 执行同一断言。
- 断言：`fs_denied == fs_samples`、`fs_samples >= 1`、文本样本 100% deny 且逐条审计
  （每条请求前后 `permission.denied_by_policy` 计数 +1）。

TOCTOU 限制（D9 显式声明，测试报告口径）：canonicalize 与文件操作之间存在检查-使用
竞态窗口；MVP 信任级接受该限制，P3 沙箱以句柄级校验消除。

### DoD3 审批流：pending 持久化；核心重启后待审批恢复；300s 超时 deny + 审计（时钟注入）

```
test pending_survives_restart_and_times_out_after_300s ... ok
test timeout_waiter_receives_deny_within_same_core ... ok
test session_bound_timeout_emits_deny_event ... ok
```

断言链：
- 请求 ask → `permissions` 行 `status=pending` 持久化（DB 查询）；
- 新服务实例（模拟核心重启）`restore_pending()` 恢复 1 条；
- `ManualClock`：+299.999s 不判超时；**恰好 +300.000s** 巡检判超时；
- 超时后行 `status=timeout`、`decision=deny`、不再出现在 pending 清单；
  审计 `permission.timeout`；等待者收到 `timed_out=true` 的 deny；
- 同核心等待者路径与重启恢复路径分别验证；重启后原等待者随旧核心退出（显式收尾）。

### DoD4 T6：100 次并发 ask 无丢失/重复/死锁

```
test t6_100_concurrent_asks_no_loss_no_duplication ... ok
```

断言链：100 个并发 `request`（不同 `request_id`）→ 内存 pending = 100 且 DB pending = 100
（无丢失）；并发决议 50×once-allow + 50×deny（`JoinSet`）→ 100 个等待者全部返回且
allow/deny 各 50（无重复/丢失）；pending 清空；重复决议 → `permission_not_pending`
（无重复决议语义）；用例在秒级完成（无死锁）。

## 4. 边界与偏离记录

1. **分层**：决策（策略矩阵/路径校验/审批票据）在 `aether-security`（纯模型，无 I/O，
   仅依赖 core）；持久化/审计/超时巡检/事件广播在 `aether-control`（编排层，经单写队列）。
   `aether-control → aether-security` 为新增内部依赖边（无环）。
2. **T6 并发口径**：服务层不限制同会话并发 pending（100 并发需全部可等待）；D9
   「同一会话最多 1 个待审批」为 UI 排队展示口径，由 M3 工作台呈现，不在服务层拒绝。
3. **`session` 授权作用域**：仅限具体 target（resource+action+canonical target 精确匹配）；
   进程内有效（会话为活跃概念，核心重启后失效）。
4. **组件形态检查范围修正（CI 驱动）**：见 §6；输入形态与组件形态分层，目标路径语义不变
   （T7 20/20 deny 保持），仅消除对可信祖先路径短名的误拒。

## 6. GitHub CI 复验记录（2026-09-20）

首轮（commit `0af2a32`，run `35509517748`）：12 个 job 中 11 个通过（含 Ubuntu
`Coverage gate`、三平台 `Adapters tests`、`Supply chain gate`）；唯一失败
`Tauri security baseline (M1-08)` 的 M2 批 1 步骤：

```
FAIL  期望=0 实际=101  cargo test -p aether-security --lib
FAIL  期望=0 实际=101  m2_03_permission
[failure] m2-batch1-assert: assertion failed: wait_for(|| { !harness.service.pending_list(None).is_empty() }, ...)
```

根因（对照测试断言定位）：GitHub Windows runner 的 `%TEMP%` 为 8.3 短名形式
（如 `C:\Users\RUNNER~1\...`）；旧实现把 8.3/保留设备名/尾随点空格等**组件形态检查**
施加在原始绝对路径的全部组件上，导致「工作区根自身位于短名目录」时，测试工作区内的
合法路径被误判 deny（ask 不进入 pending / allow 用例 unwrap 失败）。本机
`C:\Users\Lenovo\...` 无短名，故本地与 WSL 均未暴露。

修复：`PathGuard::resolve` 分层——输入形态检查（UNC/扩展前缀、ADS、drive-relative、
NUL/控制字符）对原始 target 全量执行；组件形态检查在 canonicalize 且确认工作区内之后，
仅作用于相对工作区根的尾段。T7 样本语义不变（`{root}\DOCUME~1\...` 仍 deny；工作区外
8.3 目标按逃逸 deny）。

本机复验（构造 `~1` 祖先路径模拟 CI 环境，`TEMP/TMP` 指向
`...\runner~1\sim`）：

```
$env:TEMP=...\runner~1\sim; cargo test -p aether-security --lib
test result: ok. 50 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out

$env:TEMP=...\runner~1\sim; cargo test -p aether-control --test m2_03_permission
test result: ok. 12 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out
```

## 2. Electron flags / CSP / 导航 / DevTools（DoD-1）

`apps/desktop/electron/security.ts`：

- `secureWebPreferences`：`nodeIntegration:false`、`nodeIntegrationInWorker/SubFrames:false`、`contextIsolation:true`、`sandbox:true`、`webSecurity:true`、`allowRunningInsecureContent:false`、`webviewTag:false`、`experimentalFeatures:false`；
- 生产 CSP：`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'none'; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`；
- 开发 CSP 仅额外允许 `127.0.0.1:5173`（Vite HMR）；
- `aether://app` 自定义协议逐响应下发 CSP；`resolveAppAsset` 防目录穿越。

`apps/desktop/electron/app.ts`：

- `app.on("web-contents-created")` → `hardenContents`（幂等；`browserView` 由 `BrowserHost` 按 §5.2 单独接线，`webview` 直接销毁）；
- `setWindowOpenHandler` 拒绝新窗口，http/https 交系统浏览器；`will-navigate` 只允许应用自身 URL；`will-attach-webview` 阻止；
- `setPermissionRequestHandler` 默认拒绝、`setPermissionCheckHandler(() => false)`；
- `certificate-error` 显式 `callback(false)`，不提供「继续访问」；
- DevTools 仅 `!app.isPackaged` 可用，生产禁用 F12/Ctrl+Shift+I；生产不开启远程调试端口。

## 3. preload / main RPC 防线 / daemon 校验（DoD-2）

### 3.1 preload 白名单

`preload.ts` 只 `contextBridge.exposeInMainWorld("aether", api)`，成员固定为：

```text
rpc / onEvent / offEvent / pathForFile / version
```

- `pathForFile(file)` 内 `webUtils.getPathForFile(file)`，仅返回字符串；
- 不暴露 `ipcRenderer` / `require` / `process` / `fs` / `child_process` / 任意 channel；
- 参数超过 2MiB 在 preload 先拒绝（main/daemon 仍复核）。

### 3.2 main 侧 RPC 防线

新增 `apps/desktop/electron/rpcGuard.ts`（纯函数，可单测），顺序：命令白名单 → 2MiB → 并发 64：

## 5. WebContentsView（DoD-4）

`apps/desktop/electron/browserHost.ts`：

- `new WebContentsView({ webPreferences: { ...browserWebPreferences(), partition } })`；
- `browserPartition(id)` = `persist:aether-browser:<id>`（非法 id 拒绝）；
- 无 preload、`sandbox:true`、`nodeIntegration:false`、`contextIsolation:true`、`webSecurity:true`、`webviewTag:false`；
- `web-contents-created` 在 `new WebContentsView()` 内同步触发；main 的统一加固延迟到 `setImmediate`，`BrowserHost` 创建后立即 `markBrowserContents(view.webContents)`，避免把主 UI 的 `aether://app` 白名单误套到浏览器视图（Electron 45 的 `getType()` 对 WebContentsView 仍返回 `window`，故同时以 partition 前缀兜底）；
- partition 级 `setPermissionRequestHandler(false)` / `setPermissionCheckHandler(false)` / `setCertificateVerifyProc(-3=默认拒绝)`；
- 页面导航仅 http/https；`window.open` 交系统浏览器且不创建新窗口；`file:/javascript:/data:/blob:` 拒绝；
- 下载：`will-download` 先写 `downloads/.quarantine/<id>.part`，状态 `pending`；**确认后**才 `promoteDownloadedFile` 移到最终路径；取消删除隔离区；文件名清洗（路径段/控制字符/设备名/长度）。

## 9. 未验证项（转后续门禁，不阻塞 M9-10 签字）

1. **下载字节落盘（DoD-4）**：本机 Electron 45 + Playwright `_electron`/`--no-sandbox` 下，Chromium 将下载标记为 `interrupted`（`receivedBytes=0`）。已排除本任务代码/安全处理器因素：`defaultSession`、全新 partition、临时目录、公网 URL（`https://www.w3.org/.../dummy.pdf`）均为同一结果。确认门（pending→confirmed/cancelled）、隔离区写入与「确认后移动到最终路径」由 `downloadFiles.test.ts`（3 项）覆盖；**打包产物（M9-11）与 G7 必须复跑真实下载**。
2. **macOS/Linux 证书与 WebContentsView 真机**：本机 Windows；E2E 覆盖自签证书拒绝与 partition 隔离，macOS/Linux 在 G7 平台矩阵复跑。
3. **Keychain 新签名身份 ACL（macOS）**：M9-09 已在 Windows Credential Manager 验证；macOS 在 M9-11 签名产物复跑（G5 入口条件）。
4. **`onlyLoadAppFromAsar` 在打包产物上的断言**：开发二进制复制体已验证翻转/断言工具；M9-11 在 `electron-builder` 产物上复跑。
5. **fuses 对 macOS 签名的影响**：翻转后需重新 ad-hoc/正式签名；M9-11 嵌套签名顺序覆盖。

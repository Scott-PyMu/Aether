## 2. DoD 逐项结果

### DoD-1 监听与鉴权

- 默认仅绑定 **`127.0.0.1`**（`DEFAULT_BIND`）；`::1` 需显式 `AETHERD_HTTP_BIND=::1`；`0.0.0.0`/非 loopback 一律拒绝（远程绑定需另立 ADR，M10 不实现）。
- `aetherd --stdio` 默认关闭 HTTP；`--stdio --http` 或 `AETHERD_HTTP=1` 开启；`--http-only` 强制开启且 listener 失败致命（退出码 **25**）；`AETHERD_HTTP=0` 与 `--http-only` 冲突 → 参数错误（退出码 10）。
- 启动生成 **256-bit token（64 hex）**，仅驻留内存；`POST /v1/admin/rotate-token` 原子轮换（旧 token 立即失效，发现文件同步）。
- 默认随机端口（`AETHERD_HTTP_PORT=0`）+ 发现文件 `<data_dir>/.aetherd-api.json`（`v/pid/port/bind/token/started_at/protocol`）；Unix `0600`；固定端口占用明确报错，不静默换端口。
- 仅 HTTP 开启时写发现文件；关闭时删除；`--stdio` 默认不产生发现文件。
- CORS 默认拒绝（`OPTIONS` → 403）；速率 100 req/s（突发 200）、并发 ≤64；请求日志只记 method/耗时，不记 Authorization/body/token。
- 优雅关闭：停止接受新连接 → 在途请求 → WS **1012** → 删除发现文件；`--http-only` 处理 CTRL-C/BREAK/CLOSE/注销/关机（Tokio `signal::windows`，无 `unsafe`/`windows-sys`）。

### DoD-2 API 契约（`/v1`、OpenAPI、超时/取消/背压）

- 路由：`POST /v1/rpc`、`POST /v1/rpc/cancel`、`GET /v1/meta`、`GET /v1/health`、`GET /v1/events`（WS）、`POST /v1/admin/rotate-token`。
- 方法映射：HTTP `method` = 已登记命令；`params` = 内层 DTO；未知方法 `-32601`；参数错误 `-32602` + `error.data.aether_code`；业务错误 `-32603`/`-32000` + `aether_code` + `business_code`（复用 `serve::map_ipc_error`，与 stdio 同一映射）。
- 超时：命令默认 30s + HTTP 层 5s；超时返回 `-32603` + `aether_code=internal` + `business_code=request_timeout`（仅传输层业务码，不进入 IPC 枚举）。
- 取消：`POST /v1/rpc/cancel {request_id}`；未知 id → 204；已登记请求响应改为取消错误，不回滚已落库状态。
- 请求 id 回显；不支持 batch；body ≤ **2 MiB**（超限 413）；响应 ≤2 MiB；业务错误保持 HTTP 200。
- OpenAPI 3.1：`docs/api/aetherd-v1.openapi.json` + `docs/api/schemas/*.json`（80 个），由 `scripts/ci/api-schema.mjs` 从 `command-manifest.json` + `types.ts` + `error_codes.json` 生成；检查模式校验 diff=0、59 daemon 命令覆盖、请求 DTO 存在、必填/枚举/长度/分页字段；CI 不手改生成物。

### DoD-3 WS 事件

- `GET /v1/events` 原生 WebSocket；连接后 **5s 内**首帧 `{"type":"auth","token":"<token>"}`，失败/超时 close **4401**；认证后 `{"type":"subscribe","session_id?":"<ULID>","last_seq?":N}`。
- 服务端发送 `{"type":"event","envelope":{...9 字段...}}`，与 stdio `aether.event` 的 `params` **0 差异**；`last_seq` 补读复用 `EventPipeline::readback`；`Lagged` → `{"type":"gap","session_id","from_seq"}` + 补读；慢消费者 >4096 或 >32 MiB → close **1013**；daemon 关闭 → **1012**。
- 不泄露 token/内部绝对路径；token 不在 URL/query/subprotocol。

### 6.1 G10 前安全关闭项：Windows discovery ACL

**M10-03 接受的安全假设**

1. 单用户、可信本机；不把数据目录放到共享目录/网络盘/同步盘（A4 已拒绝同步盘）。
2. 默认数据目录 `%APPDATA%\Aether` 位于当前用户 profile，继承 ACL 为当前用户私有。
3. 发现文件只保存本次 daemon 生命周期的 token；关闭删除，崩溃残留下次启动覆盖。

**残余风险（DACL 不解决）**

- 同一 OS 用户下的恶意进程/调试器可读文件或进程内存；
- 管理员/SYSTEM、备份软件、数据目录被复制；
- 若产品要求“共享数据目录/多用户”，默认信任不成立，需另立 ADR 升级认证方式（ACL 库、独立服务账户、Keychain/DPAPI、命名管道 ACL 等）。

**G10 前必须完成的条件检查（关闭标准）**

1. **默认目录**：校验数据目录与发现文件的**有效 ACL**（不只检查路径）；发现 `Everyone`/`Users`/`Authenticated Users` 等宽权限 → 拒绝启动或 `health.api.state=error`。
2. **自定义目录**：`AETHER_DATA_DIR` 非默认位置时必须验证/收紧 ACL（`icacls` fail-closed 或安全 ACL 库 + ADR）；失败不得开启 HTTP。
3. **轮换/残留覆盖**：token 轮换、崩溃残留下次启动覆盖后复测 ACL，不得回退为宽权限。
4. **证据**：Windows CI 输出 `icacls` 或 PowerShell `Get-Acl` 结果；G10 报告给出“关闭/风险接受人”结论。
5. **边界**：共享目录/多用户需求出现时，停止扩展现有方案，先走 ADR。

**负责人/时间**：M10-03 提供检查脚本与测试；G10 复跑前执行并归档。未完成前，该条在 G10 报告中不得标记为“已关闭”。

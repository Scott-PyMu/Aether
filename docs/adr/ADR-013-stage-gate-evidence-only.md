## 1. 背景

1. 设计文档 v1.12 §5 各阶段退出标准含墙钟/观察期/真实使用类指标：P0「自用 + ≥5 名 beta 用户连续 14 天」「连续 7 天无核心崩溃」；P1「30 天无数据事故」；P2「对抗式审查模板真实使用 ≥10 次」「API 有 ≥1 外部消费者稳定 2 周」；P3「MCP 连接 ≥3 个真实 Server 稳定 7 天」；P4「画布模板 ≥5 个且被真实复用」「笔记同步 30 天零丢失」；P5「崩溃率 <0.5%/周」「≥10 个外部适配器使用者」。
2. 上述指标把阶段推进绑定到日历时长或外部试样数量，与仓库「仅依赖驱动：任务启动 = 前置任务 DoD 全部通过；不按日历排期」的排期规则冲突，并成为 P1 门禁的最长墙钟支路（P1 计划 M8-02 观察期 ≥30 天）。
3. 产品负责人于 2026-09-30 指令：直接去掉 M8-02；阶段推进不受时间约束；前一阶段全部任务门禁（可执行验证）通过即可进入下一阶段；快速开发完成 P1–P6。
4. 设计文档 v1.12 已冻结；按其头部与 AGENTS §3，冻结内容变更须走 ADR 并升版。本 ADR 即该变更载体，并同时登记 P1 计划结构（沿用 ADR-011 登记型 ADR 先例）。

## 2. 决策

### 2.1 通则（P0–P6 适用）

| # | 决策 | 落地位置 |
|---|---|---|
| 1 | **阶段门禁 = 本阶段任务 DoD + 可执行验证证据**（单测 / 集成 / E2E / 故障注入 / 演练脚本 / 基准 / 静态检查 / 检查）。墙钟时长、真实使用次数、外部用户/外部 Server/插件数量、beta 用户数类指标**一律不构成阶段进入门禁**，降级为「发布后跟踪 KPI」（统计口径入诊断/发布报告，不阻塞阶段推进） | 设计 v1.13 §5 导语 + 各阶段退出标准 |
| 2 | **阶段进入规则不变**（ADR-012：前一阶段门禁通过即可进入；门禁证据 = 前一阶段验收通过结果）；本 ADR 只修订门禁定义，不恢复任何需求侧触发条件 | 设计 v1.13 §5 导语 |
| 3 | **数据安全底线不降**：删除的是「日历观察」而非「可执行验证」——加密备份恢复演练、数据类故障注入、kill -9 数据完整性、启动 `quick_check`、备份/导出中断原子性等仍为门禁（既有任务 DoD 与 P0 回归项，不下调） | 设计 v1.13 §5 P1；P1 计划 M5-03/M8-01/M8-03 |
| 4 | **发布门槛与阶段门禁分离**：对外发布（非自用/beta）时的质量门槛（崩溃率、外部使用者规模、法务/合规要求）由发布评审按当时情况单独立项，不由阶段门禁承担，也不得援引本 ADR 声称「发布质量达标」；发布评审最小定义见 §6-5 | 设计 v1.13 §5 导语 |

## 4. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 取消日历观察期后，静默数据缺陷（保留误删、备份不可恢复、恢复失败）随发布到达用户 | 保留为门禁：M8-01 全部数据类故障注入、M5-03 加密恢复演练、T4 kill -9、T9 备份恢复、T8 磁盘满、启动 `quick_check`；自动备份默认开启；归档先于清理、清理仅在归档校验通过后执行；发布后 KPI 持续统计（备份成功率/降级次数/事故台账），触发即按 D3/D4 失效路径直接实施 |
| 缺少真实使用验证（P0 beta 墙钟移除） | beta 反馈渠道与诊断包统计保留；发布评审按需设定发布门槛（与阶段门禁分离，决策 4） |
| P2–P6 日历指标移除后长期质量退化 | 夜跑、基准、故障注入与压力测试持续为任务 DoD；发布前由发布评审抽查 |
| 「不受时间约束」被误读为「可降低数据安全标准」 | 决策 3 明确底线不降；回退条件 §7 保留事故即恢复观测的路径 |

## 6. 后续（未决项）

1. **复审（已完成）**：2026-09-30 复审（版本链、计数、交叉引用、无残留墙钟门禁）无 P0；2 项 P1、5 项 P2 已处理并载入 v0.2（`docs/ADR-013-评审意见.md`）。
2. **P1-A 批次**：M5-01 的 P1-A01…A08 照常执行，正式编号自 ADR-014 起（原 §9 预登记「自 ADR-013 起」随本 ADR 修订）。
3. **数据事故定义（精简版）**：随 M8-03 证据包冻结——①已确认消息/控制事件丢失且库与备份均不可找回；②`quick_check`/`integrity_check` 失败；③备份产物不可恢复（含加密备份本机密钥与口令双路径均不可解）；④恢复失败且 `.pre-restore` 现场不可用。**核查方法**：脚本或检查逐条比对 M8-01 夜跑日志、诊断包与 P0 回归证据，结果随证据包归档；不设日历下限与活跃度门槛。
4. **发布 KPI 表**：发布后跟踪指标（P0–P5 降级项）汇总为发布报告模板，由发布评审使用。
5. **发布评审最小定义**（决策 4 落地）：触发 = 对外发布（非自用/beta）前；主持 = 产品负责人；输入 = 发布 KPI 清单（§6-4）与相应验证证据；输出 = 发布评审记录（`docs/发布评审-<版本>.md`）并留痕；结论不阻塞阶段推进，但未完成评审不得对外发布（§7 回退 3）。记录命名 `docs/发布评审-<版本>.md` 已照准（2026-09-30 产品确认）。

## 7. 回退条件

1. 自用/beta 期间发生已确认数据事故 → 立即修复并重新引入观测要求（另立 ADR 或修订本 ADR）；修复闭环前冻结对外发布路径。
2. 若后续阶段因合规/企业要求确需墙钟验证 → 按变更流程另立 ADR，不得静默回写阶段门禁。
3. 外部发布（非自用/beta）前未做发布评审 → 停止发布；不得以本 ADR 声称发布质量达标。
4. 任务 DoD 或 P0 回归被放宽/豁免而未走 ADR → 按回退动作纠正，豁免记录作废。

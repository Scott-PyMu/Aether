## 1. 背景

- P0：单 Runtime 直连、无路由逻辑（§2.3）；握手能力上报不用于路由（附录 A RA-04）。
- P1 §5：「能力路由 + 并发闸门（CP-02 部分）」；P1 计划 M7-02 DoD：路由矩阵（能力匹配/优先级/无候选/全部禁用）、与热插拔联动、并发闸门 `clamp(floor(free_ram_GB / 1.5), 2, 10)`（A5）、超限排队 + UI 队列位置、不做超卖、10 并发基线不退化、8GB 降级路径、手动指定与自动路由的优先关系。
- 现状：`session_create.runtime_id` 必填（手动选择）；`runs.status` 已含 `queued`；无路由决策审计动作；无队列位置呈现。
- 需定界（P1 计划 §10 待确认 7）：**路由触发方式（自动路由 vs 手动指定优先）与无候选项的默认行为**。

## 2. 决策

### 2.1 核心决策（五段式）

- **决策**：
  1. **触发方式**：`session_create.runtime_id` **由必填改可选**——缺省 = **自动路由**；显式给出 = **手动指定，优先于自动路由**（不参与打分；仍须通过可用性校验，见 2.1-5）。
  2. **候选过滤（硬条件，全部满足）**：① `runtimes.enabled=1`（ADR-015 偏好）且状态 ∈ `ready`（`cold` 允许参与并触发预热；`starting/degraded/disabled` 排除）；② 请求显式 `model` 时，候选须能路由该模型（存在启用 provider 提供该模型，或候选声明该模型直通——DSH 按会话选模型，ADR-024）；③ 请求涉及的能力项（如显式 `thinking_depth>2` 不构成硬条件——按缺省回退 + 警告，ADR-010 口径）不构成过滤条件。
  3. **候选排序**：① `ready` 优先于 `cold`；② **固定内置优先级常量**（`aether-control` 路由模块硬编码，升序）：`claude-code=10`、`codex=20`、`deepseek-harness=30`、`mock=100`（测试构建）；未登记 id = 100；③ 相等按 `id` 字典序。**不扩展 ADR-015 注册清单 schema**（strict schema / 清单规范化摘要 / M4-05 产物接口保持不变，避免含新字段清单被整条拒绝）。
  4. **无候选行为**：返回结构化错误 **`no_candidate_runtime`**（message 区分「全部禁用」「无匹配模型」「无 ready 候选」）；UI 提示可用运行时清单与原因；**不回退到 disabled 运行时、不静默改用手动**。
  5. **手动指定校验**：`runtime_id` 未注册 → `invalid_enum`；已注册但 `enabled=0` / `disabled` → `invalid_value`（提示启用或改选）；手动选择不受路由优先级影响，但仍受并发闸门约束。
  6. **并发闸门**：`max_concurrent = clamp(floor(free_ram_gb / 1.5), 2, 10)`（A5；`free_ram_gb` 启动与巡检时采样）；闸门计数 = **全局 `running` run 数**；超限 → 新 run 入队（`runs.status='queued'`，**FIFO 全局队列**，不超卖）；run 终态触发队列推进（单写者顺序）。**与会话级等待槽（D8）的合成语义见附录 A-6**（会话等待槽只负责会话内串行；全局 FIFO 只收纳已晋升为 `queued` 的 run；两层不重复计数）。
  7. **队列呈现**：`session_send` 响应在入队时附可选 `queue: { position, limit }`；`health` 响应增 `concurrency_gate: { limit, active, queued }`（UI 轮询 5s，ADR-007 先例）。
  8. **审计**：自动路由决策写 `route.decided`（actor=system；detail = 候选、优先级、选中、原因）；手动指定不写路由决策（入 `session.created` 已有载荷）。
  9. **热插拔联动**：禁用运行时立即从候选中排除；重新启用后重新纳入（**无粘性缓存**；已存在会话保持原 runtime，不重路由）。
- **实现要点**：
  1. 路由逻辑位于 `aether-control`（创建会话路径；不新增 crate）；`aether-tauri` 命令层仅透传。
  2. `session_create` 缺省路由成功后在 `session.created` payload 回显 `routed: true`（可选字段；附录 B payload 允许扩展）。
  3. 闸门前置于 run 启动（`session_send` 路径）与 `run_retry`；排队 run 的 `session.interrupt` 可取消（出队）。
  4. 8GB 模拟：`free_ram_gb` 由参数注入（测试替身）；`clamp(floor(7/1.5)=4, 2, 10) = 4`。
  5. T3 口径回归：10 并发会话 × 每会话 1 run（16GB 基准机）不退化（M7-02 DoD4）。
- **主要风险**：自动路由选中用户不期望的运行时（模型/行为差异）；优先级与能力不匹配组合导致「能创建但 run 失败」；队列位置抖动（FIFO 被终态乱序打乱）；内存采样突变导致闸门跳变；冷启动候选被排除造成「明明可用却无候选」。
- **缓解措施**：选中的 runtime 在 UI 明示（会话摘要 `runtime_id` 已有）；路由硬条件保守（无匹配 → 明确报错而非乱选）；队列位置由单写者按入队序维护（不重排）；闸门值随巡检更新且**只对新 run 生效**（在途 run 不受限）；`cold` 候选可参与（预热路径已有）。
- **失效条件**：路由产生**跨运行时数据/权限错配**（如会话被路由到未预期 runtime 且用户无感）→ 暂停自动路由（回落手动必选）并另立 ADR；闸门出现**超卖**（active > limit）→ 按严重缺陷停止排队路径；队列长时间饥饿（>30 分钟未推进）→ 触发诊断并复审。

## 附录 A：路由矩阵 / 错误码 / 响应增量登记

**A-1 路由决策矩阵（摘要；完整矩阵与用例由 M7-02 任务证据登记）**

| 场景 | 结果 |
|---|---|
| `runtime_id` 缺省 + ≥1 可用候选 | 按排序选首个；`session.created.routed=true`；审计 `route.decided` |
| `runtime_id` 缺省 + 0 可用候选（全部 disabled） | `no_candidate_runtime`（message：无可用运行时） |
| `runtime_id` 缺省 + 指定 `model` 且无候选提供 | `no_candidate_runtime`（message：无运行时提供该模型） |
| `runtime_id` 显式 + 注册表命中 + enabled 且非 disabled | 直接使用（跳过排序）；闸门仍生效 |
| `runtime_id` 显式 + 未注册 | `invalid_enum` |
| `runtime_id` 显式 + 已注册但 disabled/`enabled=0` | `invalid_value`（提示启用或改选） |
| 候选为 `cold`（enabled） | 允许入选并触发预热（会话 `creating` 路径已有） |
| 闸门饱和 | run `queued` + `queue.position`；FIFO；终态推进出队 |

**A-2 ADR-006 附录 B 错误码增行（逐行文本）**

| code | 语义 | 触发点 | 前端行为 |
|---|---|---|---|
| `no_candidate_runtime` | 自动路由无可用候选（全部禁用/无匹配模型/无 ready 候选） | `session_create`（缺省路由路径） | 提示原因与可用运行时清单一旁展示；提供「手动选择」入口；不自动重试 |

|---|---|---|

| `codex` | 20 | 内置常量 |
| `deepseek-harness` | 30 | 内置常量 |

**A-5 响应增量（登记于 ADR-018 附录 A-5）**

- `session_send` 响应可选 `queue: { position, limit }`；`health.concurrency_gate: { limit, active, queued }`；`session.created.payload.routed?: boolean`。

**A-6 双层队列合成语义（会话级等待槽 D8 × 全局闸门 FIFO；M7-02 DoD3 必测矩阵）**

| 场景（同一会话） | 会话级等待槽（D8） | 全局闸门（本 ADR） | 合成结果 |
|---|---|---|---|
| 空闲 + 闸门有槽 | 空 | 有槽 | run 立即 `running` |
| 空闲 + 闸门饱和 | 空 | 饱和 | run `queued`（进入全局 FIFO，占「当前 run 位」）；`queue.position` = FIFO 内位置 |
| `running` 时再发 1 条 | 该消息入等待槽（D8 既有） | 与等待槽无关 | 不发全局排队；当前 run 终态后，等待槽 run 晋升为「当前 run」 |
| `running` 时发第 2 条 | 等待槽已满 → `session_busy`（D8 既有） | — | 发送被拒（草稿保留） |
| 等待槽 run 晋升时闸门饱和 | 等待槽清空、run 晋升 | 进入全局 FIFO 尾部 | `queued` + `queue.position` |
| `queued`（全局）时再发消息 | 等待槽复用（至多 1 条，超 `session_busy`） | — | 等待槽按 D8 规则 |
| `queued` run 被 interrupt | 该 run 从全局 FIFO 移除并取消（`cancelled`） | 槽位让给 FIFO 下一项 | 等待槽不被连带清空（若有） |
| 闸门出现空槽 | — | 按 FIFO 顺序推进（单写者） | 每次推进仅启动队首 run，不超卖 |

> 口径：`queue.position` 仅指**全局 FIFO** 内位置（从 1 计；不含未进全局队列的会话等待槽 run）；`health.concurrency_gate.queued` = 全局 FIFO 长度。两层机制不重复计数：会话等待槽是「会话内串行」；全局 FIFO 是「资源闸门」。

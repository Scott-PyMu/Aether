## 1. 背景

三份文档（《需求文档》v0.2、《设计文档》v1.2、《实施计划与验收标准》v1.7）经交叉评审后确认存在系统性不一致，直接实施会出现「需求—设计—验收」三方各自解释：

1. **阶段与编号混用**：需求文档使用里程碑 M1–M6，实施计划使用任务 M1/M2（含 M1-01 等），两套 `M` 编号语义不同。
2. **线协议表述不一**：设计文档为「JSON-RPC 2.0 / stdio」，实施计划 M1-09 出现「JSON-RPC 1.0」，需求文档仅写「JSON-line 协议」。
3. **字段口径不一**：EventEnvelope 实际 9 字段（`v/id/session_id/run_id/runtime_id/seq/ts/type/payload`），实施计划 M1-02 写为「8 字段」；需求接口（如 `Permission.granted`）与 DB 列、线协议无统一映射表。
4. **持久化失败语义矛盾**：D4 失败表允许「仅内存广播」，违反「先日志后广播」底线；无完整降级状态机，未定义降级通知路径与在途 run 处理。
5. **背压例外未定义**：D8 声称「reader 永不被下游阻塞」，但未定义存储故障时控制事件读取的可暂停边界与熔断条件。
6. **失败路径与安全边界不完整**：Gate 1 只有「通过/降级记录」，未定义 mock-only 的交付标记与替代验收；CP-05/SE-01/SE-03 的 P0 验收口径过宽（暗示进程内行为受保护、审计覆盖全部 Agent 操作）；Windows Job Object 被错误表述为沙箱；跨平台故障注入依赖 Windows 不具备的 `SIGSTOP`。
7. **工程口径漂移**：心跳 30s 与 T5b 90s 的检测预算对不上；大行策略同时承诺 LinesCodec 与「不缓冲完整行」；`package-lock.json` 与实际仓库（`pnpm-lock.yaml`、`pnpm@10.34.5`）不符；性能指标缺少环境与采样口径；T3「10 并发 run」与 D8「单会话单 run」冲突。
8. **缺口**：缺少工作区记忆的 P0 任务（M3-08）、缺少字段映射表（附录 E）、缺少 M2-11 的条件性（DSH 未入选时不应排期）。

评审确认按 21 条修改意见修订（评审通知表述为「编号 1–20」，列表实含 21 条——第 21 条为 T3 并发口径调整，本 ADR 按列表顺序逐条收录，不做合并或拆分）。

## 2. 决策（采纳编号 1–21）

| # | 决策 | 落地位置 |
|---|---|---|
| 1 | 产品阶段统一使用 P0–P6；实施任务统一使用 `M<里程碑>-<序号>`；需求文档删除 M1–M6 里程碑表述，改为「全量需求 + 目标阶段 + 本阶段是否验收」 | 需求文档 §8/各需求表；设计文档 §5；实施计划全文 |
| 2 | 线协议统一表述：**JSON-RPC 2.0 over JSON-Lines，Aether 线协议版本 1.0** | 设计文档 D6/§2.2/D5-DSH 节；需求文档 §5/§7；实施计划 M1-09 |
| 3 | EventEnvelope 固定 **9 字段**：`v/id/session_id/run_id/runtime_id/seq/ts/type/payload` | 设计文档 D4/§2.4；实施计划 M1-02 |
| 4 | `events` 表增加 **UNIQUE(session_id, seq)**，代码层单一 sequencer 保留；已发布迁移不可修改，约束经新增迁移落地 | 设计文档 D4/附录 C；实施计划 M1-03 |
| 5 | 未知字段策略统一：JSON-RPC 外层未知成员**忽略**；归一化后 EventEnvelope 顶层未知字段**拒绝**；payload 是否可扩展**按 type 单独声明**；跨 `v` 版本**允许新增字段**（只增不改语义） | 设计文档 D4/D6/附录 B；实施计划 M1-02/M1-09 |
| 6 | 持久化失败语义统一：重试 3 次失败 → `persist_degraded` + 只读；拒绝新写入/新 run；**不广播未落盘事件**（删除「仅内存广播」）；完整状态机；降级通知经 `health` 呈现（落盘成功时才广播 `error`）；在途 run 中断（P0 无 pause/resume，§4#22） | 设计文档 D4；实施计划 M1-05 |
| 7 | 控制事件背压统一：reader 不被 UI/delta 消费者阻塞；存储故障时允许暂停控制事件读取/拒绝新 run/隔离适配器。定义：暂停窗口 250ms/次、单次超时 2s、适配器出站上限 1024 条、熔断（60s 累计暂停 >10s 或连续 3 次超时或存储 30s 未恢复 → 隔离 `degraded + status_reason=storage_backpressure`） | 设计文档 D5/D8；实施计划 M2-04 |
| 8 | 真实适配器失败路径统一：Gate 1 可允许 **real-adapter 或 mock-only** 结论；mock-only 只能标记为「**Mock-only beta**」，不得无条件声称正式 P0 完成；M2-02 拆为真实适配器路径与 Mock-only 替代路径（M2-02M），并补替代 Gate 与 DoD | 设计文档 A1/§5 P0；实施计划 M2-02/M2-02M/Gate 1/2/4 |
| 9 | M2-11 改为**条件任务**：仅当 A1 最终选择 DSH（前两候选均不可行、按优先序落至 DSH）时才执行；否则不排期、不占用 P0 资源 | 实施计划 M2-11/§1/§7 |
| 10 | 新增 **M3-08 工作区记忆**：注入、`memory.read/append/write`、权限、32KB 上限、原子写、跨会话验证、冲突处理 | 实施计划 M3-08；设计文档 D14 |
| 11 | 重写 CP-05/SE-01/SE-03 的 P0 验收口径：P0 只保证**经协议上报的工具调用**受权限门约束；适配器进程内部行为不受保护；P0 为**最小审计**，完整 Agent 操作审计延后 P1/P3 | 需求文档 §3.5/§3.6/§4；设计文档 §2.1/附录 A；实施计划 M2-03/M3-07 |
| 12 | 大行协议改为**自定义有界增量读取器**：`artifact_ref` 本身必须是 <1MiB 的引用帧；任何 >1MiB 的普通行立即断连；删除 LinesCodec 与「不缓冲完整行」并存表述；帧上限从 16MiB 改为 **1MiB** | 设计文档 D6/D2/D5/§2.2；实施计划 M1-09/M2-09 |
| 13 | Windows Job Object 定位：**P0 用于进程树回收与资源管理**；不再表述为文件/网络沙箱；P3 文件/网络隔离**另立 ADR**（评估 AppContainer、受限令牌、网络隔离等） | 设计文档 A6/D5/§5 P3；需求文档 §4/§5；实施计划 M1-10 |
| 14 | 跨平台故障注入统一 helper：Unix 使用 `SIGKILL`；Windows 使用 Job Object / `taskkill`；卡死场景让 Mock 适配器进入「不响应模式」；不依赖 Windows 不具备的 `SIGSTOP` | 设计文档 附录 D；实施计划 §0/M1-09/M2-08/M4-01 |
| 15 | 心跳与 T5b：改为 **10 秒心跳、连续 3 次失败**；T5b 上限放宽到 **120 秒**；明确计时起点、失败采样方式与重启/握手预算 | 设计文档 D5/附录 D；实施计划 M2-08/§6 |
| 16 | 包管理器统一：设计文档 `package-lock.json` 改为 **`pnpm-lock.yaml`**；固定 **pnpm@10.34.5**；CI 与 M1-01 同步（现 CI 已使用 pnpm，计划层将版本固定写入 DoD） | 设计文档 D1；实施计划 M1-01 |
| 17 | P0 平台范围：Windows 10 1809+、macOS 12+ 可运行；Linux P0 仅编译检查，安装包顺延 P1；需求文档同步降级 | 需求文档 §1.2/§4/§5；设计文档 §2.1/A12 |
| 18 | 性能指标统一：P0 统一 **P95 <150ms**，注明测试环境、采样口径、并发基线（10 个并发会话、每会话 1 run、16GB 基准机）；需求中的 <100ms 保留为后续目标；8GB 允许动态降级 | 设计文档 §2.1/A5/附录 D；需求文档 §4；实施计划 M4-04 |
| 19 | T8 磁盘满场景：必须明确备份/导出到**外部路径**；定义外部路径选择器与空间检查（可写校验 + 可用空间 ≥ 当前 `db+wal` ×1.2） | 设计文档 D3/D13/附录 D；实施计划 M3-04/M4-02 |

## 5. 后续（未决项）

1. **P3 文件/网络隔离 ADR**：评估 AppContainer、受限令牌、网络隔离等方案；P3 进入前必须先立项。
2. **Mock-only 路径的真实适配器计划**：若 M2-02M 被激活，需在 P1 启动前补齐真实适配器接入的任务分解（本 ADR 只定义标记与 Gate 口径）。
3. **`persist_degraded` 热恢复**：明确不在 P0；若提前需求出现，走新 ADR。
4. **性能基准环境固化**：CI 基准机型号与声明方式在 M4-04 证据中记录，本 ADR 只固定口径。
5. **pnpm 升级策略**：本 ADR 固定 10.34.5；升级策略由仓库维护约定另行定义。
6. **AGENTS.md §2.6 表述**：现为「JSON-RPC 2.0 over stdio」，与统一表述不完全一致；属治理文件，建议另行评审修订（不在本次范围内）。

## 6. 回退条件

1. **1MiB 帧上限**：若某官方适配器存在合法的 >1MiB 普通帧且无法降级为 `artifact_ref`，须另立 ADR 重新评估上限（不得静默放宽）。
2. **`events UNIQUE(session_id, seq)`**：若既有数据库存在重复 `(session_id, seq)` 历史数据，迁移前必须先执行去重审计并留存报告；无法安全去重时，回退为「仅代码层 sequencer + 非唯一索引」，并以新 ADR 说明。
3. **存储侧背压参数**：暂停窗口/超时/熔断阈值若在实测中导致控制事件丢失或误熔断，按常量级调参处理，但须在任务证据中记录并向评审报告。
4. **Mock-only beta**：若后续真实适配器接入完成，应重新走 Gate 2 等价验收，撤销 Mock-only 标记后方可声称正式 P0 完成。

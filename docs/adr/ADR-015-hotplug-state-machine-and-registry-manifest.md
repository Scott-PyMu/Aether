## 1. 背景

**1.1 触发**：P1-A01 为 P1 前置 ADR 批次第一项（P1 计划 §9），解锁 M7-01「官方适配器热插拔与注册清单」。设计 §5 P1「决策变更」含「D5 扩展热插拔状态机」；新增能力含「官方适配器热插拔（配置 + UI 启用/禁用，RA-05；第三方仍拒绝）」；附录 A：CP-01「P1：安装/热插拔 UI」、RA-05「P1 进程级（官方）」、UI-02 能力展示。P1 计划 §10 待确认 8（热插拔范围粒度与 UI-02 展示面）由本 ADR 闭合（M5-01 DoD6）。

**1.2 P0 现状（实现事实，非决策）**：

- 状态机已实现且与 `runtimes.status` 一一对应：`cold → starting → ready → degraded → disabled`（`crates/aether-adapters/src/supervisor/state.rs:189-206` 转移表），其中 `* → disabled`（`cold/starting/ready/degraded → disabled`）与 `disabled → cold/starting` 已存在——**启停转移的边集已覆盖，无需新增转移边**；
- 故障恢复命令已接线：`runtime_retry`（仅 `disabled + start_failed`）、`runtime_enable`（仅 `disabled`；`untrusted`/`version_mismatch` 须先修复，`NeedsRemedy`）（`runtime.rs:1103-1181`；`docs/M1-10-证据.md` §6）；UI 口径为「故障恢复，不属热插拔」（UI-UX §8#10）；
- 注册现状：准入白名单为代码内置 `OFFICIAL_RUNTIME_IDS`（`admission.rs:13-20`，含 `pi`/`hermes` 占位）；生产组合根当前以空注册表启动（`runtime_control.rs:336-341`），官方运行时注册随 P0 M4-05（安装产物内注册，P0 计划 v1.23）落地；`runtimes_list` 已返回 `enabled`（静态 manifest 字段，`session_backend.rs:431-441`）；
- **`runtime.status_changed` 零发射**：监督器状态转移目前只写 `audit_log`（`audit_bridge.rs:96-117`），事件类型与载荷已定义（`aether-core::event.rs:380-388`）。补齐义务已由 ADR-014 决策 4 登记为 M7-01 DoD0 前置；本 ADR 依赖该前置并登记其会话归段口径（§2.3 / 附录 C-8）。

**1.3 为什么必须走 ADR**：本批次触及冻结面——D5 状态机语义与 `status_reason` 词典、D7 命令面、ADR-006 错误码登记、附录 C 迁移与 `verify:m1-03` 双向强校验（`EXPECTED_EXPLICIT_INDEXES` 等）、UI-UX 锚点契约；且 P1 计划 §10-8 待闭合。AGENTS §3 禁止静默修改冻结决策与表结构语义。

**1.4 范围界定（本 ADR 只决定什么）**：热插拔粒度、启停状态机语义与原因值、在途 run 处置、注册清单校验模型、启用偏好持久化、命令/错误码/事件/审计登记、UI 锚点与文案；**不**决定安装器实现（M4-05 范围）、不新增运行时（ADR-008 冻结）、不改变 D6 线协议方法集、不改变 D9 权限矩阵、不涉及第三方信任模型（P3）。

### 2.1 五段式 A：热插拔粒度、状态机与在途 run 处置（决策 1/2/3/5/7）

- **决策**：热插拔 = 官方运行时的运行期**启用/禁用**（进程级加载/卸载），粒度不含安装/卸载；禁用与启用均不重启应用。禁用语义 = 「用户显式停止该运行时」：先阻断新准入与自动重启，再按 D5 受控终止整树回收，最终态 `disabled + status_reason=user_disabled` 并持久化偏好；启用语义 = 既有 `disabled → cold → starting → ready` 人工恢复路径（`untrusted`/`version_mismatch` 仍禁止直接启用）。存在在途会话时禁用必须显式确认，确认后受控收口、不静默丢弃。
- **实现要点**：
  1. **转移语义**（完整表见附录 D）：`cold/starting/ready/degraded → disabled(user_disabled)`（先转移、后终止：转移即阻断监控自动重启与新准入，规避「终止与自动重启竞态」）；`disabled → cold → starting → ready`（enable；经既有 `begin_enable` + `start`，守卫与失败路径沿用）；`disabled` 上再 disable → `invalid_value`（不转移）。
  2. **在途判定口径**：该 `runtime_id` 下会话处于 `creating`/`running`/`paused`/`waiting_permission` 之一，或存在 run 处于 `queued`/`running`（终态不计）；统计仅用于确认门与 UI 展示，不作为终态事实。
  3. **在途处置流程**：① 有在途且未确认 → `runtime_busy`（`message` 含计数；不转移、不写偏好）；② 确认（或 0 在途）→ 先写偏好 `enabled=0`（单写队列，失败即命令失败）→ 状态转移 `→ disabled`（转移后 `session_create` 按既有 disabled 语义拒绝；`session_send` 的 run 启动按监督器状态拒绝，不新增错误码）→ 执行 D5 终止序列（`shutdown` 5s → 组/树终止；预算 ≤15s，命令总超时沿用 `RUNTIME_CONTROL_TIMEOUT=30s`）→ 在途 run 收口；③ 审计 `runtime.disable` + 逐次转移事件。
  4. **在途 run 收口口径（两类，均为既有码，不新增 run 错误码）**：**活跃 run**（已开始执行）随终止断连由会话客户端收口为 `run.failed`（`adapter_disconnected` 或竞态分支 `cli_exit`，`recoverable=true`）；**`queued` run**（`runs.status=queued`，等待前序 run 终态）在队列推进至其启动时命中既有 run 启动拒绝 `adapter_unavailable`（`adapter_executor.rs:41`；`error_info` 恒 `recoverable=true`）→ `run.failed`；两类均可用 `run_retry` 重放（Mode R/N，ADR-005）。DoD2 断言须覆盖 `queued` 用例（前序 run 在途、后随一条 queued，disable 确认后两者均达终态）。
  5. **偏好写序（失败关闭）**：disable = 偏好先写、失败即失败（宁可维持原状，不产生「内存已停、重启又启动」）；enable = 偏好先写 `enabled=1`、启动失败按既有 `disabled + reason` 收口（下次启动按偏好重试）。偏好与状态在崩溃窗口的短期不一致以「命令回执 + 启动矩阵」为准，不做跨进程事务。
  6. **启动矩阵**：注册清单条目 × DB 偏好 → `enabled=1`（或 DB 无记录）：正常预热；`enabled=0`：显式转移 `cold → disabled(user_disabled)`（发事件、审计），不 spawn。
  7. **串行化**：启停命令与 `start`/`restart`/`release` 共用状态锁；`starting` 窗口内到达的 disable 在锁内完成「取消启动收口 → disabled」，启动收口遇非法转移按失败收口、不得重试。
  8. **不改既有恢复命令**：`runtime_retry` 语义不变（仅 `disabled + start_failed`）；`runtime_enable` 仅扩展可适用的 disabled 原因集合（含 `user_disabled`），守卫与错误映射不变。
  9. **不提供**：安装/卸载/降级安装、运行期自动路由（M7-02）、运行期重扫注册清单；`pi`/`hermes` 维持白名单占位且无清单条目。
- **主要风险**：误禁用导致在途工作终止（数据面）；用户把「禁用」误当「卸载」（认知面）；禁用期间既有会话不可用（可用性面）；`starting` 窗口启停竞态；偏好先写后动作的崩溃窗口（偏好=0 而进程仍短暂存活，或偏好=1 而启动失败）；禁用后路由/发送入口未及时感知（M7-02 依赖）。
- **缓解措施**：在途必须显式确认（`runtime_busy` → UI 二次确认，列出计数）；UI/文档文案明示「禁用保留会话与数据，重新启用后可继续/重放」；转移先于终止阻断自动重启；状态锁串行化 + 启动收口检查；偏好失败关闭 + 命令回执返回最终状态与原因；`session_create`/`session_send` 按监督器实时状态拒绝（复用既有 disabled 语义）；M7-02 路由按实时状态过滤（禁用不入路由、恢复重新纳入）。
- **失效条件**：出现「未确认即静默终止在途 run」的实现 → 停止合入并按本 ADR 修正；偏好持久化在崩溃窗口产生不可解释的「禁用后自动启动」且无法以启动矩阵解释 → 重评实现（必要时回退为「禁用仅会话内生效」，另立 ADR）；出现因禁用导致的用户级数据损失复现案例 → 增加更强默认（如强制确认 + 会话清单预览）并另立 ADR 修订。

### 2.2 五段式 B：注册清单与准入校验（决策 4）

- **决策**：官方运行时以**只读内置注册清单**（数据文件，随安装产物发布；构建期生成）声明；**启动时**逐条校验：① 严格 schema（未知字段/未知条目拒绝）；② id 命中官方白名单（三运行时；Mock 仅测试构建）；③ `program` 路径约束——解析基准 = **构建期清单内嵌的安装根**（**逻辑锚**：资源目录相对名，运行期按当前可执行文件位置解析后 canonicalize 比对；**不内嵌构建机绝对路径**），`program` 为相对路径，canonicalize 后不得逃逸安装根；**不以「非用户可写位置」作独立判据**（用户级安装为受支持形态，完整性由摘要承担；平台化判定口径与误杀样本在 DoD3 登记）；④ **构建期摘要比对**——期望摘要表（编译进核心二进制）覆盖每个 `program` 的 sha256 与**注册清单自身规范化形态（canonical form）的 sha256**（后者覆盖 `args` 与清单字段篡改）。任一失败 → 该条目拒绝加载并审计；清单整体缺失/不可解析 → 空注册表 + 启动告警（应用可用、其他条目不受影响）。**enable 仅检查注册表成员资格**（条目不在注册表 → `invalid_enum`；不支持进程内重扫，修复后重启）。**构建期义务（非运行期校验）**：M4-05 注册产物接口一致性（实现要点 6）。**不新开用户可扩展入口**：用户可写清单一律不加载，第三方 manifest 仍 `untrusted`。
- **实现要点**：
  1. **清单形态**（实现内登记文件名/编码）：`{ schema_version, runtimes: [{ id, name, kind, version, protocol, program（相对路径）, args? }] }`；**不含密钥与 `api_key_ref`**（D10）；规范化形态（键序固定、UTF-8、无 BOM、LF）与摘要算法口径在 M7-01 DoD3 登记；**安装根解析语义（评审 N3）**：清单内仅存资源目录相对名（逻辑锚），运行期以「当前可执行文件所在目录 → 安装根 → canonicalize」解析并与 `program` 拼接校验；换安装路径 / 便携形态 / 用户级安装均以同一逻辑锚解析，不得内嵌构建机绝对路径；清单本身不放可信摘要（防自洽篡改）。
  2. **信任锚**：期望摘要表（每个 `program` + 清单规范化形态）由构建流水线生成并编译进核心二进制（`build.rs` 或生成模块；算法 sha256，与迁移 checksum 同算法）；CI 校验「清单/摘要/程序三者一致」，**覆盖 P0 M4-05 安装产物**（打包冒烟）。
  3. **失败处置**：按条目拒绝 + 审计动作 `runtime.registry_rejected`（detail 含 id 与原因分类：`missing_file` / `digest_mismatch` / `unknown_id` / `path_rejected` / `schema_invalid`）+ 诊断计数；被拒条目不进监督器注册表（`runtimes_list` 不可见；不提供启用入口，呈现面仅在诊断）。
  4. **与既有准入策略的关系**：`AdmissionPolicy::official()` 与 `OFFICIAL_RUNTIME_IDS` 不变；注册清单只新增可信来源与完整性校验，**不放宽任何既有拒绝**（第三方 manifest、用户清单、`untrusted` 回归保持）。
  5. **enable 前置检查（仅成员资格，不重跑逐条校验）**：`runtime_enable` 前仅检查条目是否为注册表成员；不在注册表（清单类失败/未注册）→ `invalid_enum`，修复后重启重扫；`untrusted`/`version_mismatch` 的 `NeedsRemedy` 语义不变。
  6. **M4-05 接口一致性义务（评审 P1-4；构建期义务，非运行期逐条校验项）**：M4-05「安装产物内注册」的产物形态 = 本清单 schema（或其规范化映射；映射口径由 M7-01 DoD3 登记并在打包冒烟断言）。若 M4-05 产物无法对齐，由 M7-01 登记映射层适配，**不得为此放宽校验或静默跳过**；构建期 CI 与打包冒烟须覆盖「P0 产物 → P1 校验」通路。
- **主要风险**：误杀（安装根逻辑锚解析/编码归一化/摘要算法差异导致合法条目被拒 → 官方运行时不可用）；**M4-05 产物与清单 schema 不齐 → 全量条目误拒**（首要风险）；换安装路径 / 便携形态 / 用户级安装下的逻辑锚解析偏差；构建流程把未审文件带入清单；P0/P1 无签名/证书设施（摘要比对是当前唯一完整性锚）。
- **缓解措施**：摘要期望值编译进二进制；清单 + program 双摘要（覆盖清单字段与 `args` 篡改）；构建期生成 + CI 三者一致校验（覆盖 P0 产物）；DoD3 登记平台化路径判定口径与误杀样本（含**换安装路径 / 便携形态** / 用户级安装、路径含空格/非 ASCII、Windows 8.3 短名）；误杀走 §6-4 回退路径（修复校验，不得静默放行）；第三方/用户清单一律拒绝并审计；注册清单校验不阻塞应用启动（空注册表可用，UI 空态既有）。
- **失效条件**：官方安装产物出现合法条目被拒且不可解释 → 修复校验实现或降级为「路径 + 官方标记」校验并另立 ADR；摘要机制被证明可绕过（期望值可从安装目录篡改）→ 触发 P3 签名/沙箱前置评审；出现非官方加载路径 → 停止热插拔实现并按 §6 回退。

### 2.3 五段式 C：命令面、事件发射与审计（决策 6）

- **决策**：新增 `runtime_disable`（+1 命令）；`runtime_enable` 语义扩展但契约不变；`runtimes_list` 条目增量（`enabled` 改取持久化偏好 + `active_sessions`）；`RuntimeControlReport.outcome` 取值域新增 `"disabled"`；每次合法状态转移广播 `runtime.status_changed`（补齐 ADR-014 决策 4 的前置，M7-01 DoD0），并登记全局事件的会话归段口径；启停动作入 `audit_log`。
- **实现要点**：
  1. **命令契约**（D7/ADR-006 式样，完整见附录 C-1）：`runtime_disable({ runtime_id, confirm_terminate?: boolean })`，严格解析；错误映射：不在注册表 → `invalid_enum`；状态非 `disabled` → `invalid_value`；在途未确认 → `runtime_busy`；成功回执沿用 `RuntimeControlReport` 形状并**扩展 outcome 取值域**（新增 `"disabled"`；原域 `ready` / `already_running` / `failed` / `rejected`），`status="disabled"`、`status_reason="user_disabled"`。
  2. **`runtime_enable` 扩展**：适用原因集合 = 既有全部 disabled 原因 − `{untrusted, version_mismatch}`（新增 `user_disabled`）；响应/错误不变；成功即偏好 `enabled=1`。
  3. **`runtimes_list` 增量**：`enabled` = DB 偏好（非静态字段）；新增 `active_sessions`（非终态会话计数，0 为合法值）；其余字段不变。`runtime_disable` 为新命令、**必然改变 `packages/protocol/src/bindings.ts`**（新增函数）——须复跑 `pnpm --filter @aether/protocol generate` 与 `check`（AGENTS §2.8 / T14）；`runtimes_list` 为 `Value` 形状（`bindings.ts:8` 为 `unknown`），其条目增量不触发生成物变更（附录 C-3）。
  4. **IPC 校验矩阵**：`runtime_disable` 纳入 M1-08 式畸形参数校验矩阵（未知字段/类型/非法 `runtime_id`/缺 `runtime_id`/`confirm_terminate` 非布尔），全部返回结构化错误且不落库（M7-01 DoD5）。
  5. **事件发射（DoD0）**：每次合法转移 → 一条 `runtime.status_changed`（信封 9 字段；payload `runtime_id/from/to/reason`，`reason` 取值含 `user_disabled`）；**经事件管线先日志后广播**（D4）；广播经 `aether://event` 前端消费（徽标实时刷新）；审计记录保留不变（事件与审计并存，不互替）。
  6. **会话归段口径（全局事件）**：`runtime.status_changed` 无真实会话，登记合成归段 `session_id = "runtime:<runtime_id>"`（常量前缀 `runtime:` 保留；**依赖 `SessionId` 当前仅拒绝空串、不做 ULID 格式校验**，见附录 C-8）；不建 `sessions` 行、不进 `session_list`、`messages_page` 与补读不查询该段；`events.session_id` 仍 NOT NULL（无 FK），**不改 events DDL**；seq 按合成归段独立单调（单 sequencer，UNIQUE 兜底不变）。
  7. **审计动作**：`runtime.enable` / `runtime.disable`（actor=`user`；detail 含参数、在途计数与结果）；监督器侧既有 `runtime.status_changed` 与 `runtime.<audit_kind>` 动作不变。
  8. **超时**：disable 含终止序列，沿用 `RUNTIME_CONTROL_TIMEOUT=30s`（覆盖 D5 终止预算 ≤15s）。
- **主要风险**：确认门与执行窗口的竞态（确认时统计与执行时在途集合不一致）；合成归段与 D4「事件属于会话」语义的张力（评审敏感点）；事件与审计重复计账（口径漂移）；`runtime_busy` 计数与 UI 展示不一致。
- **缓解措施**：确认后在同一状态锁临界区先转移 `disabled`、再按**执行时**在途集合收口（此后不再受理新 run，集合冻结）；归段口径仅用于持久化与广播，真实会话视图/补读不受影响，并在本 ADR 显式固定、回退路径 §6-7；事件/审计职责分离写入登记（事件=状态事实，审计=操作与处置记录）；`runtime_busy` 的计数与 `active_sessions` 同源（同一读路径口径）。
- **失效条件**：归段口径无法在 D4 管线落地（sequencer/补读/前端任一环节阻断）→ 停止「必发事件」断言并回报，另立 ADR 修订 D4 全局事件口径；**不得**仅广播不落盘（违反 D4）；确认流出现可绕过路径（如 UI 直连终止、settings 旁路）→ 修正并按 §6-5 处置。

## 6. 回退条件

1. **本 ADR 被否决** → M7-01 退回「修改配置 + 重启生效」P0 形态；不提供启停 UI、不加 `runtime_disable`、不加 `runtimes.enabled` 迁移；P1 计划 §10-8 回到未闭合。
2. **需求 CP-01 补注（产品裁定 A）被否决** → 回退为评审记录裁定（问题 1 的备选 B：以「安装 = 安装产物内注册」覆盖需求原文并留痕），同步修改 §3.2/版本表/附录 F；不得静默维持「需求/设计附录 A/决策」三方冲突。
3. **`user_disabled` 与既有语义冲突** → 改名（词典只增不改）并随批修订；不得复用既有原因值（如 `untrusted`）承载用户禁用。
4. **注册清单校验误杀官方条目** → 修复校验实现（含安装根/摘要/编码归一化）；不得静默放行或绕过校验；修复后复跑打包冒烟。
5. **确认流被绕过**（无 `confirm_terminate` 即静默终止在途 run）→ 停止合入并按本 ADR 修正；**不得**以 UI 兜底（无命令层拒绝不得发布）。
6. **`queued` run 收口路径与实测不符**（实际产生其他错误码或不可重试）→ 修订收口口径并按 ADR-006 附录 B 处理该码（新增码须先登记）；不得放宽 DoD2 断言。
7. **归段口径无法落地** → 停止 DoD0 的「必发事件」断言并回报，另立 ADR 修订 D4 全局事件口径；**不得**仅广播不落盘。
8. **迁移（编号按合入顺序）在既有库升级失败** → 单版本单事务回滚；禁止修改 `0001`–`0003`（AGENTS §8）。
9. **10 次热插拔循环出现孤儿/句柄/内存泄漏** → 修复前不得通过 M7-01（M2-08 三条件脚本复跑）。
10. **新命令实现中发现需要新错误码/警告码** → 先按 ADR-006 附录 B 登记（增行），不得自造。
11. **`runtime_busy` 计数与执行时在途集合不一致导致确认语义被破坏** → 回退为「禁用一律显式确认」的保守口径（另立 ADR 修订命令契约）。

| from → to | 现有用途 | ADR-015 新增用途 |
|---|---|---|

| `degraded → disabled` | 熔断/隔离升级 | 用户禁用（`user_disabled`） |

| `disabled → starting` | 兼容直达启动 | —（仍受命令层校验） |

**D-2 命令矩阵**

| 命令 | 当前状态 | 前置条件 | 结果 |
|---|---|---|---|
| `runtime_disable` | `cold`/`starting`/`ready`/`degraded` | 在途 0 或 `confirm_terminate=true` | 偏好 `enabled=0` → `disabled(user_disabled)` → 受控终止（适用时） |
| `runtime_disable` | 同上 | 在途 >0 且未确认 | `runtime_busy`（不转移、不写偏好） |
| `runtime_disable` | `disabled` | — | `invalid_value`（不转移） |
| `runtime_enable` | `disabled`（非 `untrusted`/`version_mismatch`） | — | 偏好 `enabled=1` → `disabled → cold → starting → ready`；失败按既有 `disabled + reason` |
| `runtime_enable` | `disabled + untrusted/version_mismatch` | 先修复清单/版本 | `NeedsRemedy`（`invalid_value` 映射；不变） |
| `runtime_retry` | `disabled + start_failed` | — | 不变 |
| （启动）清单条目 + `enabled=1`/无记录 | — | 清单校验通过 | 预热（既有路径） |
| （启动）清单条目 + `enabled=0` | `cold` | — | `cold → disabled(user_disabled)`（不 spawn） |
| （启动）清单条目校验失败 | — | — | 不入注册表 + 审计（`runtime.registry_rejected`） |

## 1. 背景

评审 C1/C2：

1. **C1（高）`client_msg_id` 幂等无持久化支撑**：D4 与 M2-01 DoD3 要求「同一 `client_msg_id` 重发不产生重复消息/run」，但附录 C 的 `messages`/`runs` 表均无 `client_msg_id` 列与去重唯一索引；仅内存去重在**核心重启后的重放**会重复入库。附录 E 字段映射表也未覆盖该字段。
2. **C2（高）会话恢复能力未纳入 spike 验证**：T5a/T4 的「重放重试」与 kill -9 后恢复，隐含依赖适配器能用 `sessions.config.native_id` 恢复原生会话并续聊；但 M1-11 spike DoD2 只验证 create/send/stream/interrupt，未验证「进程重启后用 `native_id` 恢复会话」。若目标 Runtime 不支持恢复，崩溃后只能「新建会话重发」，与「重放重试成功」的验收语义冲突。该风险必须在 M1-11（最便宜的验证时点）暴露，不得推迟到 M2-02。

## 2. 决策

| # | 决策 | 落地位置 |
|---|---|---|
| 1 | `messages` 表增加 `client_msg_id TEXT` 与 `UNIQUE(session_id, client_msg_id)`（SQLite 中 NULL 互不冲突，系统/助手消息不参与去重）；重复 `session.send` 返回既有 `message_id`/`run_id`；**去重跨核心重启有效**（持久化支撑） | 设计文档 D4/附录 C；实施计划 M1-03/M2-01 |
| 2 | 迁移落地策略沿用 ADR-004 决策 6：P0 首次迁移可直接包含该列与约束；已应用旧迁移的既有库经 `0002+` 增量迁移补齐 | 设计文档 附录 C；实施计划 M1-03 DoD5 |
| 3 | 会话恢复语义两模式（由 M1-11 结论确定）：**Mode R（原生恢复）** = 用 `sessions.config.native_id` 恢复原生会话续聊、上下文保留；**Mode N（无原生恢复）** = 新建原生会话并重放输入、UI 明示「原生上下文可能丢失」；两种模式下旧 run 均保留审计 | 设计文档 D5；实施计划 M2-02/M3-06 |
| 4 | M1-11 spike DoD2 增加会话恢复验证（进程/运行时重启后用 `native_id` 恢复并续聊）；产出 Mode R/N 结论并写入接入笔记；Gate 1 结论类型扩展为「real-adapter/mock-only + 会话恢复能力」 | 实施计划 M1-11/Gate 1 |
| 5 | 需求 CP-03「异常可恢复」验收口径按两模式收敛；附录 E 增补 `Message.client_msg_id` 与 `Session.native_id` 映射 | 需求文档 CP-03/§3.8；设计文档 附录 E |

## 3. 影响

### 3.1 《设计文档》v1.5

- D4 幂等条目：`client_msg_id` 去重改为存储层持久化支撑（列 + 唯一约束），重启后重放不重复。
- D5：新增「会话恢复与重放重试」实现要点（Mode R/N）；失败场景表「运行中崩溃」按模式收敛。
- A1 验证：spike 范围追加「进程重启后用 `native_id` 恢复会话续聊」与会话恢复能力结论。
- 附录 C：`messages` 表增列与唯一约束；附录 D T5a 通过标准按恢复模式执行；附录 E 增补两行映射。

### 3.2 《需求文档》v0.5

- §6 Message 模型补 `client_msg_id`（幂等键）。
- CP-03 与 §3.8：异常可恢复按 Mode R/N 两模式描述（结论由 A1 spike 给出）。

### 3.3 《实施计划与验收标准》v1.11

- 基线升 v1.5；修订记录追加 v1.11。
- M1-03（messages DDL/差异迁移）、M1-11（恢复验证 + 结论）、Gate 1（结论含恢复能力）、M2-01（重启后幂等断言）、M2-02（按模式验收重放）、M3-06（重放按模式）、§6 #15、§7 映射、§8 基线。

### 3.4 《AGENTS.md》（治理文件）

- §1 必读文档与 §8 表格的版本/基线同步为需求 v0.5、设计 v1.5、实施计划 v1.11（ADR-001–005）；其余 MUST 条目未改动。

### 3.5 不影响的

- 不修改代码、迁移文件、CI 工作流；不新增事件类型；不改 D6 方法集（`session.send` 的 `client_msg_id` 幂等语义自 v1.0 已存在）。
- Mock 适配器可提供 Mode R（原生恢复），用于恢复路径的自动化测试（M2-02M 闭环不变）。

## 5. 后续（未决项）

1. **Mode N 的上下文重建策略**：是否重放本地消息历史或做摘要注入，在 M2-02 接入笔记中记录；若超出「重放输入」能力，另立 ADR。
2. **`runs` 表独立幂等列**：当前经 `messages.run_id` 关联即可（一条输入消息对应一个 run）；若目标适配器无此关联，在 M2-02 证据中说明。
3. **恢复能力声明**：`initialize` capabilities 是否暴露 `session_resume` 标志，P1 多适配器时评估；P0 以 M1-11 结论 + 配置为准。
4. **历史重复 `client_msg_id` 审计**：实现层随 M1-03 DoD5 出具报告。

## 6. 回退条件

1. 若某官方适配器的 `client_msg_id` 语义与 UI 生成方式冲突（如需服务端生成）→ 适配器侧映射为等价幂等键并记录证据；**不得取消持久化约束**。
2. 若 Mode N 被证实为唯一路径且「重放输入」无法满足恢复验收 → 调整 T5a/T4 的「重放重试」口径（降级为「新会话重发 + 明示」），须走新 ADR。
3. 若 `UNIQUE(session_id, client_msg_id)` 与既有数据冲突 → 按 ADR-004 决策 6 的审计流程处理。

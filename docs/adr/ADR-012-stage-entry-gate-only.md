## 1. 背景

1. 设计文档 v1.10 §5 规定：「每个阶段的进入都以前一阶段退出指标 + 触发条件同时满足为准；触发条件用数据说话，不按日历排期」——P1–P6 的「进入触发」均含需求侧统计条件（如「子 Agent 需求 ≥3 次」「企业/合规意向 ≥1 个」「多设备请求 ≥10 个」）。
2. 实施计划的排期规则为「仅依赖驱动：里程碑进入条件 = 前置任务 DoD 全部通过」；产品阶段却采用「退出指标 + 需求触发」双条件口径，导致阶段推进既受门禁约束、又受外部需求统计约束，两套口径不一致。
3. 产品负责人于 2026-09-30 指令：阶段进入统一为门禁驱动——**只要前一阶段门禁（退出标准）通过，即可进入下一阶段**。
4. 复审（2026-09-30）核验无 P0，裁定：①阶段进入保留复核动作，**门禁证据 = 前一阶段验收通过结果**；②§1 降级路径与 §3 失效条件为**直接实施动作**，不受阶段进入条款约束；③Mock-only 验收载体由修改者确认——按 ADR-003 §6.4 原始口径统一为 **Gate 2 等价验收（M2-02 口径）**；④本组修订以 ADR-012 v0.2 承载，四文档随之升版；⑤入库待用户指示后提交。

## 2. 决策

| # | 决策 | 落地位置 |
|---|---|---|
| 1 | **P1–P6 进入触发统一为「前一阶段门禁（退出标准）全部通过」**；阶段门禁 = 该阶段「退出标准」全部通过（非实施计划 Gate 1–4）；前一阶段门禁未通过，不得进入下一阶段 | 设计文档 v1.12 §5 导语 + P1–P6 各节 |
| 2 | **移除全部需求侧触发条件**（清单见头部「取代」行）；相关假设的降级路径（如 A9 多设备请求、A10 数据增长）保留为假设自身重评标志，不再构成阶段进入条件 | 设计文档 v1.12 §5 |
| 3 | **Mock-only beta 情形并入 P0 门禁口径**（沿用 ADR-003，不放宽）：若 P0 为 Mock-only beta，则「首个真实适配器接入完成并通过 **Gate 2 等价验收（M2-02 口径，ADR-003 §6.4）**」为 P0 门禁通过的组成部分 | 设计文档 v1.12 P0/P1 |

## 4. 风险与缓解

- 风险：移除需求侧进入触发后，P1–P6 可能缺少需求验证即按门禁推进。
- 缓解：阶段进入前核对前一阶段验收通过结果（门禁证据，含 Gate 验收报告/证据归档）并留痕；需求信号保留为假设重评标志（A9/A10），不构成进入条件。

## 7. 回退条件

1. **恢复任一阶段的需求触发条件** → 属设计变更：另立 ADR 回收本 ADR，并同步四文档版本；不得静默回写。
2. **阶段推进与门禁证据不符**（未取得前一阶段验收通过结果即进入下一阶段）→ 停止推进，审计阶段状态与门禁记录，按实施计划对应 Gate 的「回退动作」处理。
3. **Mock-only 路径被用于绕过真实适配器接入** → 按 ADR-003 Mock-only 口径纠正；未完成真实适配器接入（Gate 2 等价验收）前不得进入 P1。
4. **直接实施动作被错误挂上阶段门禁**（等待门禁才实施）→ 按决策 7 纠正：直接实施按其自身条件触发，承接另行立任务/ADR 并留痕。

### 决策 3 五段式（问题 2）

- **决策**：登记会话级三档权限模式（`read_only` / `workspace_write` / `danger_full_access`），档位语义与运行时沙箱**同名同序**，矩阵见附录 B；档位既为核心权限门的**权威判定入参**（按会话解析），又**投影**为适配器启动参数（仅新会话生效）。
- **实现要点**：①迁移 `0004+` 落 `sessions.permission_mode`（附录 C 同步 + `verify:m1-03` 绿）；②判定入参：策略评估按会话解析档位（`crates/aether-control/src/permission.rs` 评估路径）；③投影映射表（三运行时 × 三档）登记进 P1-A10 / M7-06 DoD1 并**实测断言**；④命令面：`session_create` 可选 `permission_mode` + `session_permission_mode_set`；⑤`SessionSummary` 回显档位（DTO 增量 + `pnpm --filter @aether/protocol generate/check` 复跑，AGENTS §2.8）；⑥UI：权限模式选择器 + **常驻边界声明一行**（R14，文案见附录 F）。
- **主要风险**：**顶档 = 运行时全权**（任意路径读写 + 命令执行 + 联网 → 数据外泄面）；`allow` 判定**无弹窗 → 事前不可见目标路径**（仅事后审计）；TOCTOU 在顶档**无审批兜底**（D9 原「写入限工作区内」前提失效）；非顶档区外写审批疲劳；文案夸大（把权限门说成沙箱）。
- **缓解措施**：投影（档位 = 运行时沙箱参数，形成运行时侧约束）；**会话级显式选择 + 缺省档收紧为 `workspace_write`**；**降级即失效**（R4，不变量 9）；顶档 `allow` 仍 100% 经网关 + 落审计（不变量 6，`permission.allowed_by_policy`）；区外目标禁软链接/Junction 重解析点（不变量 3）；**常驻边界声明**（R14）与既有 D9 文案纪律；`docs/ADR-014-评审意见.md` §6 残留风险声明随本 ADR 归档。
- **失效条件**：出现**顶档越权 / 数据外泄 / 误操作**事件 → 立即收紧顶档（`exec`/`net` 回 `deny`、区外读写回 `ask`），必要时回退至 v0.1 口径，并**另立 ADR**；企业要求强隔离 → 触发 P3 沙箱前置（D9 原失效条件不变）。

> **决策 3 的独立性**：本条改变了 D9 冻结策略矩阵的多条边（区外读、缺省档区内写、顶档区外读写与 `exec`/`net`），按 AGENTS §2.7/§3 不得与其他决策捆绑默认通过，故列为可单独否决项（§6-2）。**信任级边界声明不变**（设计 §2.1 第 4 条）：权限门仅约束经线协议上报的工具调用，适配器进程内行为不受保护，任何文档与 UI 不得表述为「已隔离适配器内部行为」，亦不得出现「完全权限仍无终端/网络通道」式表述（问题 7）。

## 6. 回退条件

1. **本 ADR 被否决** → P1 计划回退至 v0.3 结构（新增任务与 DoD 增补撤回）；`docs/P1-计划评审意见.md`、`docs/ADR-014-评审意见.md` 保留为评审记录。
2. **决策 3 被单独否决** → 三档不落地，或按 v0.1 收紧口径（区外 `fs.write` = `ask`、`exec`/`net` 恒 `deny`）重提；**不得以 UI 兜底**（无 ADR 不得提供档位入口）。
3. **顶档出现越权/数据外泄/误操作** → 立即收紧顶档（`exec`/`net` 回 `deny`、区外读写回 `ask`）并另立 ADR（D9 失效条件，附录 D-3）。
4. **投影语义不等价**（某运行时无法表达档位，如 Claude `acceptEdits` 边界或 DSH headless preset）→ 该运行时对应档位置灰/降级并登记；不得静默按「部分等价」实现（不变量 8）。
5. **连通性测试被要求限制出站**（推翻 R6）→ 撤回 `provider_test`/`provider_models_fetch` 命令或加白名单，并同步修订 ADR-010 §5-7。
6. **附录 C / 索引计数同步失败** → M5-01 不得通过；禁止「先改库、后补文档」；`verify:m1-03` 未绿不得合入任何 P1 schema 变更。
7. **M7-07/M7-08/M7-09 影响门禁主链** → 按直接实施项性质降级为「P1 内不承诺」，不得推迟 P1 门禁证据归档。
8. **`session.send.references` 导致任一官方运行时失败率上升** → 撤回该字段透传（协议字段保留），引用仅作 UI 侧登记。
9. **新命令实现中发现需要新错误码/警告码** → 先按 ADR-006 附录 B 登记（增行），不得自造。
10. **迁移 `0004+` 在既有库升级失败** → 单版本单事务回滚；禁止修改 `0001`–`0003`。
11. **R16 对价回退（互斥路线）**：若产品要求 M5-06 保留于 P1 → 须改为**明示豁免**（需产品签署，不宜默认），并**恢复** P1 计划的 13 处级联（§1.1/§1.3/§1.4/§1.6/§2/M8-01/§6/§7/§8/§9）与设计 §5 P1「决策变更」的 D3 预案行；两种路线**不得并用**。
12. **R15 基准语义回退**：若实现中发现「换根仅新会话生效」与 P0 断言不可调和 → 停止实现并回报（须走 ADR 修订），**不得**为通过测试把既有会话静默切到新基准（AGENTS §6）。

## 附录 B：D9 三档矩阵与不变量（按 R10/R11 定稿）

**档位定义**（会话级；**与运行时同名同序**，问题 24）：

| 值 | 显示 | 语义（对齐运行时） |
|---|---|---|
| `read_only` | 仅查看 | 只读；写请求一律 `deny`（无升权路径） |
| `workspace_write` | 工作区内修改（**缺省**） | 工作区内写免逐次审批；策略外动作（区外写、越权命令）需审批 |
| `danger_full_access` | 完全权限 | 运行时可读写任意路径、执行命令与联网（顶档；本门不做能力收敛） |

**矩阵**：

| 资源:动作 | `read_only` | `workspace_write`（缺省） | `danger_full_access` |
|---|---|---|---|
| `fs.read`（工作区内 / 外） | allow / allow | allow / allow | allow / allow |
| `fs.write`（工作区内） | deny | **allow** | allow |
| `fs.write`（工作区外） | deny | **ask**（300s → deny + 审计） | **allow** |
| `exec`（上报型工具调用） | deny | deny | **allow**（**仅门层**；R11/R13） |
| `net`（上报型工具调用） | deny | deny | **allow** |
| `browser` / `mcp` | n/a | n/a | n/a（功能未启用） |
| 记忆文件白名单 | deny | 被区内 `allow` 覆盖（留审计 + 1MB 上限） | 同左 |

> **一致性 delta 备忘（评审意见 §5-2，按 R10 落文、可回退）**：区外 `fs.read` 三档均 `allow`；缺省档区内 `fs.write` 由 P0 的 `ask` 改为 `allow`（**会明显减少默认档审批弹窗**，即 P0 权限回环在缺省档主要覆盖区外写）；如需回退，请指定后按 §6-2 处理。

**不变量（12 条）**：

1. 档位与运行时**同名同序**；缺省 `workspace_write`；档位为**会话级**参数，随 `session.create` 与 `session_permission_mode_set` 生效；**档位变更入审计**（`actor`/`action`/`resource=session`；P0 最小审计集不含档位变更，故在此显式登记，问题 P2-8）。（问题 24）
2. 档位约束「**写的作用域**」，**不约束读**：`fs.read` 区内/区外三档均 `allow`（R1/R10）。
3. 路径校验流程不变：canonicalize（解析软链接 / Junction / 重解析点）→ 前缀比较（Windows 大小写不敏感）；Windows 拒绝清单（UNC 与扩展前缀、8.3 短名、ADS、尾随点/空格、保留设备名、跨卷 Junction）不变；**区外目标要求解析后不含软链接/Junction 重解析点**（问题 12：D9 原「写入限工作区内」前提失效后的补偿）。
4. **所有 `ask` 走完整审批流**：`permission.request` → 策略判定 → 入队（`permissions.status=pending`）→ UI（原文 + 规范化对照）→ `permission.resolve`；**300s 超时 → `deny` + 审计**（问题 1：原不变量 3 重写）。
5. **`deny` 类决议不呈现 allow 按钮**（含 `read_only` 档写请求与区外写 `deny`）；不提供 UI 升权后门（问题 1：原不变量 7 重写）。
6. **顶档 `allow` 仍 100% 经网关并落审计**（`permission.allowed_by_policy`；`crates/aether-control/src/permission.rs:353-383`），**零直通口径不变**（AGENTS §2.7；M2-10 探针回归；C4）。
7. `exec`/`net`：低档 `deny`；`danger_full_access` 档 `allow`（**仅门层判定**；终端面板 PF-05 维持 P3，R11/R13；问题 26）。
8. **投影（R12）**：档位既为核心权限门的权威判定入参（按会话解析），又投影为适配器启动参数（映射表见附录 C-3）；**仅新会话按新档位启动**，在途会话保持原沙箱参数；语义等价性由 M7-06 DoD1 逐条登记并**实测断言**（问题 25；原「不经适配器」表述废止）。
9. **档位变更后，既有 `session` / `always` 授权按新档位重新求值**（R4；`permissions.scope` 枚举含 `once`/`session`/`always`，见 `migrations/0001_init.sql:111`，M6-01 正是引入 `always` 的任务）：**`read_only` 下不因任何既有授权放行写请求**（防「先开后关」绕过）；已 `pending` 票据按原决议收口，不被追溯改写。断言用例：顶档授 `always` → 降级 `read_only` → 写请求按新档位判 `deny`（P1-1）。
10. **记忆文件白名单**：仅工作区内记忆文件；`read_only` 档恒 `deny`（**含 D14 记忆写入**——上层后果：该档下 `memory.append/write` 被拒并留审计，UI 需提示；问题 22）；`workspace_write` 与顶档被区内 `allow` 覆盖，保留审计与 1MB 上限。
11. **权限基准按会话创建固定（R5 + R15）**：基准 = 会话创建时 `sessions.workspace_id` 对应工作区根（`workspace_id IS NULL` → 数据目录）；**`workspace_set` 换根仅对新会话生效**，既有会话保持原基准；**`session_workspace_assign` 不重算**（防改派放大权限）。入口关系（`workspace_set` 与 `session_workspace_assign`）由 P1-A12 定界；计划 M7-08 DoD2 同步，DoD6 回归口径按新语义（问题 6）。
12. **常驻边界声明（R14）**：权限选择器弹层常驻一行文案（定稿见附录 F）；**任何文档与 UI 不得出现「完全权限仍无终端/网络通道」式表述**（设计 §2.1 第 4 条；问题 7）。

**D-3 D9 修订条文（完整；替换 D9 决策句、矩阵、风险、缓解、失效条件）**

> **决策（修订）**：MVP 采用权限网关 + 内置固定策略 + 阻塞式审批；不支持用户自定义规则与 OS 沙箱。**`exec` 在 `read_only` / `workspace_write` 档禁用；`danger_full_access` 档放行（仅门层判定：上报型 `exec`/`net` 调用可被判 `allow`；内嵌终端面板 PF-05 仍为 P3，不因本档开放）**。权限门仅约束适配器通过线协议上报的工具调用；适配器进程内部行为（含其自身执行的 shell 命令）不受本门约束，属信任级模型的已知边界（P3 沙箱后由 OS 隔离兜底）。
> **实现要点（修订）**：档位为会话级参数（`sessions.permission_mode`，迁移 `0004+`），值与运行时**同名同序**、缺省 `workspace_write`；档位既为策略判定的**权威入参**（按会话解析），又**投影**为适配器启动参数（仅新会话生效；映射表见 ADR-014 附录 C-3）。**策略矩阵替换为下表（复审 P2-2：矩阵本体直接内联，冻结文档自含）**：
>
> | 资源:动作 | `read_only` | `workspace_write`（缺省） | `danger_full_access` |
> |---|---|---|---|
> | `fs.read`（工作区内 / 外） | allow / allow | allow / allow | allow / allow |
> | `fs.write`（工作区内） | deny | allow | allow |
> | `fs.write`（工作区外） | deny | ask（300s → deny + 审计） | allow |
> | `exec`（上报型工具调用） | deny | deny | allow（**仅门层**；PF-05 维持 P3） |
> | `net`（上报型工具调用） | deny | deny | allow |
> | `browser` / `mcp` | n/a | n/a | n/a（功能未启用） |
> | 记忆文件白名单 | deny | 被区内 `allow` 覆盖（留审计 + 1MB 上限） | 同左 |
>
> 路径校验细则、审批流、会话状态与审计口径不变；**12 条不变量以 ADR-014 附录 B 为准**（含顶档 `allow` 仍经网关 + 审计、R4 降级失效、R5/R15 基准按会话创建固定、R12 投影、R14 常驻文案）。
> **主要风险（新增）**：顶档 = 运行时全权（任意路径读写 + 命令执行 + 联网）→ 数据外泄面；`allow` 判定无弹窗 → 事前不可见目标路径（仅事后审计）；TOCTOU 在顶档无审批兜底；非顶档区外写审批疲劳；文案夸大（把权限门表述为沙箱）。
> **缓解措施（新增）**：档位投影形成运行时侧约束；会话级显式选择 + 缺省档收紧；降级即失效（R4）；顶档 `allow` 仍经网关 + 全量审计；区外目标禁软链接/Junction 重解析点；UI 常驻边界声明（R14）。
> **失效条件（新增）**：顶档越权 / 数据外泄 / 误操作 → **立即收紧顶档**（`exec`/`net` 回 `deny`、区外读写回 `ask`）并另立 ADR；企业要求强隔离 → 触发 P3 沙箱前置（原失效条件不变）。

**D-4 §4 不做清单 #9（终端面板）原因栏加注**

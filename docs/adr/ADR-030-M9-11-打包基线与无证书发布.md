# ADR-030：M9-11 打包基线与 Windows 无证书发布政策

| 项 | 内容 |
|---|---|
| 状态 | **已接受（用户裁定 2026-10-30；随 M9-11 落地）**；评审签核随 M9 Gate G6 归档 |
| 日期 | 2026-10-30 |
| 修订 | ADR-029 v0.4 §8.1/§15-10（R9）关于体积/RSS/签名门禁的口径；M9-11 DoD-7 与 G6 门禁 |
| 关联 | P2 计划 v0.6；M9-01 `freeze/thresholds.json`；`docs/M9-11-证据.md` |

## 1. 背景与事实

M9-11 首轮打包（Electron 45 + 3×Bun 单文件适配器 + `aetherd`）实测：

| 指标 | 首轮 | 冻结阈值 | 结论 |
|---|---|---|---|
| release MSI | 233,693,184 B | 191,717,376 B（1.5×Tauri HEAD） | 超 21.9% |
| idle RSS | 528–536 MiB | 500 MiB | 超 6–7% |
| UI ready | 5.8–6.9 s | 5 s | 超（G7 项） |
| 10 会话 | 725.76 MiB | 1.2 GiB | 通过 |

根因（非残留代码/资源）：

- Electron 45 运行时（`Aether.exe` 238 MiB + Chromium 资源）替代系统 WebView2，必须随包；
- 3 个官方适配器原先各自 `bun --compile`，**每个内嵌一份 Bun 运行时（约 92 MiB）**；
- `aetherd` 14.2 MiB、app.asar 0.5 MiB；已启用 `asar`、无 sourcemap、`compression=maximum`、
  `electronLanguages=[en-US,zh-CN]`，无可观的「误打包」项。

## 2. 决策

### D-030-1 适配器共享宿主（包体优化，不放开体积门禁）

- 新增 `packages/adapter-host`：**一个 Bun 宿主二进制**（`aether-adapter-host`）+ `--adapter <id>` 分发到
  各适配器 CLI；线协议、参数、`--launch-token`、stderr 前缀、能力声明均不变。
- `runtime-bundle/runtimes.json` 仍登记 3 个官方运行时，`program` 同为宿主、`args=["--adapter",id]`
  （ADR-015 schema 已允许 `args`）；Mock 仅测试构建（`main-test.ts`）。
- 结果：release MSI **160,219,136 B（152.8 MiB）**，保持冻结体积门禁
  `≤191,717,376 B` **通过**；不修改体积阈值。

### D-030-2 idle RSS 与 UI ready 基线（Electron 口径）

- `idle RSS` 硬阈值：**500 MiB → 600 MiB（629,145,600 B）**。
  依据：Electron 进程模型（main/renderer/GPU + daemon + 启动预热的 2 个适配器；实测 528–536 MiB），
  预适配器约 72 MiB 属 ADR-015/M2-08 的「启动预热」语义，不属可删残留。
- `UI ready` 硬阈值：**5,000 ms → 8,000 ms**。
  依据：同步启动预热（D2 启动序列：孤儿清理 → 适配器预热）在打包产物上实测 5.8–6.9 s；
  该预热保证会话创建 <2 s 与首条消息低延迟，属产品取舍。G7 仍记录实测值。
- 其余阈值不变（窗口 1.5 s、initialize 2 s/10 s、会话创建 2 s、10 会话 1.2 GiB、P95 150 ms）。

### D-030-3 Windows 无证书发布（对齐 Proma 口径）

- **Windows**：无 Authenticode 证书时允许发布 **unsigned MSI**；必须：
  1. `m9-11-build-manifest.json` 记录 `signing.unsigned_release=true`；
  2. 归档 SHA256SUMS；
  3. 发布说明给出 SmartScreen「更多信息 → 仍要运行」指引；
  4. 不声称「已签名」；`pnpm verify:signatures` 在 unsigned 场景输出 `UNSIGNED` 说明并按政策通过。
- **macOS**：仍必须 Developer ID 签名 + hardened runtime + 公证 + `stapler`；缺失即 G6 不通过
  （Gatekeeper 无「仍要运行」路径；与 Proma 的 macOS 证书流程一致）。
- Windows 后续获得证书时，直接配置 `CSC_LINK`/`AETHER_WIN_CERT_FILE` 即可恢复严格校验；
  该政策不删除签名/时间戳校验代码。

## 3. 影响与门禁

- `docs/M9-01-baseline/freeze/thresholds.json`：`runtime.idle_rss_max_bytes=629145600`、
  `startup.ui_ready_max_ms=8000`；manifest 对应哈希同步更新。
- `pnpm verify:m9-01-baseline`、`pnpm verify:m9-11`、`pnpm smoke:installer` 采用新阈值。
- G6：Windows 安装/卸载/体积/RSS/10 会话/无证书发布可签；macOS per-arch DMG/签名/公证仍为
  G6 必需项（本机无 macOS，证据标注未验证）。
- 本 ADR 不改变命令面/事件/错误码/迁移/设置键，不新增运行时。

## 4. 备选方案（未采纳）

| 方案 | 原因 |
|---|---|
| 删除 Electron GPU/WebGPU DLL 或裁掉 Chromium 组件 | 破坏渲染/兼容性，收益不足 |
| 适配器下载安装（瘦包） | 破坏离线安装、引入供应链/签名新面；ADR-008 三官方需随包 |
| 关闭启动预热（lazy） | 改变 ADR-015/M2-08 启动矩阵与会话首条消息时延；需另立 ADR |
| 维持 191.7 MB 且保留 3 份 Bun 运行时 | 物理上不可达（Electron + 3×92 MiB） |

## 1. 背景

《设计文档》v1.3 / 《需求文档》v0.3 / 《实施计划与验收标准》v1.8 冻结前复核发现以下不一致或缺口，评审确认必须修复（5 类必改 + 5 类中低优先同步）：

1. **D4/D8 存储降级语义冲突**：D8 允许「存储恢复 `normal` 持续 30s → 自动解除隔离并重启适配器」，与 D4「`persist_degraded` 只读必须修复外部条件 + 重启核心 + 启动自检才恢复」互相矛盾；未区分「写队列高水位（毫秒级、可自动回落）」与「持久化降级（不可自动热恢复）」。
2. **D7 IPC 命令面缺口**：备份列表/恢复、核心重启、run 重试、适配器重试/启用、工作区设置均无 IPC 命令，M3 任务无法落地。
3. **M2-10 依赖未同步**：仍写「依赖 M2-02、M2-03」，未同步 mock-only 路径（M2-02M）。
4. **1MiB 帧上限与 IPC 消息上限冲突**：D7 允许消息文本 ≤1MiB，而 D6 单帧上限 1MiB——1MiB 文本加信封/转义开销必然超帧，合法消息会被断连。
5. **Windows Job Object 终止机制未明确**：仅写「用于进程树回收」，未定义 spawn 纳入 Job Object 与终止 API 顺序（`TerminateJobObject` / `taskkill /T /F`）。
6. **中低优先同步项**：`events UNIQUE(session_id, seq)` 迁移策略需明确（P0 首次迁移可直接包含；0002+ 仅用于已有库）；D5 缺状态恢复转移（`degraded → ready`、`disabled → cold/starting`）；实施计划任务总量与 M2-02/M2-02M 互斥计数需核对；CP-05「资源配额」时点需标注 P3（P0 仅监控告警）；SE-03 需补「P0 不承诺记录所有 Agent 操作」的明确表述。

## 2. 决策

| # | 决策 | 落地位置 |
|---|---|---|
| 1 | **存储降级语义分层**：写队列 >4096（L2）为**临时背压**（事务积压毫秒级回落，队列回落即恢复，不改变存储状态）；`persist_degraded` 为**不可自动热恢复状态**，恢复 = 修复外部条件 + 重启核心 + 启动自检通过；`persist_degraded` 期拒绝新写入/新 run、不广播未落盘事件、在途 run 置 `cancelled`；**删除 D8「存储恢复 normal 30s 自动解除并重启适配器」歧义**，适配器隔离解除仅以写队列回落（≤1024 持续 30s）为条件 | 设计文档 D4/D8；实施计划 M1-05/M2-04/M3-06/M4-02、§6 #8/#10 |
| 2 | **D7 IPC 命令面补齐 7 个命令**：`backup_list`、`backup_restore`、`app_restart`、`run_retry`、`runtime_retry`、`runtime_enable`、`workspace_set`；每个命令补参数校验（枚举/ULID/终态/白名单/canonicalize/同步盘拒绝；`app_restart` 需 `confirm:true`） | 设计文档 D7；实施计划 M1-08/M1-10/M3-04/M3-06/M3-08 |
| 3 | **M2-10 依赖修正**：改为「M2-02 或 M2-02M、M2-03」（mock-only 路径下以 Mock 回环执行） | 实施计划 M2-10/§1.2/Gate 2/§7 |
| 4 | **帧上限冲突解决（采纳方案 A）**：线协议单帧硬上限提高到 **2MiB**；`artifact_ref` 引用帧仍必须 **<1MiB**；普通行 **>2MiB 断连**（含声称 `artifact_ref` 的超限帧）。方案 B（IPC 消息文本降到 900KB）不采纳 | 设计文档 D6/附录 D；实施计划 M1-09/M2-09、§6 #18 |
| 5 | **Windows Job Object 终止机制**：适配器 spawn 时纳入 Job Object；终止**优先 `TerminateJobObject`**（整树立即回收），**辅以 `taskkill /PID x /T /F` 兜底**（句柄失效/未纳入时）；Job Object 仅用于进程树回收与资源管理，**不是文件/网络沙箱** | 设计文档 D2/D5、附录 D；实施计划 M1-10/M2-08/M4-01、§6 #3/#15/#17 |
| 6 | **events UNIQUE 迁移策略**：P0 **首次迁移可直接包含** `UNIQUE(session_id, seq)`；**0002+ 仅用于已应用旧迁移的既有库**（落地前先做历史重复 seq 审计，ADR-003 §6） | 设计文档 D4/附录 C |
| 7 | **D5 状态恢复转移**：`degraded → ready` = 触发原因解除后监督器自动重启（`degraded → starting → ready`）；`disabled → cold/starting` = 仅人工动作（`runtime_retry` / `runtime_enable` / 修复后重启应用），`untrusted`/`version_mismatch` 必须先修复清单/版本 | 设计文档 D5；实施计划 M1-10 |
| 8 | **CP-05 资源配额时点**：资源配额为 **P3** 交付；P0 仅监控与告警（SE-04） | 需求文档 CP-05/§3.8；设计文档 附录 A |
| 9 | **SE-03 审计口径**：明确「**P0 不承诺记录所有 Agent 操作**；完整审计延后 P1/P3」 | 需求文档 SE-03/§3.8；设计文档 §2.1 点 5/D9 |
| 10 | **任务总量与互斥计数核对（双口径）**：文档条目 **37 项 = M1 11 + M2 12（M2-01…M2-11 + 互斥替代 M2-02M）+ M3 8 + M4 6**，§7 映射表按条目口径列出 37 行；互斥执行口径 **36 项**（M2-02/M2-02M 合 1 项）；M2-11 为条件任务，A1 未选择 DSH 时移出排期，实际执行 **35 项** | 实施计划 §1 汇总 |

## 5. 后续（未决项）

1. **2MiB 帧上限实测**：M1-09/M2-09 执行时验证；若官方适配器存在合法的 >2MiB 普通帧，须另立 ADR 复核（不得静默放宽）。
2. **Job Object API 绑定**：`windows` crate（或等价）的 `TerminateJobObject` 可用性与 Windows 10 1809+ 行为在 M1-10 证据中记录。
3. **`workspace_set` P0 语义**：仅对新会话生效（记忆注入/权限基准目录），已有会话迁移不在 P0（P1 评估）。
4. **`app_restart` UX**：重启前的未保存状态处理在 M3-06 落地时记录为任务证据。
5. **仓库实现差异（已挂接任务，落地后关闭）**：现有实现仍为 16MiB 帧、`0001_init.sql` 无 UNIQUE；已挂接实施计划 **M1-03 DoD5**（既有库走 0002+ 增量迁移，含历史重复 seq 审计）与 **M1-09 DoD8**（16MiB → 2MiB 有界增量读取器替换并回归 T10）；两项 DoD 通过即关闭本项。
6. **AGENTS.md 表述（已关闭，v0.3）**：AGENTS.md §1/§8 的版本、路径与基线，§2.3–§2.7 的 MUST 口径已与三份文档对齐（线协议表述、Job Object 终止、权限边界、迁移策略、帧上限）；差异修正记录见 §8 v0.3。

## 6. 回退条件

1. **2MiB 仍与 IPC 上限冲突**（极端转义场景）→ 回到方案 B（IPC 文本降 900KB）或提高帧上限，须走 ADR。
2. **Job Object 在目标 Windows 版本不可用/行为异常** → 退回进程组 + `taskkill /T /F`，记录能力降级。
3. **`persist_degraded` 恢复检测不可靠**（无法确认外部条件已修复）→ 保持只读并提供诊断导出，修复流程另立 ADR。
4. **新命令参数校验与既有 D7 框架冲突** → 以 D7 强制校验框架为准调整命令定义，须记录证据。

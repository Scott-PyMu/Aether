## 1. 背景与触发

设计 A10 假设「单用户 12 个月内事件库 <5GB」，D3 以单文件 SQLite + WAL + 单写者承载。ADR-014 §7 R16 把「事件分库预案验证」从 P1 延后到 P2；M10-08 要求按 D3 失效路径对 `events.db` 分库预案做压测验证，**本任务不实施分库**，只给出「保留单库 + 保留策略充分」或「需分库 → 另立 ADR」的二选一结论。

本 ADR 冻结压测数据集、指标、判定阈值、证据格式，避免 M10-08 用不可复现的「感觉」得出结论。

## 2. 决策

### D-038-1 压测范围与数据集

- **目标数据集**：`events` 表接近 **5 GiB**（`db+wal` 合计），≥ **20,000,000** 行（按中位事件 ~256B 估算；以实际行大小校准）；包含 `message.delta`（大头）、`usage`、`log`、`run.*`、`permission.*`、`session.*` 等混合类型；每会话 `seq` 连续、`UNIQUE(session_id,seq)` 成立。
- **构造脚本**：`scripts/test/m10-08/gen-events-dataset.mjs`（可重复；固定 seed；输出 `dataset.json`：行数、类型分布、字节数、sha256、机器信息）；**不依赖外部凭证**；生成到临时数据目录，不污染用户库。
- **压测脚本**：`scripts/test/m10-08/bench-events.mjs`：
  1. 10 并发写入（模拟 run/event 写入；每会话 1 writer，`seq` 单调）；
  2. 补读（`messages_page`/`last_seq`，10 会话并发）；
  3. 启动 `quick_check`（冷启动计时）；
  4. 备份（`VACUUM INTO`）/恢复（复制 + `quick_check` + 迁移）耗时；
  5. 库增长曲线（每小时采样 db+wal 大小）；
  6. 单库 vs 分库方案（分库仅做**同数据集对照**：按会话/时间分片到 N 个 DB；不改变产品 schema/命令面）。
- **机器信息**：OS/CPU/RAM/磁盘类型/文件系统/SQLite 版本/编译选项；每次运行记录到 `docs/M10-08-证据.md`。
- **可重复性**：固定 seed/批次/并发/时长；至少 3 次取中位数/P95；异常样本保留；不得静默跳过。

### D-038-2 指标与判定阈值（硬）

| 指标 | 采集 | 保留单库阈值 | 分库触发 |
|---|---|---|---|
| 单库写 P95 | 10 并发、≥10min 稳定窗口 | **≤50ms** | >50ms 持续 ≥10min |
| 补读 P95 | `messages_page`/`last_seq` 10 并发 | **<150ms** | >150ms 持续 ≥10min |
| 启动 `quick_check` | 5GB 库冷启动 | **≤30s** | >30s |
| 备份耗时 | `VACUUM INTO` 5GB | **≤600s** | >600s |
| 恢复耗时 | 复制 + `quick_check` + 迁移 | **≤900s** | >900s |
| 库增长 | 12 个月投影 | **<5GB** 或保留策略可压到 <5GB | ≥5GB 且保留策略不足 |
| 失败 | 写失败/恢复失败/`quick_check` 失败 | **0** | ≥1 次不可恢复失败 |

- 阈值与 `docs/M10-00-登记表.json` 的 `limits.sharding` 一致；常量级调参须记录证据（AGENTS §3），不得放宽判定。
- **不掩盖退化**：任一指标越线必须写入判定表并给出原因/复现；不得以平均值掩盖 P95/长尾。
- 分库方案对照必须用同一数据集/机器/并发；分库若不能改善写 P95/恢复，记录「不采用」。

### D-038-3 判定与输出

M10-08 证据必须二选一：

1. **保留单库 + 保留策略充分**：全部指标在阈值内，且 12 个月投影 <5GB 或 ADR-021 保留策略可压到 <5GB；输出「保留单库」结论 + 指标表 + 复跑命令。
2. **需分库**：任一阈值越线/不可恢复失败；输出「需分库」结论 + 判定表 + 建议分片键（会话/时间）、迁移成本、影响面；**另立 ADR 并升设计文档**，本任务不实施。

- 证据：`docs/M10-08-证据.md`（数据集、机器信息、指标、判定表、复跑脚本、原始日志/哈希）；`pnpm verify:m10-08` 校验脚本存在/指标字段/结论二选一。
- 结论若为「需分库」，M10-08 仍算完成（DoD 允许二选一），但 G13 前必须完成新 ADR/设计升版；否则 G13 不通过。
- 不实施分库：不新增 `events_*` 表/迁移/命令/设置键；不改变 0001–0009。

### D-038-4 与保留策略的关系

- 单库结论必须同时验证 ADR-021 保留策略：`message.delta`/`usage`/`log` 按 30 天清理 + 先归档后删除；清理后库增长曲线下降/稳定。
- 若保留策略已能压到 <5GB，即使原始增长 >500MB/月，也可判「保留单库 + 保留策略充分」，但必须附 12 个月投影与清理后数据。
- 归档/备份耗时按 D13/ADR-020/021 口径；不因分库验证改变 M9 基线。

### D-038-5 安全与运维

- 压测使用临时数据目录/合成数据；不含真实用户数据/密钥；不写用户库。
- 分库对照脚本只读源库、写临时目录；结束后清理；不改变产品 DB。
- 结果/日志脱敏；机器信息不含用户名/绝对路径（可用 `<home>` 占位）。
- 不引入新依赖；如需分库原型依赖，先查 `deny.toml` 并另立 ADR。

## 4. 主要风险与缓解

| 风险 | 缓解 | 失效条件 |
|---|---|---|
| 数据集不可复现 | 固定 seed/脚本/机器信息/哈希 | 无法复跑 → G13 不通过 |
| 指标只报平均 | 强制 P95/长尾/失败计数 | 掩盖退化 → 判定无效 |
| 分库对照不公平 | 同数据集/机器/并发；记录差异 | 对照不可比 → 重跑 |
| 压测污染用户库 | 临时目录/合成数据；只读源库 | 污染 → 停止并恢复 |
| 结论与阈值不一致 | 登记表 + 脚本校验 + 证据判定表 | 不一致 → 修正后重跑 |
| 分库范围蔓延 | 本任务只验证不实施；需分库另立 ADR | 直接改 schema → 拒绝合入 |

## 5. 备选方案（未采纳）

| 方案 | 原因 |
|---|---|
| 直接分库（先实施后验证） | 违反 D3/ADR-014 R16；成本/风险高 |
| 只看库大小不压测 | 无法验证写 P95/恢复；结论不可靠 |
| 用生产真实库压测 | 隐私/数据风险；不可复现 |
| 以平均值代替 P95 | 掩盖长尾/退化 |
| 分库后保留双写 | 复杂度/一致性风险；需专门 ADR |

## 6. 契约登记汇总

- 命令/事件/设置键/迁移：0。
- 脚本：`gen-events-dataset.mjs`、`bench-events.mjs`、`verify:m10-08`（M10-08 落地）。
- 证据：`docs/M10-08-证据.md`、原始日志/哈希。
- 判定：保留单库 / 需分库（二选一）；需分库另立 ADR。

## 7. 回退条件

1. 本 ADR 被否决 → M10-08 保持「未解锁」；不压测/不分库；D3 单库继续。
2. 压测污染用户库 → 立即停止，按恢复手册回滚；不得继续。
3. 结论「需分库」但未另立 ADR → G13 不通过；不得直接改 schema。
4. 阈值需调整 → 记录常量级调参证据；改变判定语义须另立 ADR。

## 1. 总体结论

- **文档完整性**：草案具备来源（M3-03 证据 §5 遗留 1–3）、事实核对（F1–F5）、归属方案与不采纳项、拟应用修订（R1–R7）、决策点（D1–D4）与批准记录位，结构完整；但存在 1 处事实前提不成立（F3/§1.4「分组已就绪」）、1 处出处引用不准确（F2）与方案 B / 基线同步范围未列全。
- **一致性状态**：与设计文档 D9（`设计文档.md:535`）、19 条边状态机（`session_state.rs:50-74`）、M2-03 冻结并发口径（`docs/M2-03-证据.md` §4 边界 2）、Gate 2 报告（`docs/M2-Gate2-验收报告.md:50-51`）、v1.15 先例（`实施计划与验收标准.md:34`）总体一致。主要不一致集中在**验证条件可执行性**（分组 E2E）与**证据/归属口径**。
- **最大风险**：R2b 的关闭条件「会话列表『等待审批』分组出现/消失（M3-03 锚点；前端已就绪，无 UI 改动）」按现状无法验证——前端为扁平列表、无分组 DOM 与已登记锚点；另 R5 的 E2E 证据归属与任务时序（M4-04 先于 M4-05）冲突。
- **结论**：不建议照准；修订重点为 R2b/R3/R4/R5 与新增任务 M3-12 登记，修订后复审。

## 6. M3-12 登记要件建议

- **任务名（拟）**：M3-12 会话等待态写入与等待审批分组。
- **对应决策/主题**：D9、UI-01/UI-02、SE-02（权限中心主题）。
- **依赖**：M3-02、M2-03（集成层硬依赖）；生产 ask E2E 条件依赖 M3-08（网关 + 工作区基准）；回归依赖 M2-05/M2-10 证据口径。
- **DoD 骨架（建议）**：
  1. 等待态写入：同会话 pending 票据 0→1 置 `waiting_permission`、1→0 回程；回程仅当当前状态为 `waiting_permission` 时生效（非等待态 no-op）；状态仅由 `SessionManager` 落行并广播 `session.status_changed`（复用既有 19 边状态机；不新增命令/事件/迁移）；
  2. 回程合法性：allow / deny / 超时 / 取消 + run 失败收口路径；取消 × 超时/决议并发幂等（票据摘除唯一仲裁点）；
  3. 重启：`restore_pending` 不标记等待态；恢复票据决议/超时后无回程、无多余 `session.status_changed`；
  4. 多会话并发等待断言（裁定 6；服务层并发 pending 能力默认保留）；
  5. 会话列表分组：按 UI-UX 组序（运行中 → 等待审批 → 失败 → 其他）、空组隐藏；UI-UX §7.3 锚点登记；前端集成 E2E（出现/消失）；
  6. 生产路径 E2E（M3-08 关闭后）：真实工作区 ask → 分组出现/消失；
  7. 回归：M2-05 取消路径、M2-10 零直通、M3-03 队列口径、M3-02 verify 静态检查（分组改动触及 `SessionWorkbench` DOM）。
- **验证入口**：`pnpm verify:m3-12` + CI job + 证据归档（沿用 M3-0x 证据文档与 verify 脚本口径）；无命令/事件/迁移变化，T14 保持无变更。

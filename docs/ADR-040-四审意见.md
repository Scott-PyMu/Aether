## 1. 总体结论

### 1.1 文档完整性

**良好。** v0.4 已形成从“背景/假设 → 唯一决策 → 选择性计划/严格匹配 → 状态机/写门 → 后台全量/周期/运行期调度 → `health`/UI/指标/兼容 → sidecar → 安全/残余风险/故障注入 → 实施/DoD/性能/no-go → 基线/契约 → G13/任务 → 失效/回退 → 签核/变更记录”的完整闭环；三审指出的冷缓存 dirty1、调度器生命周期、验证基线、旧客户端发布门、ADR-039 版本/任务计数、shutdown/import 均已落到文本。

### 1.2 一致性状态

**良好。** 关键契约一致：

- `health.storage_check` v2（`contract_version=2`、`planned_shards`/`skipped_shards`/`full_coverage`）与旧 v1 兼容矩阵、M10-03 发布门闭合；
- `verify:m10-10`（ADR-039 基线）+ `verify:m10-14`（当前/Level 1/Level 2）分工闭合；
- §4.3 Q5/Q6 no-go 闭合，冷缓存 dirty1 25–30s 已统一严格 no-go；
- ADR-039 v1.1 固定、P2 v0.15 14 项任务表固定；
- 运行期调度器/基线/`background_check_completed`/`clean_start_count` 规则闭合；
- §7 Level 1/2 回退范围闭合。

剩余差异均为 P2 表述/实现边界，见 §2。

### 1.3 最大风险（均为 P2/实施期）

1. **§3.2 与 §5 的 7 天窗口措辞**：§3.2 写“运行期调度器在 7 天内触发”，§5 定义“正常 ≤7 天；sleep/wake/时钟跳变后 ≤7 天+1 个轮询周期（默认 1h）”。需统一为“7 天目标 + 最大 7 天+1h”或收紧定时器，并由安全/QA 在签核时确认。
2. **调度器监督失败的 `health` 状态**：`persist_degraded` + `degrade_trigger=integrity_failure` + detail 已定义，但未明确 `storage_check.state=failed`/`error`/`background_check_completed` 的写回；需保证 UI S-08 与 health 契约一致。
3. **`PERIODIC_CHECK_TIMEOUT_MS=30min`**：5.22 GiB/HDD 的 `integrity_check` P99 可能超过 30 分钟；需在 DoD-6 实测并调整/记录，否则周期检查会被误判超时降级。
4. **`import_in_progress` 的来源/复位**：§4.1 仅列 `storage_check.rs` 读取，未列导入协调器暴露/复位；需确保导入崩溃/回滚后标志复位，避免调度器永久延后。
5. **`verify:m10-14:level2` 的“基线构建/fixture”覆盖**：需明确固定 ADR-039 基线构建不可用时，“回退演练证据 + `verify:m10-10`”是否足以证明 Level 2 行为，避免只验证片段。
6. **DoD 引用编号**：§0.3/§4.1 出现 “DoD-11/14”“DoD-3/5/14”，但 §4.2 DoD 只有 1–10 项；应改为 `§3.3 #11/#14` 或 DoD-3/5，避免测试映射歧义。

### 1.4 安全专项

未发现“把权限控制误述为沙箱”；ADR-040 不新增外部信任边界、命令面、事件、设置键、迁移或第三方依赖。残余风险的写入判据已可执行，运行期调度器监督/超时/迟到结果/ shutdown/import 已落文本；P2 项（7 天窗口措辞、调度器失败状态、超时常量）是安全/QA 签核前仍需收口的证据边界。

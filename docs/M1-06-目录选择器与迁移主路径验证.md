## 1. 抽象接口（可注入目录选择器）

```rust
// crates/aether-tauri/src/picker.rs
pub trait DirectoryPicker: Send + Sync + 'static {
    fn pick_directory(&self) -> Result<Option<PathBuf>, PickError>; // Ok(None) = 用户取消
}
```

| 实现 | 用途 | 说明 |
|---|---|---|
| `TauriDialogPicker` | 生产 | `tauri_plugin_dialog::DialogExt::blocking_pick_folder`；经 `startup_pick_target` 在 `spawn_blocking` 调用（不占主线程） |
| `FixedDirectoryPicker` | 集成测试 / E2E | 返回预设路径 / 取消 / 错误；脚本化序列（队列 >1 按 FIFO，=1 固定返回） |

- 分层：目录选择器属桌面壳（系统对话框）能力，定义在 `aether-tauri`；`aether-core` 保持纯模型（AGENTS §2.1）。
- 接线：`IpcState` 持有 `OnceLock<Arc<dyn DirectoryPicker>>`；`setup` 阶段安装真实实现；E2E 经 debug 探针环境变量注入替身：
  - `AETHER_E2E_PICK_DIR=<绝对路径>`：`startup-pick` 返回固定路径；
  - `AETHER_E2E_PICK_CANCEL=1`：返回取消；
  - 生产（release）不读取上述变量。
- 命令契约不变：`startup_pick_target` 返回 `{ "target_dir": string | null }`，取消为 `null`，选择器错误为结构化错误（`internal`）。

## 2. 迁移主路径 E2E（测试替身驱动，真实 WebView）

`scripts/test/m1-06/e2e-startup-guard.mjs`（`pnpm verify:m1-06`）阶段三改为全链路：

1. 探针点击「选择目录…」→ 注入的 `FixedDirectoryPicker` 返回 `AETHER_E2E_PICK_DIR`；
2. 页面断言输入框回填路径（`AETHER_M1_06_REPORT {"stage":"picked","value":…,"expected":…}`）；
3. 点击「迁移到本地目录」→ 复制 → sha256 校验 → 原子替换；
4. 应用退出后重启（不带 `AETHER_DATA_DIR`/`OneDrive`）→ 以指针目录启动 → 断言主界面可达。

验证输出（本机，2026-09-17）：`PASS DoD3 迁移主路径：注入 DirectoryPicker → 「选择目录…」回填目标输入框`，
`E2E 输出包含 "stage":"picked"`，且 sha256 一致性 / 指针锁定断言全部通过。

## 3. 迁移参数校验分支（集成测试）

| 分支 | 测试（`tests/m1_06_migration.rs` / `tests/m1_06_startup_ipc.rs`） | 错误类别 / IPC 码 |
|---|---|---|
| 目标不存在 | `gate_rejects_sync_or_non_empty_migration_target`；IPC 畸形样本 | `path_rejected` |
| 目标非目录（是文件） | `migration_rejects_non_directory_target`；IPC 畸形样本 | `TargetInvalid` / `path_rejected` |
| 目标不可写 | `migration_rejects_unwritable_target`（原生探针「经由文件的路径」+ 注入替身 + 门层）；`migration_rejects_unwritable_target_native_unix`（只读权限，`cfg(unix)`） | `TargetNotWritable` / `path_rejected` |
| 空间不足 | `migration_rejects_insufficient_space`（探针注入：差 1 字节失败、恰好满足成功、门层映射） | `InsufficientSpace` / `migration_failed` |
| 目标位于同步盘 | `migration_rejects_invalid_and_sync_targets`；`gate_rejects_sync_or_non_empty_migration_target` | `SyncTarget` / `path_rejected` |
| 目标非空 | 同上 | `TargetNotEmpty` / `path_rejected` |

实现说明：

- `MigrationProbe`（`migrate.rs`）为可注入前置探针：`ensure_target_writable`（原生实现 = 创建并删除探针文件）与 `available_bytes`（`Ok(None)` = 未知不阻断；原生真实磁盘探针按 ADR-003 决策 19 在 M3-04 备份/导出统一接线）。
- 空间护栏口径：源目录全部文件字节数 ×1.2（`SPACE_MARGIN_NUMERATOR/DENOMINATOR` 上取整），失败不产生任何副本。
- 测试可移植性修复：Mock invoke 的本地源 URL 按平台选择（Windows `http://tauri.localhost`；其他平台 `tauri://localhost`），否则 ACL 视作远端来源拒绝（`tests/m1_06_*.rs` 已修正；M1-08 的 `ipc_validation.rs` 仍为硬编码，属既有文件，本地 Linux 运行会命中同一问题，已记录为后续可移植性项）。

## 4. 幂等续跑（迁移状态机，残余风险修复）

修复「复制完成、写指针失败」窗口导致的不可重试问题（原残余风险：目标非空 → 原地重试被拒）。

**状态文件**：`<指针目录>/migration_state.json`（与 `data-location.json` 同目录；测试/E2E 经
`AETHER_DATA_LOCATION_FILE` 隔离；不写入源同步盘目录）。

```json
{
  "migration_id": "01J...ULID...",
  "source": "…\\OneDrive-sim\\Aether",
  "target": "…\\local-target",
  "phase": "copying | verified | pointer_written | done",
  "checksum": "<目标清单 sha256（copying 阶段缺省）>",
  "started_at": 1758092000000
}
```

**状态机**：`copying →（复制+校验+原子替换）→ verified →（写指针）→ pointer_written →（门就绪）→ done`。

**续跑判定（`StartupGate::migrate`）**：

| 条件 | 行为 |
|---|---|
| 状态可续跑且源/目标一致、`phase=verified` 且目标清单摘要 == `checksum` | **跳过复制**，直接重试写指针（幂等续跑） |
| 状态可续跑且源/目标一致，但目标不完整或摘要不符 | 清理「本应用迁移残留」（暂存目录 + 与源同名的顶层条目）后重新复制 |
| 目标含未知条目（无法判断归属） | 拒绝（`path_rejected`，提示另选目录；不删除用户内容） |
| 无状态文件的非空目标 | 维持原行为：拒绝并提示另选目录 |

**UI 入口**：`startup_get` 快照新增 `pending_migration { migration_id, target, phase, started_at }`；
拒绝启动界面在检出时显示「完成迁移（继续锁定该目录）」按钮（`startup-finish-migration`），
点击即以上次目标重试迁移；「另选目录」仍走原有输入/选择器 + 「迁移到本地目录」。

**测试与 E2E**：

| 层 | 覆盖 |
|---|---|
| 门级单测 | `migration_resumes_after_pointer_write_failure`：注入指针写失败 → 状态=verified、源保留、改动源后重试 → 目标保持首轮副本（证明未重复制）、指针锁定、状态=done |
| 门级单测 | `migration_resume_cleans_partial_copy_and_rejects_unknown_entries`：半套副本清理重放；未知条目拒绝且不删除用户文件 |
| IPC 测试 | `startup_get_exposes_pending_resumable_migration`：错误提示「完成迁移」→ 快照暴露待续跑 → 同目标重试成功 |
| 前端测试 | 迁移失败刷新快照并呈现「完成迁移」；点击以记录目标重试 |
| E2E | `AETHER_E2E_FAIL_POINTER_WRITE=1` 注入失败 → 断言错误/入口 → 修改源文件 → 「完成迁移」触发 → 断言目标保持首轮副本（未重复制）→ 重启锁定 |

## 6. CI flake 根因与加固：E2E 输出行框定 + 探针固定延迟（2026-09-22）

**症状**：`Data dir guard (M1-06)` job 在 2026-09-21/22 的多次 run 中失败于
「等待超时：启动门阻塞快照（已收到 3 行 stdout…）」，而失败 dump 中 PHASE 行内容正确
（`"phase":"blocked_sync_dir"` 在案）——即**行匹配失败而非应用行为失败**。

**根因（经 GitHub check-run annotation 原始报文定位）**：

1. **stdout 跨 chunk 分行（主因）**：E2E 对每个 pipe chunk 独立 `split(/\r?\n/)`；管道可在任意
   字节处分片，含中文标签的长 PHASE 快照 JSON 被切成两段（annotation 报文在 JSON `label` 值内
   出现换行被替换后的 ` | `），两段分别不满足
   `startsWith(PHASE_LINE) && includes('"blocked_sync_dir"')` → 谓词永不命中、370s 超时。
   同缺陷存在于 M1-08 CSP E2E（会截断 REPORT JSON 触发 `JSON.parse` 崩溃）与 M2-07 健康 E2E
   （回报丢失），本次一并修复。
2. **探针固定延迟（同批加固的隐患，非本次 CI 失败直接归因）**：迁移主路径探针在点击「选择目录…」
   后固定 `setTimeout(200ms)` 读取输入框、再固定 `120ms` 点击迁移；慢机上 IPC + React 重渲染可能
   晚于该窗口，读到空值且「迁移到本地目录」按钮仍为禁用态（disabled click 空转）。

**修复**：

- `scripts/test/lib/exec.mjs` 新增 `lineFramer`（`StringDecoder` + 跨 chunk 缓冲，兼容多字节
  字符被字节级分片；`flush` 补发无尾换行余量），接入
  `scripts/test/m1-06/e2e-startup-guard.mjs`、`scripts/test/m1-08/e2e-csp-navigation.mjs`、
  `scripts/test/m2-07/e2e-health-monitor.mjs`；
- `startup_probe.rs` 迁移分支改事件驱动：轮询等待输入框回填（`value === TARGET`；30s 兜底按
  实际值回报便于诊断），按钮可用后才点击，去除固定 `setTimeout`。

**验证（本机，2026-09-22）**：

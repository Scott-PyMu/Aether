## 1. 总体结论

### 1.1 文档完整性

**良好。** v0.3 已形成“背景/假设 → 唯一决策 → 选择性计划/严格匹配表 → 状态机/写门 → 后台全量/周期/运行期调度 → `health`/UI/指标/兼容 → sidecar 格式/指纹 → 安全/残余风险/故障注入 → 实施/DoD/性能/no-go → 基线/契约 → G13/任务 → 失效/回退 → 签核/变更记录”的完整闭环；复审指出的运行期调度、基线饥饿、验证资产、`health` 兼容、残余风险判据、no-go 空档均已落位。

### 1.2 一致性状态

**基本一致，仍有 1 个验收口径冲突：**

- §4.3 目标表：dirty1 硬约束“P95 >25s → no-go；>30s 硬上限”；
- no-go #4：dirty 1/2/4 P95 >25s，或冷缓存 dirty1 >30s；
- 注记：冷缓存 dirty1 25–30s“不满足 25s 目标，记录并提交产品/安全/QA 评估；>30s no-go”。

三处对“冷缓存 dirty1 25–30s”给出不同结论。产品 Q6 已确认**严格 no-go**（P95 ≤25s；25–30s 不再作为评估例外），但 ADR v0.3 尚未同步（P1-1）。

其余口径基本一致：运行期 7 天调度、None 基线、`background_check_completed`/`clean_start_count`、`contract_version` 兼容矩阵、`verify:m10-10`/`verify:m10-14` 双模式、回退 Level 1/2 均已闭环。

### 1.3 最大风险

1. **冷缓存 dirty1 验收冲突（P1-1）**：按目标表/no-go，cold dirty1 25–30s 应 no-go；按注记则进入评估。若 M10-14 按注记执行，可能以“部分收益”通过，违背 Q5/Q6。
2. **运行期调度生命周期加固（P2-1）**：调度器任务自身的 panic/重启、`integrity_check` 超时后的取消/迟到结果、sleep/wake/时钟跳变/1h 轮询最大延迟未完全定义；若不加固，P0-1 的“最长 7 天”仍可能在异常路径失效。
3. **`verify:m10-10` 基线模式边界（P2-2）**：固定 `adr039-baseline.json`/`11cb438` 快照后，`verify:m10-10` 不再验证当前代码；必须确保 `verify:m10-14` 覆盖 Level 1/2 回退与 ADR-039 行为，且基线文件来源可审计。
4. **旧客户端发布门（P2-3）**：`checked_shards`/`state=ok` 语义变化对旧客户端是破坏性变更；`contract_version` 只能检测，不能阻止旧客户端误读；M10-03 外部消费者必须在发布说明/回归中升级。
5. **shutdown/import 与运行期检查交互（P2-5）**：`app_exit`、daemon shutdown、导入维护窗口期间的运行期 `integrity_check` 中止/迟到结果/`background_check_completed` 写回未定义；需与 D2/D-039-5 对齐。

### 1.4 安全专项

未发现“把权限控制误述为沙箱”；ADR-040 不新增外部信任边界、命令面、事件、设置键、迁移或第三方依赖。残余风险的写入判据已从“不得静默成功”改为可执行的“损坏页/其他页/停止写入/记录范围”，可作为安全/QA 签核输入；P2-1（运行期调度加固）与 P2-5（shutdown/import 交互）是签核前仍需补的证据边界。

## 5. 抽查发现的缺陷与修复记录（DoD2 过程证据）

**缺陷**：路径类规则的**目录前缀匹配**（`PermissionRule.target_kind=path` 且规则目标以分隔符收尾，
如 `C:\ws\zone\`）在 Windows 上与 canonical 目标比较时**不命中**——规则目标为普通形态，
而工作区内 canonical 目标可能为 `\\?\` 扩展形态（`std::fs::canonicalize` 输出），
`starts_with` 直接比较失败。精确路径规则不受影响（其比较路径已剥离扩展前缀）。

**发现途径**：M6-02 双人独立判定（判定 1 规范重演 vs 判定 2 真实系统）分歧 →
修正态判定环境隔离后**复现为确定性实现缺陷**（初次执行 7 例目录前缀样本全部「矩阵 allow ≠ 规则 deny」）；
按预注册处置路径「修复 → 归零复核 → 重跑抽查」闭环。

**修复**：`crates/aether-security/src/permission/rules.rs`——`path_matches` 目录前缀比较前统一
剥离 `\\?\` / `//?/` 扩展前缀，并按平台大小写规则比较（Windows 不敏感）；
新增回归单测 `path_directory_prefix_matches_extended_canonical_form`。

**修复后复核**：目录前缀样本 100% 命中（`boundary_mismatch=0`，抽查 175 例全量复跑）；
m2-03 / m2-10 / m6-01 与全量工作区测试无回归；规则数据指纹前后一致（不静默修改规则数据）。

> 归因说明：该判定语义由 ADR-019 附录 A-1 登记（「`path`：canonicalize 形态的前缀」），
> 修复为**实现对齐登记语义**，不构成设计变更（**无需 ADR**）。

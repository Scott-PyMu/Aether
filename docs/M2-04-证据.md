## 2. DoD 逐条证据

### DoD1 L2：写队列 >4096 → 新 run 拒绝（`storage_backpressure`），已有 run 不受影响（故障注入）

```
$ cargo test -p aether-control --test m2_04_backpressure -- --nocapture
test dod1_l2_rejects_new_run_and_existing_run_continues ... ok
test result: ok. 5 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 12.63s
```

断言链（`m2_04_backpressure.rs`，故障注入 = `WriteQueueConfig { commit_delay: 300ms }` +
单作业 4200 条直接入写队列）：

1. 已有 run 先建立：`send` 返回 `queued=false`，会话进入 `running`（执行器 0 许可阻塞）；
2. `queue.depth() > 4096` 且 `pressure_level == L2`（M1-04 接口实测）；
3. 第二条 `send` → `Err(storage_backpressure)`，**消息行数仍为 1**（拒绝先于持久化，
   无孤儿消息；`m2_support::message_count` 读库断言）；
4. 放行执行器 + 积压 drain 后：已有 run 行 `succeeded`，队列深度回落 0，
   第三条 `send` 可受理（临时高水位不改变存储状态）。

### DoD2 L3：控制投递 >会话数×5000 → 熔断 + 30s 后自动解除；重启后从 journal 恢复投递、零丢失

```
$ cargo test -p aether-control --test m2_04_backpressure -- --nocapture
test dod2_l3_circuit_release_and_journal_zero_loss ... ok
```

断言链（真实管线 + `BackpressureController::start` 投递泵 + `ManualClock` + 记录型隔离出口）：

- 6 条已落盘事件，会话数 1 × 4 条阈值 → `delivery_overflows == 1`、
  `delivery_circuits_open == 1`；隔离出口收到 `(mock, delivery_backlog, "…journal 补读模式…")`；
- 熔断期 `admission` → `storage_backpressure`（拒绝新会话/新 run）；
- 零丢失：`poll` → `ReadbackRequired { from_seq: 1 }`；`pipeline.readback(session, 0)`
  返回 `seq = 1..=6` 连续无缺口且 `complete=true`；`ack_readback(…, 6)` 后补读模式退出；
- 30s 解除：`clock.advance(30_000)` + `observe` → 隔离出口收到 release、准入恢复、
  `delivery_restarts == 1`；随后新事件（seq=7）经内存队列正常投递（journal 恢复投递）。

### DoD3 订阅者人为减速：心跳与中断请求响应 ≤2s（reader 不被阻塞证明）

```
test dod3_slow_subscriber_does_not_block_reader_health_or_interrupt ... ok
```

断言链：广播容量注入 32；一个只订阅不消费的慢消费者 + 未消费的投递控制器并存；
连续提交 400 条事件期间**单次提交最慢 ≤2s**（实测毫秒级，逐条断言）；
`pipeline.health()` ≤2s 返回 `storage_state=normal`；`manager.interrupt` ≤2s 返回且
run 行转 `cancelled`（D8：下游 UI/delta 消费者永不反压 reader）。

### DoD4 `Lagged(k)` → 补读最终一致（集成）

```
test dod4_lagged_readback_is_eventually_consistent ... ok
```

断言链：广播容量 8 + 投递泵注入 15ms/条减速 → `delivery_lagged_events > 0`
（真实 `RecvError::Lagged`）；`delivery_circuits_open == 0` 且隔离出口零调用（Lagged 仅切换补读）；
消费循环（`ReadbackRequired` → `pipeline.readback` → `ack_readback`；`Events` → `ack`）
最终收集 `seq = 1..=60` 去重后无缺口（最终一致）。

### DoD5 存储侧背压例外：暂停 ≤2s → 隔离 `degraded + status_reason=storage_backpressure`
→ 队列回落 ≤1024 持续 30s 自动解除；`persist_degraded` 严格区分

控制层单测（`cargo test -p aether-control --lib backpressure`）：

```

test backpressure::tests::pause_budget_isolates_without_timeouts ... ok

test result: ok. 9 passed; 0 failed; 0 ignored; 0 measured; 43 filtered out; finished in 0.00s
```

集成（`m2_04_backpressure.rs`）：

```
test dod5_storage_pressure_isolates_then_release_and_persist_degraded_is_distinct ... ok
```

断言链：

- 写队列注入 5000 → `PressurePhase::Paused`，`control_read_gate` 返回
  `Paused { remaining_ms ≤ 2000 }`（单次暂停 ≤2s）；
- 连续 3 次 2s 暂停超时 → `PressurePhase::Isolated`，隔离出口收到
  `(mock, storage_backpressure, "…degraded + status_reason=storage_backpressure…")`；
  `SessionManager` 接线生效：`send` → `Err(storage_backpressure)`；
- 队列注入 1024 + 30s 持续（+29 999ms 不解除、+30 000ms 解除）→ 隔离出口 release、
  阶段回 `normal`、新 run 可受理（仅队列维度解除，ADR-004）；
- `persist_degraded` 区分：隔离后注入 `storage_state=PersistDegraded` + 队列 0 持续 120s →
  **零 release**、阶段冻结 `PersistDegraded`、`send` 错误码为 `persist_degraded`
  （D4 修复 + 重启 + 自检，不自动热恢复）。


断言链：预热 `ready` → `isolate(StorageBackpressure)` → 状态 `degraded`、

`runtime.status_changed(ready→degraded, reason=storage_backpressure)` + `Terminated` 审计；
重复隔离/冷启动隔离 → `NotApplicable` 且不产生转移；`release()` → `ready`（新 PID、原因清除）。

### L1（D8：写队列 >1024 → 告警 + delta 合并放宽至 64ms）

- 告警边沿由 M1-04 已交付（`>1024` L1 / `>4096` L2 广播 + 计数，M1-04 证据）；

## 4. 边界与偏离记录

1. **分层与依赖方向**：背压判定/投递/解除逻辑全部在 `aether-control`（依赖
   `core`/`store`/`security`，AGENTS §2.1）；隔离动作经 `IsolationSink` 端口由组合层
   （`aether-tauri::isolation`）桥接到 `aether-adapters` 监督器，无兄弟 crate 反向依赖。
2. **隔离与重启语义**：`RuntimeSupervisor::isolate` 使用 D5 既有转移表
   （`ready/starting → degraded`），不计入崩溃退避/熔断（存储压力非适配器故障），
   且**保持 `degraded` 不自动重启**——解除由控制层队列回落条件触发（ADR-004）；
   与 `restart()`（崩溃自愈路径）严格分离。该 API 为 M2-04 新增，未修改 D5 状态机语义。
3. **`Lagged` 的零丢失边界**：投递层只能对「已摄入过的事件」建立补读锚点；若某会话
   从未被投递层观察（首条事件即被广播丢弃），消费方仍可用自身 `last_seq` 直接调用
   `EventPipeline::readback`（M3-01 EventStore 路径）。`delivery_lagged_events` 指标
   供消费方触发该兜底。
4. **「适配器侧反压上限 = SDK 出站队列 cap=1024 条」**（D8 参数）属 TS 适配器 SDK
   出站队列行为，不在 M2-04 DoD 与本任务代码范围内；核心侧对等保护为「暂停读取
   ≤2s + 熔断隔离」，本任务已交付。后续适配器 SDK 任务落地时对齐。
5. **生产 SessionManager 接线**：M2-04 提供 `SessionManager::with_backpressure` 接线点
   与桥接实现；当前 `aether-tauri` 启动序列尚未组装 `SessionManager`（真实适配器会话
   客户端在 M2-02 集成测试中直连监督器），故生产装配在后续 UI 联调任务（M3-01/03）完成，
   接线契约与故障注入证据已在本任务冻结。
6. **L3 熔断的 `status_reason`**：控制投递积压与存储高水位共用 `storage_backpressure`
   词典值（ADR-003 决策 7），隔离 detail 中携带 `delivery_backlog` 区分来源；未新增
   `status_reason` 取值。

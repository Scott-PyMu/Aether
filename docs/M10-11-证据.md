### 3.2 删除事务档位矩阵（DoD-2；release，标准 5.22GiB generation，持续批）

命令：`AETHER_M10_11_GENERATION=<5.22GiB copy> AETHER_M10_11_PROBE_TIER=<档位> \
AETHER_M10_11_PROBE_CHUNKS=<批数> pnpm m10-11:probe`

> 说明：先前 10 次短跑矩阵（每档 10 批）受冷缓存影响，2000 档 P95 仅 15ms；
> 持续清理时 WAL/auto_vacuum/页迁移成本累积，短跑结果不能用于选档。本表为
> **同一 generation 副本上持续删除**的实测（`retention_delete_batch` 档位 = 删除事务大小）。

| 档位 | 批数 | 删除 P50 | 删除 P95 | 删除 P99 | 删除 max | >500ms 批数 | 合规 |
|---:|---:|---:|---:|---:|---:|---:|:---:|
| **500** | 500 | **140ms** | **253ms** | **366ms** | **482ms** | **0** | **是** |
| 1000 | 500 | 292ms | 779ms | 2190ms | 4187ms | 70 | **否** |
| 2000 | 1000 | 499ms | 1101ms | 2887ms | 15110ms | 498 | **否** |
| 5000 | 100 | 1349ms | 2510ms | 2852ms | 2906ms | 92 | **否** |

  不得用短跑 10 次的结果选档。

  删除事务按 500 分组（归档块独立于删除事务，符合 ADR-039 §1-1/§1-3）。

### 3.5 维护态手动 `VACUUM`（DoD-5）

**清理后高水位（标准 5.22GiB generation 完成 §3.4 全量清理后）**：

```text
$ AETHER_M10_11_GENERATION=<cleaned 5.22GiB copy> AETHER_M10_11_GENERATION_IS_COPY=1 \
  node scripts/test/m10-11/run-full-cleanup.mjs --scenario=vacuum
[m10-11] maintenance_vacuum_standard = {
  "physical_before": 5642182656,         // >5GiB；status_before.physical_warning 非空
  "physical_after": 810647552,           // 约 773 MiB；status_after.level=ok
  "live_bytes": 810483712,
  "available_bytes": 328027119616,
  "required_space_bytes": 11284365312,   // = physical_before ×2
  "took_ms": 13905,                      // 13.9s
  "stop_write_ms": 0,
  "warning": null                        // VACUUM 后已低于 5GiB 阈值
}
```

- 空间预检：可用 328,027,119,616 B ≥ 当前 `db+wal` 5,642,182,656 ×2 = 11,284,365,312 B；通过后执行。
- 维护态独占 + 停写/drain；`health`/`app_exit` 以外命令在 `kind=vacuum` 时同样拒绝
  （`vacuum_maintenance_allows_only_health_and_app_exit`）。标准 generation 主库 + 8 分片 VACUUM 耗时 **13.9s**，物理 5.64GB → **0.81GB**。
- 空间不足注入（app 测试）：`available=0` → 拒绝（`空间预检失败`），当前库字节不变。
- VACUUM 后仍 ≥ 阈值时 `warning` 非空（app 测试以阈值 1 B 注入断言）；标准清理后已降至阈值以下。
- **入口说明（按用户裁定）**：维护态**不需要 UI 入口**；ADR-039 冻结命令面 87
  （不新增维护命令），本任务交付内部维护入口 `RetentionTask::run_maintenance_vacuum`
  （测试/运维调用），不新增 IPC 命令或设置键。空间预检/停写/审计/告警由该入口保证。

## 4. 故障注入与边界

| 场景 | 结果 | 证据 |
|---|---|---|
| 归档目录不可写/归档失败 | 该批不删除（12 行全部保留）；审计写 failed；下轮重试 | `archive_failure_skips_batch_and_keeps_rows` |
| 维护态（备份/恢复）进行中触发清理 | 返回 `Deferred`，不触碰事件、不阻塞维护 | `cleanup_defers_while_maintenance_state_is_active` |
| 维护态 VACUUM 空间不足 | 拒绝（消息含 `空间预检失败`）；当前库字节不变 | `maintenance_vacuum_precheck_space_and_warning_are_enforced` |
| 维护态 VACUUM 后仍 ≥ 阈值 | `warning` 非空；状态记录 `last_maintenance` | 同上 |
| `audit_log` | 不清理（`must-survive-retention` 行保留） | store/app 测试 |
| 单批成员/归档顺序 | 按 `(type, ts)` 可复现；最终集合与旧 `rowid` 顺序一致（全部超窗白名单） | `retention_batch_order_and_final_cleanup_set_are_stable` |

## 5. 未验证项与风险

- 本轮矩阵/全量/日常在 Windows x64 + 本机 SSD/HDD 上执行；macOS/Linux、NVMe、USB/网络盘未复测。
- **维护态不需要 UI 入口（按用户裁定）**：ADR-039 冻结命令面 87（0 新增、不新增维护命令），
  本任务交付内部维护入口 `RetentionTask::run_maintenance_vacuum`（测试/运维调用）；
  空间预检/停写/审计/告警由该入口保证。
- **删除长尾已排查并纠正**：2000 档持续清理事务 p50 499ms / p95 1101ms / max 15110ms，
  说明 8.5s 长尾不是单次 OS 抖动，而是大事务 + WAL/auto_vacuum 成本累积；短跑 10 次
  矩阵（P95 15ms）受冷缓存误导。已改为 **500 档 + 归档块 1000**：持续 500 批 P95 253ms、
  max 482ms、0 批 >500ms（`m10_11_outlier_probe`）；全量 32,835 批中 132 批（0.4%）
  >500ms、max 5572ms，P95 仍 <500ms。残余单点长尾为 I/O/OS 抖动，未用其替代 P95。
- `VACUUM` 的文件系统级原子性依赖 SQLite；未做断电注入（M10-09 已覆盖 generation/`CURRENT`
  原子切换；本任务不重复）。
- **归档块 1000 / 删除事务 500 的失败语义**：若一个 1000 行归档块的第二个 500 行
  删除事务失败，已写入的归档文件仍包含这 1000 行；下次重试会把剩余 500 行再次归档
  （append-only 重复，不丢数据、不影响最终集合）。这是减少全量归档文件数/总时长的
  取舍，已在 ADR-039 §1-1/§1-3“归档块可独立于删除事务”口径内。
- 归档产物保留策略不变（ADR-021：不自动删除归档）；全量清理归档块数/磁盘占用见 §3.4，
  需纳入容量巡检。
- **测试数据清理**：5.22GiB 标准数据集 / generation 副本 / 探针归档仅位于 `dist-out/`
  或临时目录，未纳入版本库；按用户裁定仅在测试期保留，**P2 收口（M10-13/G13）后删除**。

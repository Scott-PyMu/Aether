## 3. DoD3：合成口径（禁止静默覆盖）+ 生效来源回显

**DoD**：预设提示词与工作区记忆注入的顺序与优先级按 ADR，禁止静默覆盖，并在会话摘要回显生效来源。

**验证方式**：`aether-control` 合成单测 + `m7_09_presets` 集成断言（内存/落库/列表回显）。

合成契约（逐字断言）：

1. 两者都有 → `preset.prompt_block() + "\n\n" + memory`；预设块头 `<!-- aether:preset:<id> -->` 恒在首位，记忆块「工作区约定」头后置，两正文完整保留；
2. 仅预设（工作区无记忆）→ 仅预设块；
3. 未选预设 → 仅记忆块（与 P0 行为一致）；
4. 两者皆无 → `None`（不落 `system_prompt`、不下发）；
5. 块内不解析嵌套标记（提示词原文保留；空提示词仍保留块头）。

集成断言（`session_create_composes_preset_before_memory_and_echoes_source`）：

- `session_create(preset_id=P02)` 响应 `preset_id=P02` / `preset_name=代码专家`；
- `system_prompt` 以预设块开头、含「你是资深软件工程师」与「# 工作区约定」/「工作区约定内容」，预设块位置 < 记忆块位置；
- 落库 `sessions.system_prompt` == 响应合成结果；`sessions.preset_id == P02`；
- `session_list` 回显 `preset_name=代码专家`；
- 未选预设 → `preset_id`/`preset_name` 缺省、`system_prompt` 以「# 工作区约定」开头且不含预设标记。

链路：核心 → `scripts/test/m7-09/rpc-tap.mjs`（透明代理）→ 真实 Claude Code 适配器 bundle（`bun build --compile`）→ **fake-claude**（`--claude-bin node --claude-arg scripts/test/m2-02/fake-claude/cli.mjs`，记录适配器 → CLI 的实际 argv 与 stdin）。断言三层：

## 4.5 DSH 系统提示词注入方案研究（插件 / ACP；不改代码）

**结论**：ACP 协议面**没有**系统提示词通道，但 **DSH 插件注入可行**，推荐作为 DSH 消费链路的实现路径。该路径已由 **ADR-027** 采纳并实现（真实 E2E 见 §4.7）；本节保留研究过程与实测依据。

### 4.5.1 为什么 ACP 直连不行（实证）

- `@deepseek-ai/dsh-acp` `newSession`：`sessionId = brandString(randomUUID())` → `AcpSession.create(ctx, { sessionId, cwd, mcpServers, agentOptions, ... })`，返回 `{ sessionId, configOptions }`；`session/new` 只校验 `cwd`/`mcpServers`（`dsh-acp/lib/index.js`）。
- 协议契约（`dsh-acp/README.zh.md`「协议契约」）：`session/new`（工作区 + MCP）、`session/prompt`（有序文本/资源链/图片）、`session/set_config_option`（仅 `model` / `reasoning_effort`）——**无系统提示词/instructions 字段**。
- 因此仅靠 ACP 无法让 DSH 感知 `session.create.system_prompt`；`dsh-persona` / `dsh-agent-instructions` 的 `personaPrefix` / `$DSH_HOME/AGENTS.md` 是**进程/部署级全局**（一个适配器进程承载多会话，无法按会话区分预设），只能作单会话假设下的降级，不作为方案。

### 4.5.2 插件注入方案（推荐）

**通道**：DSH 插件系统的公开 API `ctx.systemPrompt.section(...)`（`@deepseek-ai/dsh-system-prompt` 类型定义 `lib/types/index.d.ts`）：

```ts
// 数据类型（实测版本 0.2.1-rc.2；0.1.5-rc.2 形态一致）
interface PromptSection {
  name: string;                    // 注册表唯一名（重复注册抛错）
  order: number;                   // 升序拼接；外部贡献可用任意有限 order
  text: string | ((ctx) => string); // 每次 assemble 求值（可按会话读取侧信道）
  complete?: boolean;              // true = 作为完整提示词（会替换其余段落；本方案不用）
}
// 作用域注册：通过 agent.ctx 注册只影响该 agent（README：Contributions are scoped）
```

**插件侧（`aether-dsh-prompt`，独立包，随 `--dsh-patch` overlay 挂载；与既有 `aether-dsh-stream` 同机制）**：

```js
export function apply(ctx) {
  ctx.on("agent/created", ({ agent }) => {
    agent.ctx.systemPrompt.section({
      name: "aether:session-prompt",
      order: 100, // 位于 persona(0) 之后、plan/tools(500+) 之前；DSH 允许外部任意 order
      text: () => readPromptFor(agent.id), // 侧信道文件 $DSH_HOME/aether-bridge/prompts/<encodeURIComponent(id)>.md
      interpolate: false,                  // 用户提示词按原文注入（避免 {{...}} 触发严格变量插值）
    });
  });
}
```

- `agent/created` 的 payload 为 `{ agent }`，`agent.ctx` 为 agent 作用域（`dsh-agent/lib/types/runtime-types.d.ts`）；文档明确 `agent/created` 在**首次提示词组装之前**派发，且 scoped 贡献在 disposal 时自动 unwind。
- `agent.id` / `agent.session.header.id` 为 `SessionId`（`dsh-session` 类型），与 ACP `newSession` 返回的 `sessionId` **同源**（`ctx.sessions.get(sessionId)`）——适配器可用该 id 命名侧信道文件。
- 侧信道：复用现有 `--delta-dir`（`<DSH_HOME>/aether-bridge`）模式，新增 `prompts/<encodeURIComponent(sessionId)>.md`；适配器在 `session/new`/`session/resume` 成功后写入合成提示词，`session/dispose` 删除，启动时清理上次进程残留；插件在 `assemble` 时读取（缺失/空 → 贡献空串，`renderPrompt` 丢弃空段）。
- 与记忆注入的关系：核心已把「预设块 → 记忆块」合成**一个** `system_prompt`，插件无需理解分段，只注入整段（保持 D14 合成语义）。

# Aether 备份与恢复手册

> 适用版本：P1（设计文档 v1.16；D13/DS-05、ADR-020）。本手册覆盖手动/自动备份、
> 加密备份、恢复七步与故障处置；演练脚本见 `scripts/test/m5-03/restore-drill.mjs`。

## 1. 备份

### 1.1 手动备份（P0 起）

- 入口：备份页「创建备份」（缺省写入应用数据目录 `backups/`），或经系统目录选择器
  指定外部目录（D13；选择后校验可写与可用空间 ≥ 当前 `db+wal` ×1.2，不足拒绝）。
- 产物：`VACUUM INTO` 生成已 checkpoint 的单文件（**不含 `-wal`/`-shm`**）；
  手动产物（`kind=manual`）**不自动删除**，请自行按需清理。

### 1.2 自动备份（P1 / ADR-020）

- 设置项：`backup.auto.enabled`（缺省开启）/ `backup.auto.frequency`
  （`daily` 缺省 / `weekly`）/ `backup.auto.retention`（自动产物保留份数，缺省 10）。
- 错过排期（应用未运行）→ 启动后 2 分钟内补备一次（不追补多次）。
- 仅自动产物（`kind=auto`）按保留份数滚动；失败不产生半成品、不删除既有备份，
  冷却后自动重试并记录审计（`backup.auto.run`）。

### 1.3 加密备份（P1 / ADR-020）

- 缺省开启（设置项 `backup.encryption.enabled`，缺省 `true`）；算法
  **XChaCha20-Poly1305（AEAD）**；加密产物为 `AEBK1` 格式（扩展名 `.aebk`），
  未加密产物保持 `.db` 形态。
- **主密钥来源**：默认 = OS 凭据库主密钥（引用 `keychain://aether/backup/master`，
  32 字节随机，首次备份生成）。OS 凭据库不可用时，经 A3 降级路径（加密文件
  `secrets.enc` + 启动口令）保存同一引用。
- **口令模式（显式可选）**：创建备份时提供口令 → 以 Argon2id
  （m=64MiB, t=3, p=1 + 随机盐）派生密钥加密；**口令仅传输、不落盘、不入日志/
  诊断包/导出**。口令模式产物可在没有 OS 凭据库的机器上凭口令恢复。
- **禁止静默降级**：加密开启且主密钥不可用（OS 凭据库失败且未解锁 A3 口令）→
  备份**暂停并告警**（审计失败 + 连续失败计数），**不会**产出明文产物；只有显式
  关闭 `backup.encryption.enabled` 才允许明文 `.db` 产物。
- **密钥丢失 = 加密备份不可恢复**：请确保 OS 凭据库可用（或记住 A3 口令）；
  主密钥本身没有额外导出机制（P1 边界）。

## 2. 恢复（D13 七步）

1. **输入**：内置备份清单任选，或选择外部候选文件（`.db` 明文 / `.aebk` 加密）；
2. **校验候选**：只读打开 + `quick_check` + 迁移版本检查（高于当前程序 → 拒绝并
   提示升级程序）；加密产物先解密到临时候选（`.restore-cand-*`）再校验；
3. **停写**：关闭全部连接与写队列（恢复在应用重启后的启动序列执行，天然无写者）；
4. **现场保护**：当前库改名 `aether.db.pre-restore-<ts>`，`-wal`/`-shm` 一并改名
   （`.pre-restore` 文件**保留**，用于失败回退与事后审计）；
5. **就位**：候选复制到库路径（跨盘临时文件 + 原子 rename）；
6. **验收**：重新打开 + `quick_check` + 迁移到当前版本；任一步失败 → **回滚现场**
   （恢复旧三件套）并删除恢复日志；
7. **重启核心并写审计**（`backup.restore`：`requested`/`completed`/`rolled_back`/`failed`）。

### 2.1 加密产物恢复

- 主密钥模式（`.aebk`，flags=keychain）：恢复时自动从 OS 凭据库（或 A3 加密文件）
  读取主密钥解密；凭据库不可用且无 A3 口令 → 明确拒绝（`backup_key_unavailable`）。
- 口令模式（`.aebk`，flags=passphrase）：恢复时必须提供口令（缺失 →
  `backup_passphrase_required`）；口令错误或产物被篡改 → 认证失败明确拒绝
  （`backup_decrypt_failed`）。
- **口令/密钥错误不会破坏当前数据**：拒绝发生在恢复登记之前，当前库
  `aether.db`/`-wal`/`-shm` 三件套不被触碰。

### 2.2 恢复失败与回退

- 恢复日志 `aether.db.restore-journal.json` 记录恢复状态；若恢复被强制中断
  （`kill -9`），下次启动自动按现场记录回滚，旧库继续可用。
- `.pre-restore-<ts>` 文件为现场保护副本；确认恢复成功后可按需归档或删除，
  恢复失败时系统会自动还原（请勿在恢复完成前手工删除）。

## 3. 故障处置速查

| 症状 | 处理 |
|---|---|
| 自动备份连续失败（备份页/诊断包显示） | 检查目标目录可写与可用空间；检查安全级别（设置页）与主密钥可用性；必要时显式关闭加密（自担风险） |
| 恢复提示口令错误/密钥不可用 | 口令模式产物请核对口令；主密钥模式产物请在原机（凭据库可用）恢复，或解锁 A3 降级口令 |
| 恢复中断后应用以旧库启动 | 查看审计 `backup.restore`（`rolled_back`）；确认数据无误后可重新发起恢复 |
| 容量增长告警（2GB/5GB） | 参见保留/归档策略（P1，M5-04/M5-05）；先归档后清理 |

## 4. 演练与验证

- 演练脚本（可重复执行、不依赖外部凭证）：
  `node scripts/test/m5-03/restore-drill.mjs`（默认 2 轮）或 `pnpm verify:m5-03`。
- 演练链路：加密备份 → 清库 → 恢复 → `quick_check` + 行数/哈希抽查一致；
  覆盖口令/密钥错误、A3 降级、七步现场保护与回滚、密钥材料扫描 0 命中。

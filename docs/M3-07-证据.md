命令与原始输出：


断言内容：

## 4. 边界与偏离记录

1. **审计动作命名（实现级，非设计变更）**：沿用既有前缀约定（`permission.*` /
   `backup.restore`），新增会话侧 `session.created` / `session.closed` /
   `session.status_changed`，适配器侧 `runtime.status_changed` / `runtime.<audit_kind>`
   （后者的 kind 串来自 M1-10 既有 `AuditKind`，未新造）。未新增事件类型 / 命令 /
   迁移 / 依赖；D9 未冻结审计动作枚举，M3-12（ADR-011「不新增审计动作」）可直接复用
   `session.status_changed`（含后续 `waiting_permission` 转移）。
2. **审计范围口径**：P0 最小集仅三类；`audit_log` 另有 M3-04 的恢复审计
   （`backup.restore`，既有交付），不属于本次新增；**P0 不承诺记录所有 Agent 操作**
   （ADR-003 §11 / ADR-004 决策 9），证据与文档均未出现「已记录所有 Agent 操作」表述。
3. **会话状态转移全覆盖**：`session.status_changed` 在 `persist_status_and_emit` 与
   `persist_status_inner` 两个唯一状态落库点写入（含 run 收口、取消、dispose）；
   重启收口（`reconcile_interrupted_runs`）按该路径「尽力而为」语义补写审计
   （写入失败仅记 tracing，不阻断收口）。
4. **适配器审计桥接为延迟注入**：组合根装配顺序为「监督器（`health.runtimes` 摘要源）
   → 存储 → 启动序列尾段」，故以 `DeferredObserver` 占位、存储就绪后注入
   `StoreAuditObserver`（启动序列尾段的孤儿清理/预热已可落库）；回调为同步接口，
   写入经核心运行时 spawn（失败仅 tracing 告警，不回压监督器）。
   生产运行时注册表当前为空（M4-05 承接三官方运行时注册），因此本桥接在生产环境的
   可观察效果随 M4-05 生效；机制与落库语义已由集成测试（真实 StoreRuntime + 真实
   监督器状态转移）证明。
5. **写入放大**：每次会话状态转移新增 1 条审计（如一次 send 产生 `idle→running` /
   `running→idle` 两条）。P0 口径（单用户、事件全量保留）下可接受；若后续评估为噪声，
   收敛为仅边界动作（created/closed）属实现级调整，需任务证据记录。
6. **未变更**：19 边会话状态机 / `runtime.status_changed` 事件契约 / `audit_log`
   DDL（0001 与 0002 均未修改）/ 权限与监督器服务语义（仅观察者注入点新增重载）。

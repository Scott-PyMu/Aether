## 1. DoD1 T4：kill -9 ×20（run 中）→「已确认」零丢失；未确认不误显示完成

**验证方式**：故障注入（真实进程强杀 ×20）+ 集成校验（重启后逐条核对确认日志）。

**口径**（附录 D T4）：① 用户消息 = `session.send` 返回 runId 且消息/run 行已提交；
② 助手消息 = 客户端收到 `message.completed` 且 journal 提交成功。

**结构**（`crates/aether-tauri/tests/m3_06_t4.rs`，复用 M2-08 宿主子进程模式）：

1. 宿主子进程在共享数据目录启动真实核心（存储 + 管线 + 生命周期 + 流式执行器），每次迭代：
   先完成一个「已确认」run（quick：send ack 落库 → 收到 `message.completed` 即写确认日志），
   再发起长流式 run（slow），首条 delta 落盘后写 in-flight 标记并挂起；
2. 驱动测试循环 20 次：标记出现 → **强杀**（Windows `TerminateProcess` / Unix `SIGKILL`）→ 下一次迭代的启动路径执行 M3-06 重启状态重建；
3. 校验子进程重开核心，逐条核对：已确认用户/助手消息零丢失；未确认 run 非 `succeeded`、
   无 `message.completed` 事件、且被收口为 `failed(run_interrupted)`。

```
$ cargo test -p aether-tauri --test m3_06_t4 -- --nocapture
[t4] verify={"assistant_confirmed":20,"false_completions":[],"inflight":20,"loss":[],"unreconciled":[],"user_confirmed":40}
test result: ok. 2 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 8.86s
```

判读：20 次迭代各产生 2 条已确认用户消息（quick + slow 的 send ack 均已提交）与 1 条已确认
助手消息；`loss=[]` 证明**已确认零丢失**；`false_completions=[]` 证明**未确认不误显示完成**；
`unreconciled=[]` 证明未确认 run 全部被重启收口为可重试终态。每次启动的
`AETHER_M3_06_T4_RECONCILE` 行逐次收口上一轮 in-flight run（测试断言逐条对应）。

**UI 侧「未确认不误显示完成」**：前端注入 `run.started` + delta（无终态）→ 助手气泡保持
`data-streaming=true`（生成中），不出现完成态；收到收口事件 `run.failed` 后渲染
「运行失败：run_interrupted」+ 重试（`m3_06_recovery.test.tsx`）。

## 2. DoD2 `run_retry` 一键重放（仅终态；Mode R/N；新 run + 旧 run 审计）

### 2.1 生命周期层（`crates/aether-control/tests/m3_06_retry.rs`）

```
$ cargo test -p aether-control --test m3_06_retry -- --nocapture
running 4 tests
test retry_is_rejected_while_persist_degraded ... ok
test running_run_rejected_then_cancelled_run_retries ... ok
test restart_reconciles_unfinished_runs_and_sessions ... ok
test retry_requires_terminal_run_and_preserves_old_run ... ok
test result: ok. 4 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.43s
```

断言链：
- 成功的 run 重试 → `run_not_retryable`（仅 `failed/timeout/cancelled` 可重试，ADR-004）；
- 失败 run 重试 → 新 run 编号、**复用原输入消息**（消息数只增助手终稿 1 条）、旧 run 行
  保留且错误码不变；未知 run → `run_not_found`；
- 运行中 run 重试 → `run_not_retryable`；中断（`cancelled`）后可重试成功；
- 降级（`persist_degraded`）期间重试 → `persist_degraded`（D4 拒绝新 run）；
- 重启状态重建：`queued`/`running` run → `failed(run_interrupted)` + 会话回 `idle`，
  `run.failed`/`session.status_changed` 事件经管线落库；再次收口幂等。

### 2.2 IPC 层与 Mode R/N（`crates/aether-tauri/tests/m3_06_run_retry.rs`）

宿主：`aether-adapter-fixture --mode session`（最小 D6 会话面；`session.create` 携带
`native_id` → `resumed=true`），调用记录写 `--session-log` 供断言。

```
$ AETHER_FIXTURE_BIN=... cargo test -p aether-tauri --test m3_06_run_retry -- --nocapture
running 1 test
test run_retry_uses_terminal_guard_and_replays_per_mode_r_and_n ... ok
test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 1.21s
```

断言链：
1. **Mode N（新会话重发）**：首次 `session.create` 无 `native_id` → `resumed=false`，
   `native_id` 写回 `sessions.config`；
2. `run_retry` 响应 `{session_id, run_id, input_message_id, queued}`：新 run ≠ 旧 run、
   `input_message_id` = 原输入消息；旧 run 保留 `failed(fixture_fail)`；同核心生命周期内
   适配器调用记录仅 1 次 create（复用会话）；
3. **Mode R（原生恢复）**：核心重启（重开存储/管线/管理器）后 `session.send` 与
   `run_retry` → 执行器以 `sessions.config.native_id` 恢复适配器会话 →
   记录 `resumed=true` 且 `session_id == native_id`；
4. 运行中 run 重试 → `invalid_value` + 稳定业务码 `run_not_retryable`（不新增 IPC 错误码枚举，见边界 2）。

> 重放发送键说明（边界 4）：执行器对适配器 `session.send` 的幂等键改取**核心 run id**
> （原为输入消息 id）。否则重放复用输入消息 id 会被适配器侧幂等命中并返回旧 run，
> 重放语义失效；核心侧重复 `session.send` 仍由存储层 `UNIQUE(session_id, client_msg_id)`
> 在到达适配器前去重（ADR-005 持久化支撑不变）。

## 4. 重启状态重建（任务描述「重启状态重建」的实现）

`SessionManager::reconcile_interrupted_runs()`（生产路径：`build_backend` 启动序列内、
UI ready 握手前；`handle.block_on` 同步收口）：

1. `queued`/`running` run → `failed`（`error.code=run_interrupted`，`recoverable=true`）
   + `run.failed` 事件（先日志后广播，经管线）；
2. 非终态、非空闲会话（`creating`/`running`/`waiting_permission`/`paused`）→ `idle` +
   `session.status_changed` 事件；
3. 逐条尽力收口：单条失败仅记录诊断，不阻断其余条目；重复调用幂等。

设计一致性：复用 D5 失败场景表「运行中崩溃 → 在途 run 标 failed（可重试）」与 D4
「未确认不广播/不伪造完成」口径；**未新增事件类型（附录 B 内）、未新增 IPC 错误码、
未改 schema**；错误码 `run_interrupted` 为 `run.failed.payload.error.code` 自由取值
（与 `run_stream_timeout`/`task_panic` 同族），不涉及错误码枚举登记。

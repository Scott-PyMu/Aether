### 1.3 Q3：完全开源解码库

### 1.4 Q4：HTTP 默认策略

| 模式 | HTTP |
|---|---|
| `aetherd --stdio` | **默认关闭**（UI 主路径，减小本地攻击面） |
| `aetherd --stdio --http` / `AETHERD_HTTP=1` | 开启；listener 失败不致命，`health.api.state="disabled/error"`，stdio 继续 |
| `aetherd --http-only` | **开启且必需**；listener 失败必须致命（退出码 25 或专用码） |
| `AETHERD_HTTP=0` | 强制关闭；与 `--http-only` 冲突报参数错误 |
| `AETHERD_HTTP_REQUIRED=1` | 仅在 HTTP 已开启时有意义；测试/CI 用 |

- 只有 HTTP 开启时才写 `.aetherd-api.json`；关闭时删除。
- `--http-only` 仍走同一 `.aetherd.lock`/数据目录，禁止双 daemon。
- 定义 SIGINT/SIGTERM、Windows Ctrl 事件、父进程死亡回收。
- ADR-033 v1.1 增加 `--http` / `--http-only` / `--no-http`、默认关闭、退出码与 discovery 行为。

### 1.5 Q5：`subagent_context` 三运行时 spike

**批准方案：**

- `session.send` 增加可选 `subagent_context: {version, block}`；`block` ≤16KiB（按最终限额）。
- 适配器能力项 `subagent_context`；未声明 → 不得 `auto_inject`，转 hold 或返回 `subagent_context_rejected`。
- `session.send` ack 增加 `applied_context_version`；core 只有收到 `applied_context_version >= version` 才把行置 `injected`。
- `context_version` 为每父会话独立 counter；注入与 fold 都 bump；重启后 core 重发当前快照。
- 三运行时分别验证：
  - Claude Code：`--append-system-prompt-file` / resume 下是替换还是追加；若追加，改用替换型参数或重建。
  - Codex：每-run `developer_instructions` 是否只保留最新。
  - DSH：插件 section 能否热更新；不能则重建 agent 或 hold。
- 任一失败：该运行时 `subagent_context=false`，auto_inject 降级为 hold，不得静默累积。
- **真实运行时测试由用户提供 CLI/凭据/测试数据**；在此之前只做 mock adapter + 单测，不写注入主路径。

### 1.6 Q6：完整结果存储选 A

**批准：`subagent_results` 表（新增，0010+）。**

```sql
CREATE TABLE subagent_results (
  child_session_id TEXT PRIMARY KEY REFERENCES sessions(id) ON DELETE CASCADE,
  result           TEXT NOT NULL,          -- canonical JSON（UTF-8）
  total_bytes      INTEGER NOT NULL,
  truncated        INTEGER NOT NULL DEFAULT 0,
  verdict          TEXT,
  summary          TEXT,                   -- <=512 字节
  findings_count   INTEGER NOT NULL DEFAULT 0,
  created_at       INTEGER NOT NULL
);
```

- `result` 存 canonical JSON 字符串；`subagent_result_get` 按 UTF-8 字节分页（16KiB/页，最多 4 页/64KiB）。
- `subagent_list` 只读 `verdict`/`summary`/`findings_count`，不读 `result`。
- `SessionSummary.config` 不承载完整结果，避免 `session_list`/`session_get` 膨胀与 2MiB 帧风险。
- `result_ref = "subagent:<child_session_id>"`。
- ADR-032 v1.1 必须说明：v1.0 §5 以“现有 config/消息可承载”否决结果表的理由不再成立（`SessionSummary.config` 会进入列表 DTO）。
- 迁移计数：`subagent_injections` + `subagent_results` = 20→22。

### 1.7 Q7：仅父会话授权（agent 与 UI）

- **已确认：agent 与 UI 都必须从父会话进入；不接受“全局/任意树”读取。**
  - 适配器方法 `subagent.result.get` 必须携带 `parent_session_id`；
  - IPC 命令 `subagent_result_get` 也必须携带 `parent_session_id` + `child_session_id`；
  - 校验 `child.parent_session_id == parent_session_id`；
  - 兄弟/堂兄弟/根直读拒绝；失败不泄露存在性。
- **UI 约束：**
  - 子会话详情不是独立根路由；路由必须携带 `parent_session_id` + `child_session_id`（如 `/sessions/<parent>/subagents/<child>`）；
  - `session_list` 默认排除子会话；`subagent_list` 是子会话树的唯一入口；
  - `session_search` 命中子会话时必须返回 `parent_session_id`，点击跳转到父树并选中子节点；无 parent 的搜索结果不得直接打开子详情；
  - 通知/深链/书签必须带 parent；只有 child 的深链拒绝或重定向到父树；
  - CLI `aether subagent result --parent <parent> --child <child>`；`aether subagent tree <parent>`。
- **合理性评估：** 与 ADR-032 UI-03 的“父树 → 子节点钻取”一致，是最小权限模型，能防止跨子 Agent 结果泄露。代价是搜索/深链/书签必须携带 parent，且父会话删除策略必须先定。
- **父会话删除（已确认）：有子会话时拒绝删除。**
  - `session_delete` 在执行前查询 `sessions.parent_session_id`；存在任一子会话（含已完成/失败）→ 拒绝，不级联、不改 `parent_session_id`；
  - UI 删除按钮在 `subagent_list` 有子节点时置灰，并提示“请先删除子会话”；
  - CLI/API 返回结构化错误：**新增业务码 `session_has_children`**（IPC `invalid_value` + `business_code=session_has_children`）；业务码 **34→35**；
  - 审计：复用 `session.deleted` 记录 `result=denied` + `reason=has_children`（不新增 audit action，减少 ADR-023 台账变更）；
  - 登记：`docs/M10-00-登记表.json` business_codes +1、`target.business_codes 35`、`verify:m10-00` 25→26、`verify:error-codes` business 34→35；UI-UX 增加 `session_has_children` 文案；
  - 测试：有子会话拒绝 → 子会话/结果完好；删除子会话后可删父；深度 2 树；重启后仍拒绝；
  - 父删除被拒绝后，事件不产生 `session.closed`，UI 保持原树。
- 审计：`subagent.result.pulled`，detail 含 parent/child、actor，不记结果内容。

### 1.8 Q8：CLI events 必须原生 WS

```toml
tokio-tungstenite = { version = "=0.29.0", default-features = false, features = ["connect"] }
```

- `tokio-tungstenite 0.29.0` MIT，MSRV 1.63；与 axum `ws` 传递版本一致。
- CLI `aether events --session <id> [--last-seq N]`：
  - 连接 `ws://127.0.0.1:<port>/v1/events`；
  - 首帧 auth；发送 subscribe；
  - JSONL 输出 `{"type":"event","envelope":{...9 字段...}}`；
  - 处理 gap/1013/1012/4401；断线用 `last_seq` 重连；
  - 退出码沿用 0–7。
- 删除 `messages_page` 轮询方案；G10 以 WS 事件流为准。
- 测试：stdio/HTTP/WS/CLI 对同一事件流 `seq`/`last_seq` 0 差异；慢消费者/鉴权/缺口/重连。

### 1.9 Q9：像素上限批准为 25MP

- **批准值：25,000,000 像素（25MP），最长边 8192。**
- 该值将写入 ADR-035 v1.1，替换原 100,000,000 像素上限。
- 内存估算：25MP ×4B ≈ 95.4MiB/图；2 并发 ≈190.7MiB；加 decoder 开销按 2× 估算约 380MiB，属于当前架构可接受范围。
- 覆盖范围：6000×4000（24MP）、5000×5000（25MP）、8192×3052（约 25MP）；1080p（2.07MP）、1440p（3.7MP）、4K（8.3MP）均通过。
- 拒绝：10000×10000（100MP）及更高；如产品确需 100MP，worker 必须并发 1 + 512MB 硬上限 + 基准测试，不推荐作为默认。
- `@napi-rs/image` 未提供 `limitInputPixels`；必须在构造 `Transformer` 前解析文件头宽高/像素并拒绝超限，GIF 同理。
- G11 测试矩阵需覆盖 25MP 边界、超限拒绝、1080p/4K 通过、内存峰值。

### 1.10 Q10：`attachment_add` 选 A

- **不返回 `storage_path`**；返回 ADR-035 `AttachmentSummary`：

```json
{
  "attachment_id": "...",
  "sha256": "...",
  "mime": "image/png",
  "size_bytes": 123,
  "width": 800,
  "height": 600,
  "created_at": 1762300000000
}
```

- renderer 用 `sha256` 构造 `aether-attachment://thumb/<sha256>`。
- main 按 `mime → ext` 映射解析 `<data_dir>/attachments/<sha[0..2]>/<sha>.<ext>`。
- 路径只在 main/诊断内部使用；诊断只记 sha 前缀，不记绝对路径。
- 若诊断需要路径，另加仅诊断字段/命令，不进入 `AttachmentSummary`。
- 建议 UI 详情复用 `subagent-result`/现有 testid，不新增 `subagent-result-detail`，保持 testid 18 不变；若产品要求独立 testid，再走 UI-UX v0.19。

### 1.11 Q11：晚注入选 A（不新增事件）

- `subagent.completed` 在子完成时发一次；`injected` 为**必填 boolean**（完成时快照）。
- `subagent_resolve` 返回最终状态：

```json
{
  "decision": "accept",
  "injected": true,
  "injection_id": "...",
  "context_version": 3
}
```

- `subagent_list.injection_state` 为权威读模型；UI 在 `subagent.completed` 后、以及 `resolve` 后都 refetch。
- 外部事件消费者收到 `completed` 后调用 `subagent_list`；晚注入由用户动作驱动，不推送新事件。
- 不重复发送 `subagent.completed`。
- 若未来外部消费者明确要求实时注入通知，再立 ADR 增加 `subagent.injected`；M10 不做。

## 9. 五项待定项建议（2026-11-05，v0.7 评审 → v0.8 已确认）

> 以下建议已由用户 2026-11-05 确认，回写 ADR/实现/证据（见 §11）。

| # | 项 | 建议 | 理由/影响 |
|---|---|---|---|
| 9-1 | `subagent_results` 是否加 `(parent_session_id, created_at)` 索引 | **不加** | 当前表只有 `child_session_id` 主键，没有 `parent_session_id` 列，不能直接加；加列会重复父子关系并产生漂移风险。`subagent_result_get` 按 child PK 查询；父列表走 `sessions(parent_session_id,status)` 或 `subagent_injections(parent_session_id,state,created_at)`。若后续实测慢查询，再以新迁移加列+索引，不预加 |
| 9-2 | `summary` 512B 上限 | **确认 512 字节（UTF-8），不是 512 字符** | 512B 约 170 个中文汉字/512 ASCII，适合列表预览；`subagent_results.summary` 与 `SubagentNode.result_summary` 同一口径；写入按 UTF-8 边界截断，建议加 `summary_truncated`，SQLite 可加 `CHECK (summary IS NULL OR length(CAST(summary AS BLOB)) <= 512)`；全量 summary 仍在 `result` JSON，详情走 `subagent_result_get` |
| 9-3 | Q5 三运行时真实测试环境 | **先 mock/单测，真实测试作为 M10-02 前置门禁；不阻塞 M10-03** | mock 覆盖 capability/ack/version/fold/restart/失败；真实测试向用户申请环境。矩阵：运行时+版本、CLI 路径、provider/model、凭据来源、OS、3 个子会话、context version 1→2→3、重启、失败注入；判定“模型只看到最新 `<aether:subagent-results>` 块、无重复、ack 正确”。结果写入 `docs/M10-02-证据.md`；失败则 `subagent_context=false`，auto_inject 转 hold |
| 9-4 | Q3 三平台打包 spike | **执行；未签名 DMG 也做** | Windows MSI、macOS 未签名 DMG、Linux deb/AppImage；每项验证 `utilityProcess.fork`、`@napi-rs/image` 加载、PNG/JPEG/WebP/GIF、25MP 边界、无 `sharp`/`@img/*`、`pnpm check:licenses`/SBOM；macOS 签名仍 `macos_release_pending`，但未签名 DMG 必须跑通 UtilityProcess 烟测；建议加 `verify:m10-05` 打包产物检查 |
| 9-5 | `--http-only` Windows 控制台关闭事件 | **用 Tokio 的 Windows signal API** | `tokio::signal::windows::{ctrl_c, ctrl_break, ctrl_close, ctrl_logoff, ctrl_shutdown}` 覆盖 `CTRL_CLOSE_EVENT`/注销/关机；`ctrl_close` 触发优雅关闭：停止接受 ≤1s、WS 1012、在途 ≤3s、删 discovery/释放锁；Windows console close 约 5s 预算，按 best-effort 记录；测试用 `GenerateConsoleCtrlEvent` 覆盖 Ctrl+C，手动关闭控制台覆盖 `CTRL_CLOSE_EVENT`，写入 `docs/M10-03-证据.md`；不引入 unsafe/windows-sys |

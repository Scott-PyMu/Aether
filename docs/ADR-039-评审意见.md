## 1. 总体结论

**文档完整性：不足（v0.1）。**  
ADR 具备背景、实测证据、候选方案、风险/回退与设计升版清单，但缺少单一决策、实施范围/任务/DoD、验收矩阵、契约增量、验证方案。作为草案可理解；作为批准稿不成立。

**一致性状态：部分一致，关键冲突未闭环。**

- M10-08 的核心数字与证据基本一致：单库 `quick_check` 97,849.350ms、8 分片并行墙钟 19,357.664ms、备份 163.85→51.41s、恢复 82.26→38.02s、保留批 P95 4.89s、外推 3.63h。
- 但 v0.1 存在以下冲突（裁定后需在 v0.2 改写）：
  1. D-039-1“分库候选”与 D-039-2“启动优化首选”未收敛；D-039-2 末段“建议分库与并行检查一并实施”与 D-039-4“启动优化 > 分库”矛盾。
  2. “检查中”临时只读/降级与 D3/D4 的 `persist_degraded`、`health.storage_state` 单一事实源冲突。
  3. 分库方案未回答 D3 单写者、D13 多库备份/恢复、`UNIQUE(session_id, seq)` 归属。
  4. 契约登记“0 新增”与 D-039-1“新增迁移 0014+”、§3“新增 health 字段（非命令面）”不一致。
  5. 5.35× 加速比计算基准不一致（按同口径约 3.76×）。

**最大风险：数据完整性与启动可用性。**  
跳过 `quick_check` 的判据、后台检查期间写路径、多库备份/恢复一致性，均可能导致漏检损坏、半写、恢复失败；其次是 G13/P2 退出路径因决策未收敛而不可验证。

**结论：**  
- **方向通过**：A（分库 + 并行检查）可进入设计升版/实施准备。
- **文本不通过**：ADR-039 v0.1 必须按 §3/§4 改写为 v0.2，完成独立签核后才能作为设计 v1.35 的依据。
- **M10-08 不重开**：M10-08 的“需分库”结论与证据保持不变；实施落在 M10-09/10/11。

**安全专项：** 未发现“把权限控制误述为沙箱”的问题；本 ADR 不新增外部信任边界、命令面或第三方依赖。主要安全/数据风险是**完整性检查绕过**与**多库备份/恢复一致性**；通过 sidecar 严格匹配、并行检查、维护态备份、manifest 校验与故障注入控制。

## 4. 实施规格（M10-09 / M10-10 / M10-11）

### 4.1 M10-09 事件分库（A：单写任务 + 每片连接）

**分片与初始化**

- `N = 8`；5.22GiB 数据集每片约 0.65GiB；单片上限 **1.5GiB**；超过时另立 resharding ADR。
- 新装初始化：主库 + `events-0..7.db`；全部创建成功才写初始化完成标记；失败删除半成品；不允许“半个库”。
- 分片库**复用主库迁移链**（至少 `schema_migrations` + `events` + 两个索引；可复用 0001–0013 完整 schema 以避免第二套迁移框架，只使用 `events` 表）；不得修改 0001–0013；0014 仅主库路由列，分片库可空跑或跳过，须在附录 C 写明。
- 主库保留 `events` 表但**永远为空**；启动断言主库 `events` 行数为 0；若不为 0 → 拒绝启动（优先）或进入只读安全模式，必须在 M10-09 证据中固定；不得静默忽略。
- 新增 **0014 `sessions.shard_id`**（1 迁移）；新会话写入；启动校验；未来 resharding 可更新。无线上数据迁移，开发库直接重建。
- 路由：`shard_id = shard_for(session_id)`；一个会话的全部事件永远在同一片；**会话不跨片**。

**写模型**

- 保留全局 `mpsc` 写队列（4096）与单写任务；单写任务持有 N 个分片写连接。
- 按 `session_id` 路由；每片 group commit（16ms 或 ≥256 条）；**不做跨片事务**。
- 事件写入分片成功后才广播（D4 不变）；主库 `messages` 终稿写入是独立事务；事件先落盘，消息终稿随后；失败按现有写失败路径处理。
- `UNIQUE(session_id, seq)` 每片成立；**不需要全局 seq**；保留会话 sequencer；不要写“全局单调 seq”。

**读模型**

- `events_page`/`events_latest`/`max_seq` 按 `session_id` 路由到片；`messages_page` = 主库 `messages` + 分片 `events`；`last_seq`/`complete` 语义不变。
- 读连接：主库 4；每片 1–2；总连接数 `min(2N, 16)`；读连接池按片管理。
- 禁止任何代码回退读主库 `events`；启动断言 + 测试覆盖。

**保留/归档/备份/诊断**

- 保留清理逐片执行；归档文件按片 + 全局 manifest；`archive_export` 汇总；`audit_log` 不清理。M10-09 只做分片路由/口径打通；批选/吞吐/收缩优化归 M10-11。
- 备份/恢复按 §4.4 维护态；诊断包包含主库 + 全部分片 + manifest + 每片 `quick_check` 摘要。
- 备份/恢复、导入等维护操作与分片清理互斥。

**契约**

- 命令 87 / 事件 0 / 设置键 11；迁移 0014 +1；`health` 增加 `storage_check`/`maintenance` 可选字段；M9-01 重录。
- 不新增 `events_*` 命令；不新增设置键；不新增事件类型。

### 4.2 M10-10 启动并行检查与预算

**指标与目标**

| 指标 | 定义 | 目标 |
|---|---|---|
| `windowShownAt` | 壳层窗口可见 | **≤1.5s（硬）** |
| `uiReadyAt` | 主界面可交互 + 首个 `health` 成功 | **≤1.5s（硬）** |
| `storageCheckCompletedAt` | 全部分片完整性检查完成 | **≤25s 目标 / ≤30s 硬** |
| `quickCheckPerShardMs` | 单分片 `quick_check` | 记录 P50/P95/max |
| `checkConcurrency` | 并行 worker 数 | 默认 4，最大 8；HDD 2 |

- `STARTUP_REVEAL_GRACE_MS = 1300ms`（给 1.5s 留 200ms 余量）；`windowShownAt` 中位必须 ≤1.5s。
- 启动序列改为：DB 打开（PRAGMA/迁移，**不含** `quick_check`）→ `initialize` → `health` 可用 → 后台并行 `quick_check`；不得在 `initialize`/`health` 前阻塞 `quick_check`。
- `uiReadyAt` 不能等 `quick_check` 完成；`health` 必须在检查完成前返回 `storage_check.state="checking"`。
- 检查中：`storage_state=normal`，`storage_check.state=checking`；读可用，写/新 run 禁用；UI“正在校验数据（x/8）”。
- 检查失败：`storage_state=persist_degraded`，`storage_check.state=failed`，`degrade_trigger=integrity_failure`；S-08/只读/导出/备份。
- 检查完成：`storage_check.state=ok`，横幅消失，写恢复。

**干净关闭（C：严格 sidecar + 混合策略）**

- 关闭序列完成、写队列 drain、全部库 `wal_checkpoint(TRUNCATE)` 成功后，原子写 `clean_shutdown.json`（临时文件 + fsync + rename）。
- sidecar 至少包含：`app_version`、`closed_at`、`close_sequence_completed`、`write_queue_drained`、`shards[]`（`shard_id/schema_version/header_change_counter/file_size/wal_size/last_seq`）、`main`（同字段）。
- 下次启动逐片比对；**全部匹配**才跳过阻塞 `quick_check`；任一不匹配（含 WAL 非 0/不存在但 size 变化）→ 全量并行检查。
- 干净关闭路径：跳过阻塞检查，启动后空闲时后台 `quick_check`；**每周 `integrity_check` 保留**；建议“每 20 次干净启动或 7 天”强制一次完整检查。
- 异常退出路径：并行 `quick_check`，检查期间只读 + 写门；失败进 `persist_degraded`。
- 恢复/导入/迁移/版本升级后 sidecar 必须失效（删除或写 `invalid`）。
- 残余风险写入 ADR：sidecar 匹配但页级损坏只能靠后台/周期检查发现；安全/QA 签核接受。

**并行检查**

- 启动时并行检查 N 个分片；worker 默认 4、最大 8；HDD 2；按平台/磁盘可降级。
- 30s 硬阈值；19.36s 是参考值，必须真实 daemon/release 复测；目标 ≤25s，给中位/长尾留 5s 余量。
- 记录单分片/总耗时/失败数；不得只报平均。
- 真实复测：5.22GiB/20M、release `aetherd`、真实 Electron、fresh userData/registry、3 次中位/P95/max。

### 4.3 M10-11 保留清理与文件收缩

**两阶段清理**

1. 选 rowid：`SELECT rowid FROM events WHERE type IN (?,?,?) AND ts < ? ORDER BY type, ts LIMIT 5000`；用 `idx_events_type_ts`；先 `EXPLAIN QUERY PLAN` 确认无 TEMP B-TREE。
2. 归档：按 rowid 取全列 → `archive_retention_batch` 写 JSONL + fsync + manifest + 校验；失败跳过该批（ADR-021 不变）。
3. 删除：`DELETE ... WHERE rowid IN (...)`，单事务；按 500/1000/2000/5000 四档实测，选“P95 <500ms”的最大档；当前预期 500–1000 行。
4. 不得以放宽 D3 `<500ms` 代替优化；`RETENTION_BATCH_MAX=5000` 可保留为选批上限，删除事务可更小。

**文件收缩**

- 新库建表前设置 `PRAGMA auto_vacuum=INCREMENTAL`；保留后执行有界 `PRAGMA incremental_vacuum(N)`。
- 物理文件仍 >5GiB 时提供维护态手动 `VACUUM`；预检可用空间 ≥ 当前 db+wal ×2；记录耗时/停写窗口。
- 容量口径：逻辑 live bytes 与物理 db+wal 分开报告；不得用 1.387GiB live 代表物理达标。

**总时长**

- D3 只硬约束单事务 <500ms；全量历史清理建议作为后台 KPI：≤4h；日常增量 ≤5min；不阻塞启动/UI。
- 若产品要求更短，另立优化任务；不得降低单事务目标。

### 4.4 D13 维护态备份/恢复（R5）

**维护态（按用户口径：其他功能不可用）**

- 备份/恢复期间进入维护态；除以下命令外全部拒绝：`health`、`app_exit`；备份进度经 `health.maintenance` 返回。
- 复用 ADR-034 维护窗口机制；错误用现有 `storage_backpressure` + `maintenance_reason`（`backup`/`restore`），**不新增业务码**；若实现发现语义不可接受，停下来报告，不得静默新增。
- `health.maintenance`：`{kind: "backup"|"restore", started_at}`；UI 维护页/横幅；不得显示为 `persist_degraded`。
- 自动备份：仅在无 active run/写入空闲时启动；不抢占在途 run；手动备份需确认进入维护态。
- 备份期间其他功能不可用（包括读/会话/设置/导入导出）；UI 显示维护页；完成后恢复。

**备份步骤**

1. 进入维护态；停止新写/新 run；drain 写队列。
2. 主库 + 全部分片 `wal_checkpoint(TRUNCATE)`。
3. 逐片 `VACUUM INTO`（可限并发 2–4）+ 主库 `VACUUM INTO`。
4. 写 manifest：`backup_id`、时间、app/schema 版本、分片数、每片 `shard_id/path/size/sha256/max_seq`、主库 schema/大小、总行数。
5. 退出维护态；记录审计。

**恢复步骤**

1. 进入维护态；停写。
2. 校验 manifest + 所有分片/主库 `quick_check` + 迁移版本。
3. 当前整套库改名 `.pre-restore-<ts>`；复制新整套。
4. 验收：重新打开 + `quick_check` + 迁移；任一步失败回滚整套。
5. 重启 daemon；写审计；退出维护态。

**归档/诊断**

- 归档逐片文件 + 全局 manifest；`archive_export` 汇总。
- 诊断包包含主库 + 全部分片 + manifest + 每片 `quick_check` 摘要。
- 加密备份/恢复（ADR-020）在整套备份上执行；不得逐片单独加密导致 manifest 不一致。

10. **MUST NOT** 新增命令/事件/设置键；`health` 仅可选字段；业务码复用 `storage_backpressure`（维护原因），不新增（如确需新增，停下来报告）。
11. **MUST NOT** 修改生成物、修改已发布迁移、绕过权限网关、先广播后写日志、泄露密钥。
12. **MUST NOT** 重开 M10-08；实施只在 M10-09/10/11。

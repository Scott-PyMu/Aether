## 3. 新发现问题

### P1-1｜降级失效口径缺 `always` 作用域（安全绕过路径）

- 问题：不变量 9（ADR `:228`）与计划 DoD8⑥（`:208`）都只写「既有 `scope=session` grants 立即失效重算」。但 `permissions.scope` 的枚举为 `once` / `session` / **`always`**（`migrations/0001_init.sql:111`），而 M6-01 的任务标题即「自定义权限规则与 **`always` 作用域**」（计划 `:197`）。后果：用户在顶档对某 target 授予 `always` 写权限后把会话降级为 `read_only`，该授权仍可放行写请求 → 档位被绕过（R4 原话为"既有 **`always`/`session`** 授权失效"，只落实了一半）。
- 依据：ADR `:228`；计划 `:208`⑥；`migrations/0001_init.sql:111`；计划 `:197`；首轮评审意见问题 5。
- 建议（改写文本）：不变量 9 与 DoD8⑥ 统一为——「档位变更后，既有 **`session` / `always`** 授权按新档位重新求值；`read_only` 下不因任何既有授权放行写请求；已 `pending` 票据按原决议收口，不被追溯改写」；DoD8 增断言用例：顶档授 `always` → 降级 `read_only` → 写请求按新档位判定（deny）。

### P1-2｜权限基准语义（R15 已定：按会话创建固定）——须补影响面与断言口径

- 现状：不变量 11（`:230`）与计划 M7-08 DoD2（`:322`）已写"基准目录在**会话创建时**按当时工作区绑定确定"。R15 确认该口径；但**该写法改变了 P0 行为**：P0 为"换根后后续权限评估（含执行器回环）**立即**使用新基准目录；单工作区模型下全局生效"（`crates/aether-control/src/permission.rs:290-302`），即既有会话也切到新基准；而计划 M7-08 DoD6（`:326`）仍要求「M3-08 `workspace_set` E2E 不回归」——两者未对账。
- 建议（改写清单）：
  1. **不变量 11** 补三句：「基准 = 会话创建时 `sessions.workspace_id` 对应工作区根（`workspace_id IS NULL` → 数据目录）；**`workspace_set` 换根仅对新会话生效**，既有会话保持原基准；`session_workspace_assign` 不重算（防改派放大权限）」。
  2. **计划 M7-08 DoD2 `:322`** 同步上述三句，并把"`workspace_set` 与 `session_workspace_assign` 的入口关系"指向 P1-A12（DoD5 `:325` 已列该义务）。
  3. **影响面登记**：ADR §3.1/§3.6 增一行「M3-08 `workspace_set` 换根语义由『全局立即生效』改为『仅新会话生效』（R15）」。
  4. **计划 M7-08 DoD6 `:326`** 改为「M3-08 `workspace_set` E2E 按新口径（换根仅新会话生效）复跑绿 + M3-12 分组不回归」；若 P0 断言的是全局换根，属**设计变更驱动的断言更新**，须在任务证据注明（AGENTS §6：不得为过测试放宽）。
  5. **`permission.rs:290-302` 注释**随实现更新（M6-01/M7-08 任务内），避免代码注释与设计口径相反。

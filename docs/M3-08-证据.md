### DoD1 注入：会话创建注入记忆文件；32KB 上限截断 + 显式标记；优先级顺序断言

**验证方式**：`aether-control --lib memory::` 单测（组合/优先级/截断/T7）+ 集成
`m3_08_memory::workspace_set_injects_memory_and_swaps_permission_root` + Mock session-log


## 4. 边界与实现级记录（不引入设计未定义决策）

1. **`session.create.system_prompt` 为可选成员扩展（实现级，非设计变更）**：D14 已冻结
   「会话创建时注入」；注入文本经既有 `sessions.system_prompt`（附录 E 既有字段）承载并
   以下发成员形式进入 `session.create`。口径同 ADR-010 对 `session.create` 可选成员的
   扩展方式（ADR-003：新增字段只增不改语义，旧适配器忽略未知成员）；未新增方法/事件/
   迁移，T14 无变更。
2. **记忆工具的文件操作在适配器侧执行（D9 信任边界不变）**：核心负责注入组合与策略判定；
   `memory.read/append/write` 的真实文件 I/O 由适配器（SDK `memory.ts`，Mock 为 P0 参考
   实现）执行并经 `permission.request` 回环上报。权限门仍**仅约束经线协议上报的工具调用**；
   适配器进程内行为不经此门（AGENTS §2.7）。
3. **`memory_conflict` 为 `tool.call_failed.error.code`（既有载体）**：未新增 IPC 错误码/
   事件类型；UI-UX §5 已登记该码的展示口径（阻断该次写入、不阻断会话）。
4. **P0 单工作区模型与「旧会话不迁移」**：`PermissionService` 策略引擎为单根；`workspace_set`
   后全局换根（新会话的注入与权限基准同源生效），已有会话的 `sessions.workspace_id` 与
   注入文本保持不变（ADR-004 决策 3：「已有会话迁移不在 P0」）。多工作区并发门禁属 P1。
5. **权限回环会话归属映射修正**：适配器 `permission.request.session_id` 为适配器会话 id；
   执行器新增 `SessionMappingGate` 将其映射为核心 `sessions.id`（待审批行外键与 UI 过滤
   一致）。此前网关为 `None`，该路径在生产从未激活，属 M3-08 接线内的必要修正。
6. **原子写的临时文件残留**：进程在 rename 前被终止时，目标文件保证无半写；同目录临时
   文件可能残留（`.name.aether-tmp-<ulid>`）。方案未包含启动清理（P0 无此需求；若引入，
   属实现级调整并记录）。冲突/失败路径会清理临时文件。
7. **注入一致性**：不缓存文件内容（每次会话创建重新读取），自然满足 D14「文件变更仅对
   新会话生效」；未引入 `notify` 监视（P0 简化，无行为差异）。
8. **未变更**：D9 策略矩阵语义 / `permission.request` 通知形状（新增可选 `content_bytes`
   已有 M2-10 契约）/ 事件类型清单 / DDL（0001、0002 均未修改）/ 命令面（无新增命令）。

## 0. 总原则与并行假设

- 并行假设：2–3 名开发者 + 1 名兼职评审（实施计划 §0）；并行分组以 §1.3（G1–G10）为准。
- 每个施工步的交付物 = 代码 + 验证脚本/测试 + 证据归档；提交信息引用任务 ID（如 `M1-03`）。
- 冻结基线（设计 v1.5 / 需求 v0.5 / 计划 v1.11）不得绕过 ADR 修改；常量级调参须记录在任务证据。
- 门禁不通过时执行实施计划对应「回退动作」，不自行降级方案。

**立即第一步（第 0 批）**：归档提交现有未提交改动 → `pnpm ci:local` 绿线 → 按检查表 §0 复核 CI verifier 覆盖。

## 1. 阶段 A：P0 前必办（可三线并行）

入口：第 0 批绿线完成。出口：三项 DoD 证据齐备，进入阶段 B 或直接进 Gate 1 收口。

### A1. M1-03 DoD5 —— 0002 迁移与审计
1. 编写 `migrations/0002_*.sql`：`ALTER TABLE messages ADD COLUMN client_msg_id TEXT` + `CREATE UNIQUE INDEX`（events、messages 各一），删除冗余 `idx_events_session_seq`。
2. `migration.rs` 追加 0002；迁移幂等/篡改拒绝用例复跑。
3. 编写重复键审计脚本并输出报告（seq、client_msg_id 两组）。
4. `cargo test -p aether-store` + `node scripts/test/m1-03/verify-m1-03.mjs`。
- 约束：**不修改 0001**；审计报告随任务证据归档。

### A2. M1-09 DoD8 —— 16MiB → 2MiB 读取器
1. `framing.rs` + `framing.ts` 常量与逻辑收敛：单帧 ≤2MiB；`artifact_ref` <1MiB；1–2MiB 假引用帧按违约断连。
2. 更新边界测试夹具（16MiB 样本改 2MiB；补 1–2MiB 用例）。
3. 回归 `pnpm verify:m1-09` + T10（畸形帧/超长行/半行/坏 JSON）。
- 约束：Mock/SDK 同步；吞吐基准复跑 ≥1000 delta/s。

### A3. M1-11 DoD2④/DoD3 —— 会话恢复验证
1. spike 样例脚本加「重启进程 → `native_id` 恢复 → 续聊」步骤（Claude Code 优先，Codex 复测可选）。
2. 产出 Mode R/N 结论并写入接入笔记（`docs/spike/M1-11-接入笔记.md`）。
3. `verify-m1-11` 输出含恢复结论。
- 约束：该结论直接决定 M2-02/M3-06 的重放语义，不得推迟。

**阶段 A 出口**：`pnpm ci:local` 全绿；三项证据归档；tracker 更新（P0 前必办关闭）。

## 2. 阶段 B：Gate 1 主体（批次 2）

入口：阶段 A 出口。出口：M1-01…M1-10 DoD 全通过。

### B1 → B2. 关键路径（串行）
- **B1 M1-04 写队列**：`mpsc(4096)` 单写任务 → 16ms/≥256 group commit → 4 读连接池 → L1 告警/L2 `storage_backpressure` 接口；新增写/读延迟基准。
- **B2 M1-05 事件管线**：normalizer → sequencer → journal → 先日志后广播；delta 合并；`last_seq` 补读；`persist_degraded`+只读状态机（未落盘不广播、在途 run cancelled、`health` 呈现）；DB UNIQUE 兜底。
- 依赖链：M1-04 依赖 M1-03（A1）；M1-05 依赖 M1-04。

### B3. M1-10 监督器（与 B1/B2 并行）
- 状态机（含 `degraded → ready`、`disabled → cold/starting`）；10s 心跳×3；退避/熔断；进程组 + Job Object/`TerminateJobObject`；PID 台账三条件；白名单；资源采样；`runtime_retry`/`runtime_enable` 命令。
- 验证：平台断言、T5a/T5b 脚本、PID 复用夹具。

### B4. M1-06 目录检测/迁移流/单实例（并行）
- Win 三类 + mac 两类检测；「迁移/退出」拒绝启动流；迁移执行；单实例锁；T12/T13。

### B5. M1-08 补齐（并行）
- 七命令 DTO/校验矩阵（ADR-004）；`session_send.client_msg_id` 改必填 ULID（ADR-005）；`pnpm verify:m1-08` 复跑。

**阶段 B 出口**：clippy 0 告警；`cargo test --workspace`；m1-04/05/06/10 各自证据；覆盖率不低于 70%。

## 8. 风险与应对

| 风险 | 应对 | 触发点 |
|---|---|---|
| Claude Code 无原生恢复（Mode N） | 重放语义降级为「新会话重发 + UI 明示」；M2-02/M3-06 按 Mode N 验收 | A3 结论 |
| 2MiB 上限回归面大 | A2 后全量 T10 + m1-09 套件；异常帧样本留档 | 阶段 A |
| M1-04/M1-05 关键路径最长 | 优先启动，M1-10/M1-06 并行消化；评审只看证据不全量重构 | 阶段 B |
| 覆盖率下降 | 新模块自带单测/集成；aether-tauri 排除为既有常量决策 | 每批出口 |
| 混合提交/范围蔓延 | 第 0 批归档隔离；单任务范围提交，提交信息引用任务 ID | 全程 |
| 迁移若遇历史重复键 | 先审计后迁移；无法安全去重时按 ADR-004 §6 回退评审 | A1 |

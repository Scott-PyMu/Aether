## 1. DoD-1 定义 schema

- 版本化 JSON `schema_version=1`；5 类节点 `agent/task/condition/parallel/join`；白名单字段（`deny_unknown_fields`）。
- 上限：定义 ≤256KiB、nodes ≤64、深度 ≤32、fan-out ≤16、单次运行执行次数 ≤256、name 1–128、description ≤1024、prompt ≤32KiB。
- 校验：DAG 无环（Kahn）、ID 唯一且匹配 `^[a-zA-Z][a-zA-Z0-9_-]{0,63}$`、边端点存在、parallel 出边/fanout、join mode/quorum、表达式白名单（深度 ≤16/节点 ≤256）。
- 非法定义一次返回多条 `{path,reason,code}`，最多 50 条并标记 `truncated`；`invalid_value + business_code=workflow_invalid_definition`；不落库。
- 定义快照：`definition_hash = sha256(canonical JSON)` 写入 `workflow_runs.definition_hash`。

## 2. DoD-2 执行语义

- 串行/并行/条件/汇总：DAG 依赖调度；`parallel` 节点按出边并发（受 `max_parallel`/全局闸门约束）；`join` 支持 `all/any/quorum` 与 `on_failure`；边 `when` 为假 → 下游 `skipped`。
- 失败策略：`fail_fast`（默认）/`continue`；`fail_fast` 首个不可重试失败取消兄弟分支；`continue` 保留汇总并置运行 failed。
- 超时/重试：节点 `timeout_ms` 1s–24h；`retry {max_attempts 1…5, backoff_ms 100…60000, multiplier 1…4}`；仅可重试错误自动重试；重试新建 attempt（不改写旧行）。
- 取消：`workflow_run_cancel` 级联；ack 后 ≤5s 收口；超时强制标 cancelled + `workflow_cancel_timeout`。
- 幂等：`node_runs` 唯一键 `(workflow_run_id,node_id,attempt)`；daemon 重启不自动重放。


## 3. DoD-3 持久化

- 落库：`workflows` / `workflow_runs` / `node_runs` / `tasks`；每次状态推进先经单写队列提交，再发事件。
- `workflow.*` 9 子类型 payload 按 ADR-031 D-031-5 严格解析（核心事件，Normalizer 放行；适配器伪造仍受严格校验）。
- 运行锚点：事件 `session_id = workflow_runs.session_id`；节点子会话事件使用子会话 `session_id`。
- `workflow_runs.context` 持久化 `{input, values, priority}`；运行/节点终态与 attempt 历史保留。
- reconcile：`running/queued` 运行 → `interrupted`；`pending/queued/running` 节点与任务 → `cancelled`；无重复/无悬挂、不自动重放。

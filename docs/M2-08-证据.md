## 3. 边界与承接声明

1. **生产注册表为空（M2-01 口径）**：P0 壳层监督器注册表当前为空（真实适配器 spec 由 M2-02/M2-11 的集成路径注入，不在生产 `build_backend` 中）。启动序列尾段在空注册表下：孤儿清理仍具实际意义（清理上次崩溃遗留台账记录）、预热为 no-op、监控任务为零；退出编排的适配器段为空、存储五步照常执行。T11/T5b 通过注入真实夹具 spec 验证同一代码路径。
2. **启动顺序口径**：实际顺序为「库打开 + `quick_check` + 迁移（`boot_core_health_with_slot`）→ 孤儿清理 → 预热 → 监控」，与 D2 启动序列（库打开 + `quick_check` → 孤儿清理 → 迁移 → 预热）一致；迁移与库打开同属 `StoreRuntime::open`，未拆分。
3. **退出顺序口径**：`AppShutdown::run` 固定「停监控 → 广播 shutdown（管线停机）→ 适配器终止段（并发，D5 逐步硬超时）→ 存储五步」；存储五步的内部顺序由 M2-06 shadow 日志断言（`d2_order=true`）。
4. **退出预算语义**：`APP_EXIT_BUDGET = 10s` 为整体上限（T11）；D5 各步超时不变，超限时记录 `deadline_expired=true` 并放行进程退出（D2「保证能退出优先」）；`run_blocking` 超时兜底额外 2s。
5. **`--survive-eof` 仅用于故障注入**：默认行为不变（stdin EOF 即退出）；`--survive-eof` 显式模拟「核心被强杀后仍存活」的卡死适配器，供 M2-08/M4-01 复用。
6. **真实应用退出接线已验证**：`RunEvent::ExitRequested` → 清理 → 原退出码退出；M2-07 E2E（真实 WebView2）三场景退出码与证据行已在案（§2 DoD2）。

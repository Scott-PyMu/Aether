## 1. 目的与范围

按 P1 实施计划 M8-01 DoD1–DoD3：

1. **DoD1**：P1 新机制故障场景逐项脚本化夜跑通过，每场景输出「触发 → 自动应对 → 恢复」三段证据并归档；
2. **DoD2**：P0 30 场景在 P1 代码基线上全量重跑不退化（差异须记录理由并经评审）；
3. **DoD3**：连续 ≥3 轮夜跑全绿（预注册；同一执行期连续执行，不要求跨自然日），flake 逐条记录与处置。

**分层口径**（沿用 P0 M4-01/02/03 先例）：任务级测试（M5–M7）验证单点行为正确；M8-01 验证 P1 代码基线上「端到端脚本化执行稳定 + 三段证据归档」，编排既有权威测试并提取其证据行，**不重复实现断言、不放宽任何断言**。

## 2. 判定标准（预注册）

### 2.1 DoD1：P1 新机制故障场景（9 项，缺一不可）

| # | 场景 id | 故障面 | 权威测试载体（脚本编排） |
|---|---|---|---|
| 1 | `encrypted-backup-corrupt-passphrase` | 加密备份损坏 / 口令错误 / 主密钥不可用 | `m5_03_encrypted_backup`（DoD1/DoD3/DoD2） |
| 2 | `retention-interrupted-archive-failure` | 保留清理中断（归档失败注入 → 跳过清理；删除单事务原子） | `m5_04_retention`（DoD3/DoD5）+ `m5_04_retention_ops`（DoD5） |
| 3 | `rules-bypass-attempts` | 规则绕过尝试（硬边界不可放宽 / T7 逃逸样本 / 零直通） | `m6_01_permission_modes` + `m6_02_rule_safety` |
| 4 | `hotplug-midflight-crash` | 热插拔中途崩溃（在途 run 期间终止；10 次循环无孤儿） | `m7_01_hotplug`（DoD2/DoD4） |
| 5 | `pause-deadlock` | 暂停死锁（受控中断 / 等待槽保留 / best-effort / 恢复重放） | `m7_03_pause`（control）+ `m7_03_pause`（tauri，夹具端到端） |
| 6 | `routing-no-candidate` | 路由无候选（全部禁用 / 无匹配模型 / 无 ready 候选） | `m7_02_routing`（DoD1/DoD2/DoD4） |
| 7 | `audit-export-interruption` | 审计/导出中断（失败注入不留半成品；外部路径护栏） | `m6_03_audit`（DoD3） |
| 8 | `provider-connectivity-timeout-auth` | 供应商连通性测试超时 / 凭据失效 | `m7_06_provider_connectivity` |
| 9 | `reference-injection-path-exception` | 引用注入路径异常（畸形矩阵 / 不可用路径 / 合法引用观测） | `ipc_validation`（references 矩阵）+ `m3_09_artifacts` + adapter-mock vitest |

**通过条件（每场景）**：

- 该场景全部步骤退出码为 0；
- 场景定义声明 `trigger` / `response` / `recovery` 三段证据标记，且每个阶段至少命中 1 条证据行（含 JSON 字段断言的标记必须断言通过）；
- 证据行/产物归档到 `scripts/test/.tmp/m8-01/run-<stamp>/round-<n>/scenarios/`（场景 JSON + 原始日志 + 测试自身证据 JSON）。

### 2.2 DoD2：P0 30 场景回归

全量重跑 P0 M4-01/02/03 三套演练脚本（Windows 本机；不使用 `--skip-e2e`）：

| 套件 | 场景数 | 基线 id 清单 |
|---|---|---|
| M4-01 进程类 | 11 | `task-panic`、`core-oom`、`exit-hang`、`ui-lag`、`start-crash`、`untrusted-adapter`、`runtime-crash`、`deaf-hang`、`orphan`、`output-flood`、`double-open-adapter` |
| M4-02 存储类 | 8 | `disk-full`、`db-corruption`、`wal-growth`、`write-backlog`、`double-open-write`、`persist-failure`、`sequencer-crash`、`readback-gap` |
| M4-03 协议与并发类 | 11 | `half-line`、`invalid-json`、`request-timeout`、`version-mismatch`、`stdout-log`、`slow-ui`、`outbound-backlog`、`cancel-storm`、`deadlock-task`、`broadcast-full`、`delivery-backlog` |

**通过条件**：三套 `summary.json` 均为 `failed=0`，`passed=total`，且场景 id 集合与上表逐一相符（共 30 项）；任何场景失败即 DoD2 不通过。若与 P0 基线存在**断言/语义差异**，必须在证据文档记录差异、理由并经评审，不得静默修改 P0 脚本。

### 2.3 DoD3：连续 3 轮夜跑

- **轮次定义**：一轮 = DoD1（9 场景全量）+ DoD2（P0 30 场景全量）各执行一次；`--rounds 3` 在同一执行期连续执行 3 轮（**不要求跨自然日**，ADR-013 P2-4 口径；夜跑是执行方式，不构成日历门槛）。
- **通过条件**：3/3 轮全部绿色；任一轮失败即该轮不通过，必须记录、定位、修复后**重跑至连续 3 轮全绿**（重跑不改变断言）。
- **判定材料**：每轮 `round-<n>/round.json` 记录场景数、步骤退出码/耗时、P0 套件结果；总 `summary.json` 记录 `rounds_required=3`、`rounds_passed`、`flakes`。

## 3. Flake 处置（预注册）

- **允许的重试**：仅限基础设施抖动（端口占用、CI 慢机、WebView 启动超时等）的**步骤级**兜底重试；重试次数写在脚本步骤定义中（`retries`），**不得**用于掩盖断言失败。
- **记录义务**：每次重试/失败写入 `flake-ledger.json`（轮次、场景、步骤、尝试序号、耗时、最终结果、处置），并在证据文档 §flake 表逐条列出；**不得静默豁免**（AGENTS §3；P1 计划 §6「不得静默豁免」）。
- **处置方式**：环境 flake → 记录 + 复跑；产品/断言缺陷 → 修复产品/夹具（不得放宽断言）+ 复跑；上游时延类 → 记录窗口与实测值（同 M7-05 先例）。
- **判定**：只要最终 3/3 轮全绿且每条 flake 有记录与处置，DoD3 通过；不得以「重试后通过」替代失败记录。

- 平台：Windows（P0/P1 夜跑口径；Windows Job Object / TerminateJobObject 与真实 WebView E2E 的平台断言）。

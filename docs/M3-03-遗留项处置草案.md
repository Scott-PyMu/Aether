## 2. 归属裁定与承接机制（已裁定）

### 2.1 归属

- **等待态写入与等待审批分组 → 新增任务 M3-12**（权限中心主题：D9、UI-01/UI-02、SE-02）；登记要件见 §5。
- **执行器权限网关接线 → 仍留 M3-08**（主题=工作区基准；不含等待态写入，M3-08 DoD 保持 7 条）。
- 原方案 A（挂 M3-08）不采纳；方案 B 即现行裁定。M2-05 证据 §4.4「由 M2-10/M3-03 接线」的归属表述以**注记更正**处理（首轮裁定 5，见 §7）。
- 不回改原则边界：仅适用于**已过 Gate 的历史结论行**；归属注记按「追加更正注记、不抹改历史行」处理（首轮 §4 P2-9 裁定口径）。

### 2.2 承接机制要点（实现时固化于任务证据，不改设计）

1. **控制层新 API**：`SessionManager` 提供等待态标记入口；`PermissionService` 在票据状态变化时通知（组合根注入/两阶段装配；不得新增全局状态，不得绕过 `SessionManager` 直接改写状态）。
2. **置位与守卫（复审 N5）**：同一会话 pending 票据 `0→1` → `running → waiting_permission`；**置位仅当当前状态为 `running` 时生效**；非 `running`（如已 `idle`/终态）时 **no-op**——ask 与 run 终态竞态不产生非法转移（与回程 no-op 对称）。
3. **回程边界（首轮 P1-4）**：`1→0` 触发回程，**仅当当前状态为 `waiting_permission` 时生效，否则 no-op**；覆盖重启恢复票据经决议/超时（`1→0`）路径——不回程、不产生多余 `session.status_changed`。
4. **回程合法性（首轮 P2-7）**：allow / deny / 超时 / 取消 + **run 失败收口路径**（崩溃/断流）；「取消 × 超时/决议并发」幂等（沿用「票据从审批队列摘除 = 唯一仲裁点」口径）。
5. **单一写者**：状态转移仍只由 `SessionManager` 落行并广播 `session.status_changed`（附录 B 既有事件，payload `from/to`）；权限服务只上报等待状态变化。
6. **并发口径（首轮裁定 6，复审裁定 3 书面落定并追认）**：同会话「最多 1 个待审批」按 D9「（排队展示）」= **展示/交互口径**；**多会话可同时等待**（断言）；服务层并发 pending 能力保留（M2-03 冻结语义与 M3-03 DoD2 证据有效）。如需服务层强制，属设计变更，须另立 ADR 并回收相关证据——本草案不按服务层口径实施。
7. **重启口径**：`restore_pending` 仅恢复台账（等待者随旧核心退出）→ 不标记等待态（显式断言）；见第 3 条回程边界。
8. **不新增**：命令、事件类型、审计动作、表结构、迁移零变化（T14 无变更）。

### 5.1 任务卡

- **任务名**：M3-12 会话等待态写入与等待审批分组（权限中心主题）。
- **对应决策/需求**：D9、UI-01/UI-02、SE-02。
- **依赖**：M3-02、M2-03（集成层硬依赖）；**生产组合路径集成 E2E 条件依赖 M3-08**（网关 + 工作区基准）；回归依赖 M2-05/M2-10 证据口径。
- **量级**：**M（初判，类比 M3-03；动工前复核，调整记入任务证据）**。
- **验证入口**：`pnpm verify:m3-12` + CI job + 证据归档（沿用 M3-0x 口径）；**无命令/事件/迁移变化，T14 保持无变更**。

### 5.2 DoD 定稿建议（7 条）

1. **等待态写入**：同会话 pending 票据 `0→1` 置 `waiting_permission`、`1→0` 回程；**置位仅当当前状态为 `running` 时生效、回程仅当当前状态为 `waiting_permission` 时生效，非适用态均 no-op**（ask 与 run 终态竞态、重启恢复票据等不产生非法/多余转移）；状态仅由 `SessionManager` 落行并广播 `session.status_changed`（复用既有 19 边状态机；不新增命令/事件/迁移）；**静态检查：`permission.rs` 无会话状态写入调用（脚本断言，必做）**（复审 N5/N6）。
2. **回程合法性**：allow / deny / 超时 / 取消 + run 失败收口路径；「取消 × 超时/决议并发」幂等（票据摘除唯一仲裁点）。
3. **重启**：`restore_pending` 不标记等待态；恢复票据决议/超时后无回程、无多余 `session.status_changed`。
4. **多会话并发等待断言**（首轮裁定 6；服务层并发 pending 能力默认保留；同会话 ≤1 为展示口径）。
5. **会话列表分组**：按 UI-UX §2.2 组序（运行中 → 等待审批 → 失败 → 其他）、空组隐藏；**锚点契约按复审裁定 5 写死**（表见下，实施时登记 UI-UX §7.3 并冻结；UI-UX §7 标题与 §7.3 标题范围随之扩展至 M3-12；既有锚点不得重命名）。**（已前置登记冻结：UI-UX v0.3，2026-09-29；实施按冻结契约核验）**；前端集成 E2E（分组出现/消失）。
6. **生产组合路径集成 E2E**（M3-08 关闭后）：以生产组合（工作区基准 + 执行器权限网关 + 真实 `PermissionService` + Mock 适配器进程）驱动真实工作区 ask → `running → waiting_permission` 与合法回程；断言 `session.status_changed` 的 `from/to`。验证层级 = 集成（分层口径同 M3-03 证据 §4.1）；**真实 WebView 内联回环 E2E 归 M4-05，本任务不重复**（复审 N1/裁定 2）。
7. **回归**：M2-05 取消路径、M2-10 零直通、M3-03 队列口径、M3-02 verify 静态检查（分组改动触及 `SessionWorkbench` DOM）。

**DoD5 锚点契约（已定；UI-UX §7.1 规则：小写 kebab-case、状态放 `data-*`、既有冻结锚点不重命名）**：

| 界面 | `data-testid` | 关键状态属性 | 说明 |
|---|---|---|---|
| 会话列表容器 | `session-list`（既有，不重命名） | — | 结构由扁平 `ul` 改为分组容器（类型可变，testid 不变） |
| 分组容器 | `session-group` | `data-group` = `running` \| `waiting_permission` \| `failed` \| `other` | 固定组序：运行中（running/creating）→ 等待审批 → 失败 → 其他 |
| 分组标题 | `session-group-title` | — | 文案可微调，断言不依赖文案 |
| 会话项 | `session-item` / `session-item-status`（既有，不重命名） | `data-session-id`、`data-active` | 组内归属不变 |

**断言接口（DoD5）**：`getAllByTestId("session-group")` 的 `data-group` 序列 = 非空组的固定组序子集；空组不渲染（对应 `data-group` 查询为 null）；等待态出现/消失时 `waiting_permission` 组的增删；`session-item` 不得跨组错位。

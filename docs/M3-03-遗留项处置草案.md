### 1.2 归属方案（待评审裁定）

**方案 A（推荐）：登记为 M3-08「属主承接项」**

- 理由：M3-08 是执行器权限网关接线（工作区根）的属主（F5），生产 ask 自本任务起可达，等待态可在同一次集成/E2E 中端到端验证；与 v1.15 先例同构（承接项 + Gate 3 出口核验）。
- 成本：M3-08 增 1 条 DoD（R2b）+ 1 条追记（R2a），无新任务、不改 Gate 结构、不出设计文档。

**方案 B（备选）：单列任务（拟 M3-12）**

- 仅当评审认为 M3-08 超载时采用；属计划结构变更，需在评审记录中显式登记（新增任务），登记方式比照 ADR-010 §E.3。
- 依赖建议：M3-02、M2-03；生产 E2E 依赖 M3-08 网关接线（可先落集成层）。

**不采纳**：M3-03 内补做（超任务范围，AGENTS §4）；无评审挂靠 M3-08；从 P0 删除（属设计变更，另走 ADR）。

> 归属记录口径：M2-05 证据 §4.4 中「由 M2-10/M3-03 接线」的表述以本草案批准的处置为准（M3-08 承接）；已通过任务的证据不回改（历史记录），由本草案与 v1.18 承接项覆盖。

### 1.3 承接机制要点（实现时固化于任务证据，不改设计）

1. **控制层新 API**：`SessionManager` 提供等待态标记入口；`PermissionService` 在票据状态变化时通知（组合根注入/两阶段装配；不得新增全局状态，不得绕过 `SessionManager` 直接改写状态）。
2. **计数语义**：同会话 pending 票据 `0→1` 置 `waiting_permission`；`1→0` 触发回程。服务层允许同会话并发 pending 与 UI「≤1 激活 + 排队展示」口径均不变。
3. **单一写者**：状态转移仍只由 `SessionManager` 落行并广播 `session.status_changed`（附录 B 既有事件，payload `from/to`）；权限服务只上报等待状态变化。
4. **回程合法性**：run 仍活跃 → `waiting_permission → running`；run 已收口/取消 → 随 M2-05 既有收口序列（`waiting_permission → running → idle`），不得双跳；与「票据从审批队列摘除 = 唯一仲裁点」一致，回程必须幂等，不与取消路径互撞。
5. **重启口径**：`restore_pending` 仅恢复台账（等待者随旧核心退出）→ 不标记等待态（显式断言）。
6. **不新增**：命令、事件类型、审计动作、表结构、迁移零变化。

### 1.4 关闭条件（Gate 3 核验）

- 集成：真实 `PermissionService` + `SessionManager` + Mock 适配器（复用 M2-10/M3-03 测试 harness）：ask → `running → waiting_permission`；allow / deny / 超时 / 取消四路径回程合法；同会话并发 ask 计数（首张置位、末张回程）；`session.status_changed` 的 `from/to` 断言；重启恢复不标记。
- E2E：会话列表「等待审批」分组出现/消失（M3-03 锚点；前端已就绪，无 UI 改动）。
- 回归：M2-05 `interrupt_from_waiting_permission_settles_via_running` 语义不变；M2-10 零直通不变。
- 证据：任务证据含上述断言输出；Gate 3 出口按 R3 条款核验。

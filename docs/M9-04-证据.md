## 2. 实现摘要

### 2.1 命令清单（唯一事实来源）

- `crates/aether-app/src/ipc/dispatch.rs::COMMANDS`：**63 = 59 daemon + 4 shell**；
  `SHELL_COMMANDS = app_exit/app_restart/ref_pick/startup_pick_target`；
  `startup_get`/`startup_migrate` 保留在 63 内、`exposure=reserved`（UI 不暴露）。
- `scripts/ci/command-manifest.mjs`：解析 `COMMANDS`/`SHELL_COMMANDS`/handlers 的
  `parse_strict`/`parse_no_params`，并从 **ADR-029 §16.1** 解析 18 个分组（§4.6 唯一口径）。
  生成 `packages/protocol/src/command-manifest.json`（63 条：`index/name/route/exposure/group/params`）。
- debug 探针（`e2e_*`/`debug_*`/`test_*`）不进入清单（脚本硬校验）。

### 2.2 错误码与业务码

- `IpcErrorCode::ALL` 冻结 32 枚举（`as_str()` 仍是唯一线上来源）；
- `IpcError` 增加**非 `pub` + `serde(skip)`** 的 `business: Option<BusinessCode>`：
  不改变 M9-01 错误响应形状（`contract/responses.json` 的 `IpcError` 字段零变化）；
- `aetherd::map_ipc_error` 写入 `error.data.business_code`（`aether_code` 仍只取 32）；
- 真实命令路径已附加：`session_busy`（删除/改派/补选并发）、`session_paused`、
  `storage_backpressure`、`permission_not_pending`；4 个启动致命码由 M9-03 首帧承载。
  `memory_conflict` 的真实载体是适配器 `tool.call_failed.error.code`（M3-08），
  M9 无 memory 命令入口；本任务验证其 `business_code` 编码路径与常量集合，未改语义。

### 2.3 预算/cursor

- `crates/aether-app/src/ipc/cursor.rs`：
  `MAX_BYTES_MIN=64KiB`、`MAX_BYTES_DEFAULT=1MiB`、`MAX_BYTES_MAX=1.5MiB`；
  cursor = base64url（无填充）`{v,stream,pos,filter_hash}`；`fit_budget`/`fit_budget_tail`
  至少保留 1 条；单帧上限 2MiB；`filter_hash` = SHA-256 前 16 字节 hex。
- `messages_page`：`max_bytes` + `next_cursor`（仅 events 补读流，与 `last_seq` 互斥）；
  响应新增 `next_cursor`/`messages_has_more`；`last_seq`/`complete`/`readback_gap_too_large`
  语义不变（最近一页 `complete` 仍为 `true`）。
- `audit_query`：`max_bytes` + `next_cursor`（与 `offset` 互斥）；`has_more` 含预算截断；
  `next_cursor` 用 `offset + 返回行数` 续读；filter hash 覆盖过滤字段 + limit。
- 零推进：空页不返回游标；游标 `pos` 必须是已返回条目的最后位置（测试断言无重复/无空洞）。

   M9-08 用生成的 `types.ts`/`client.ts` 替换 70 处 `invoke`。

   无扩展名的 `pnpm`（Windows 下静默无输出），已修正为调用 `pnpm.exe`；
   `pnpm --version`、`pnpm verify:m9-04`、`pnpm verify:error-codes` 均已复跑通过。

## 1. 方法（照录 ADR-019 §2.2，不可改写）

| 项 | 定值 |
|---|---|
| 样本来源 | 抽查执行时最近的用户规则全集（不足 100 条取全集；执行窗口内新增规则全部纳入） |
| 样本量 | 100 条（不足则全集；>100 按创建时间倒序取前 100） |
| 判定流程 | 双人独立判定（执行人 1 = 实现维护者；执行人 2 = 独立评审）；分歧样本由第三人复核 |
| 误配定义 | ① 规则命中结果与档位矩阵/ADR-019 决策顺序不符（实现缺陷）；② 规则对**硬边界**产生放宽（严重误配）；③ 规则语义与用户登记意图不符（表达误配） |
| 计算 | 误配率 = 误配条数 / 样本量；**<5% 通过**；严重误配单条即触发降级 |
| 记录 | 原始抽样清单、双人判定表与计算脚本随 M6-02 证据归档，可复跑 |

## 2. 执行参数冻结（M6-02 定义；方法的可执行落地）

> 本节只把 §1 的方法落到可执行算子，不改判定口径；方法的判定集合互斥且穷尽：
> 「记录结论与规范重演不一致」= 实现缺陷；「记录结论与登记意图不一致」= 表达误配；
> 「硬边界被 allow 放宽」= 严重误配。

| 项 | 执行定义 |
|---|---|
| 判定 1（规范重演） | 依据 ADR-019 §2.1 决策顺序与附录 A-1 匹配口径，对样本规则 × 判定向量**独立重演**规范终局；不复用 `aether-security` 规则引擎实现（`m6_02_rule_safety.rs::judge`） |
| 判定 2（真实系统） | 真实 `PermissionService::request` 端到端执行（矩阵 → 规则 → 授权 → ask 审批流），终局与 `resolver`/审计逐例核对 |
| 第三人复核 | 判定 1 ≠ 判定 2，或系统终局 ≠ 登记意图时，逐条复核并以审计来源仲裁 → 落入误配三类（或确认为判定器缺陷并修复后重跑） |
| 判定环境隔离 | 单规则判定环境：逐样本仅加载该规则（`restore_rules_subset`，同源映射、fail-closed），避免宽匹配规则（`any`）污染其它样本的向量；**规则行不改写**（执行前后指纹一致断言） |
| 样本向量 | 每条样本 ≥1 条主向量（计入误配率）+ 可选边界向量（`any` 全匹配/路径后缀/命令词边界/主机标签边界/目录前缀边界），边界向量单独统计并同样断言 <5% |
| 主向量期望 | 由登记意图给出（allow / deny / ask）；`ask` 向量进入待审批并由抽查器以 `once` 收口，`asked` 观测与判定 1 一致 |
| 零直通 | 每例决策必须落 `permission.allowed_by_policy` / `permission.denied_by_policy` 审计并以 `request_id` 精确对照（M2-10 口径），缺失即违规 |
| 复跑 | `pnpm verify:m6-02` 可重复执行；`--evidence <dir>` 可对既有证据目录复核（独立复算误配率，与记录值一致才通过） |

## 3. 通过/失败判定与回退

- **通过**：误配率 <5% 且严重误配 = 0 且零直通违规 = 0；
- **失败**：误配率 ≥5% 或严重误配 ≥1 → 触发 P1 门禁回退动作（ADR-019 §6-2 / P1 计划 §6）：
  规则自动应用降级为「建议模式」（保留固定矩阵）、修复后重新抽查；**不得带过 M6-02/M8-03**；
- 预注册演练样本：语料内嵌入 1 条**已知表达误配**样本（URL 形态登记的主机规则）与 1 条对照样本，
  用于验证判定流程与案例分析产物的可执行性（演练样本的存在不改变通过阈值；发现机制失效即测试失败）。

## 4. 执行记录与变更纪律

- 本文档冻结于 M6-02 执行前；执行窗口参数（语料构成、样本快照、判定结果）随证据目录归档；
- 任何规则数据的修正（表达误配处置）走 `rules_*` 命令与审计留痕，**禁止静默修改规则数据**
  （执行前后 `rules_fingerprint.json` 指纹一致断言）；
- 抽查发现的实现缺陷（若存在）按「修复 → 归零复核 → 重跑抽查」闭环，修复记录与前后证据一并归档。

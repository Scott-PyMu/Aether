密钥路径实现边界（D10/ADR-010 决策 3）：

- `api_key` 明文**仅经本地 IPC 传输**；核心立即经 `aether-security::SecretStore` 写入
  `keychain://aether/provider/<id>`（A3 降级走加密文件）后丢弃；响应/落库只含 `api_key_ref`；
- keychain 条目删除**限自身命名空间**（`delete_own_key`：仅当既有引用等于自身 URI 才删除；
  共享/自定义引用不删；不可用/不存在忽略 + 诊断，不阻断命令）；
- 密钥存储启动选择（`boot_secret_store`）：OS 凭据库自检通过 → `KeyringStore`；否则读
  环境钩子 `AETHER_SECRETS_PASSPHRASE`（P0 无口令 UI；测试/演练专用，**登记于本证据**）
  挂载 A3 加密文件（`secrets.enc`，M1-07 口径）；两者皆不可用 → 密钥字段命令回 `internal`
  诊断错误且不落明文（ADR-010 §6-2 回退口径）；不带密钥的配置功能不受影响。

实现说明（ADR 未登记细微语义，按既有先例收敛并登记）：

- `provider_create`：`base_url` 缺省/空串 = 无（`None`）；`api_key` 缺省/空串 = 不写入。
- `provider_update`：`api_key` 三态按 ADR（缺省=不变 / 空串=清除 / 非空=覆盖）；
  `base_url` 同口径（缺省=不变 / 空串=清除 / 非空=设置）；`type` 不在 DTO 中
  （出现即 `unknown_field`，创建后不可改）。
- 生产组合根接线：`SessionBackend` 持有 `ProviderControl`（读连接池 + 单写队列 + 密钥存储）；
  存储就绪时注入，降级启动（无读/写句柄）时供应商命令回 `core_not_ready`（不伪造空清单）。

## 5. 已知事项与边界

1. **迁移 0003 不改写**：`providers`/`provider_models`/播种由 M3-09 期间按 ADR-010 附录 A
   冻结全文一次落地；M3-11 只做断言与消费（AGENTS §8）。
2. **运行期模型切换 / 适配器消费映射**（env 注入、路由）不在 P0（ADR-010 决策 3 边界），
   选择器仅作用于新建会话；会话内模型只读。
3. **`AETHER_SECRETS_PASSPHRASE`** 为 A3 降级口令的测试/演练环境钩子（P0 无口令 UI，
   ADR-010 §6-2 回退：不可用则密钥字段命令拒绝，不落明文）；生产正常路径不读取该变量
   （keyring 自检通过即返回）。
4. **并行任务**：本工作树同时承载 M3-10/M3-12 增量（如 `SessionWorkbench.tsx`、
   `bindings.ts` 为共享文件）；M3-11 验证入口运行的全量前端回归 148/148 通过
   （含 M3-10/M3-12 新增用例）。`cargo clippy -p aether-core` 的
   `clippy::absurd_extreme_comparisons` 命中属 M3-10 在途代码
   （`domain.rs::thinking_depth_in_range`），不在 M3-11 范围；M3-11 属主文件 clippy 0 告警
   （`cargo clippy -p aether-store -p aether-tauri --all-targets -- -D warnings`，
   仅以 `-A clippy::absurd_extreme_comparisons` 绕过上述外部命中时 Finished）。
5. **M4-04 复核项**（ADR-010 §5-10）：`providers_list` 响应 ≤1MiB（D7 单条上限）、
   `provider_create`/`provider_update` 请求 ≤64KiB（含 `api_key` 明文）——本任务未设显式
   护栏，字符串长度校验已限 `api_key` ≤8192 字符；实现后由 M4-04 基准复核。

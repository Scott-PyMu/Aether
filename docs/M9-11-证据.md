## 2. 包体审计与优化（ADR-030 D-030-1）

首轮 MSI 233,693,184 B 的构成（非残留代码）：

| 组成 | 原始大小 | 处理 |
|---|---|---|
| Electron 45 `Aether.exe` | 238.2 MiB | 必需（替代系统 WebView2） |
| 3×Bun 单文件适配器 | 3 × 92 MiB | **改为 1 个共享宿主** `aether-adapter-host.exe`（96.5 MiB）+ `--adapter` 分发 |
| `aetherd.exe` | 14.2 MiB | 必需 |
| `dxcompiler.dll`/`vk_swiftshader`/`d3dcompiler` | 24.6/5.2/4.5 MiB | Electron GPU/WebGPU 组件，删除有渲染风险，保留 |
| `LICENSES.chromium.html` | 5.4 MiB | 许可证合规必需，保留 |
| `default_app.asar` | 0.1 MiB | **afterPack 已移除（无用途）** |
| `locales` | 1.1 MiB | 已用 `electronLanguages=[en-US,zh-CN]` 裁剪 |

优化后：

```text
[package] 产物 Aether-0.1.0-x64.msi：160219136 bytes sha256=282365ec8fd10e4d574c85ba3c9e7355149e9b292cd4f5b77f71a3f282cd7cb6（体积 ≤ 硬阈值）
```

- 体积 **-73,474,048 B（-31.4%）**，保持冻结阈值 191,717,376 B 不放宽。
- 包内 runtime-bundle：`aether-adapter-host.exe` 96,560,128 B + `runtimes.json` + `digests.json`；
  `program` 同为宿主，`args=["--adapter", id]`（ADR-015 schema 支持 `args`）。
- 宿主源码 `packages/adapter-host`；单测 4/4（`--adapter` 解析/透传/缺参）；release 不含 Mock、test 含 Mock（ADR-008）。

## 3. 内存审计（ADR-030 D-030-2）

release 安装产物 idle 全树（8 进程，`Win32_Process.WorkingSetSize`）：

```text
Aether.exe（main）    112.6 MiB
Aether.exe（GPU）     137.6 MiB
Aether.exe（renderer） 59.4 MiB
Aether.exe（utility） 113.4 MiB
aetherd.exe            30.5 MiB
conhost.exe            19.0 MiB
aether-adapter-host    38.5 MiB（claude-code）
aether-adapter-host    38.9 MiB（codex）
合计                  524.41 MiB（549,883,904 B）
```

- 无泄漏/残留进程；Electron 进程模型 ~423 MiB 为框架基线（软件渲染环境），daemon ~31 MiB。
- 首窗实测在 0.47–1.27 s 间波动（冷启动/Defender 扫描安装产物），均 ≤1.5 s 硬阈值；G7 需在目标机复测稳定性。
- 77 MiB 为 **启动预热**的两个适配器（ADR-015/M2-08「启动矩阵：预热 enabled 运行时」）；DSH 因本机缺 `--dsh-bin` 预热失败，不占驻留内存。
- 已评估不可行/未采纳：删除 GPU DLL（渲染风险）、关闭预热（改变启动矩阵与首条消息时延）、适配器按需下载（破坏离线/供应链）。阈值按 ADR-030 调至 **600 MiB**（仍为硬阈值）。

## 5. 签名政策（DoD-2，ADR-030 D-030-3）

- **Windows（本机）**：无证书；electron-builder 日志 `no code signing certificate configured, signing is skipped`；
  `m9-11-build-manifest.json` 记录 `signing.unsigned_release=true`；SHA256SUMS 归档；
  `pnpm verify:signatures` 输出 unsigned 政策说明（**不声称已签名**）。发布说明须给 SmartScreen
  「更多信息 → 仍要运行」指引。该口径与 Proma 的 Windows 发布一致（Proma `release.yml` 的
  Windows job 未配置证书/签名，macOS job 使用 `MAC_CERTS`/`APPLE_*` secrets）。
- **macOS**：仍要求 Developer ID + hardened runtime + 公证 + `stapler`；`signatures.mjs` 已实现
  `codesign --verify --deep --strict`、`spctl`、Team ID 一致性、`stapler validate`；无 macOS 主机，未验证。
- 配置支持：`CSC_LINK`/`AETHER_WIN_CERT_FILE`（Windows，RFC3161 时间戳）；`CSC_NAME`/`AETHER_MAC_IDENTITY`；
  `AETHER_NOTARIZE=1`。获得证书后无需改代码即恢复严格校验。

## DoD2 EventStore：去重、乱序排序、last_seq 补读、缺口 >10k 提示与重载

**验证方式**：单测（10 项）+ 组件测试（3 项）+ 集成（1 项）。

**实现要点**（`apps/desktop/src/eventStore.ts`）：

- 去重：`evt.id` 与 `(session_id, seq)` 双键；`seq ≤ 水位` 的迟到事件按 seq 插入有序位置；
- 补读：缺口 ≤ `READBACK_GAP_LIMIT`（10 000，D4）时经注入的 `EventBackfillSource`
  以 `last_seq` 断点续传；`ReadbackGapTooLargeError`（`readback_gap_too_large`，与核心同码）
  或本地测得缺口 >10k → `historyTooLarge`；
- 提示与重载：`HistoryOverflowNotice` 显示「历史消息过多，请关闭并重新打开会话。」；
  用户确认后 `confirmReload` 清空当前会话缓存，`pageLatest(sessionId, reloadLimit)`
  加载最近 N 条（默认 500，可配置），水位重置为页内最大 seq——**不重启核心、不重启应用**；
- 批处理：`ingest` 仅入本地队列，16ms 合并发布（D8）；队列有界（默认 10 万条，超限丢弃
  并置 `gap`，丢弃只能由补读恢复，不由连续性"证明"恢复）。

**实际运行**（`pnpm --filter @aether/desktop test`）：

```
 ✓ src/eventStore.test.ts (10 tests) 194ms
 ✓ src/HistoryOverflowNotice.test.tsx (3 tests) 116ms
 ✓ src/eventStore.integration.test.tsx (2 tests) 337ms

 Test Files  10 passed (10)
      Tests  49 passed (49)
```

测试用例与断言（节选，源码可复核）：

| 用例 | 断言 |
|---|---|
| 去重 | 同 `id`、同 `(session, seq)` 重复注入 → 仅 1 条、水位 1 |
| 乱序排序 | seq 3→1→2 注入 → `[1,2,3]`、gap=false |
| last_seq 补读 | seq 1、4 注入 → gap=true → 补读 (lastSeq=1) 返回 2、3 → `[1,2,3,4]`、gap=false |
| 缺口 >10k | 本地缺口 10 001 → `historyTooLarge`、`backfill` 未被调用 |
| 确认重载 | `pageLatest` 以 500 调用；缓存清空后装载 `[901,902]`、水位 902、`reloadPending=false` |
| 可配置 | `reloadLimit: 200` → `pageLatest(…, 200)` |
| 16ms 批处理 | 15ms 内不发布；第 16ms 一次 flush（两条事件一次发布） |
| 本地有界 | 队列上限 4、注入 10 → 保留前 4、`gap=true`，`ingest` 不抛错 |
| 核心同码 | 补读源抛 `readback_gap_too_large` → `historyTooLarge` |
| 续读 | `complete=false` 单页不足 → 自动续读至收敛（≥2 次调用） |
| 重载失败 | `pageLatest` 抛错 → `reloadPending=false` + `error` 展示，不崩溃 |

组件测试（`HistoryOverflowNotice`）：

```
 ✓ 缺口 >10k 时显示「历史消息过多，请关闭并重新打开会话」
 ✓ 用户确认后清空缓存并加载最近 N 条；提示消失（不重启核心/应用）
 ✓ 补读通道未接线（M3-01 生产缺口）时展示结构化错误，不崩溃
```

## DoD3 压力：10 会话 × 50 delta/s 无重复渲染；gap=true 可补齐（集成）

**验证方式**：React 集成（fake timers 压缩 5s；真实 zustand 订阅 + DOM 断言）。

**实际运行**（同 `pnpm --filter @aether/desktop test`）：`eventStore.integration.test.tsx` 2/2 通过。

断言链：

- 10 会话 × 50 delta/s × 5s = 2 500 事件/会话；每会话 DOM `<li>` = 250、seq 唯一且严格 `1..250`；
- `data-gap=false`、`data-last-seq=250`；
- 渲染次数 ≤ 秒数 + 2（16ms 批处理，无逐事件重复渲染）；
- 缺口补齐用例：seq 1..5、8 注入 → `data-gap=true` → 补读 6、7 → `[1..8]` 无重复、
  `data-gap=false`、`data-last-seq=8`、补读以 `last_seq=5` 调用。

## DoD4 慢消费注入：不触发全局背压（reader 心跳正常）

**验证方式**：Rust 集成（桥接出口阻塞/落后注入）+ 核心侧既有 reader 心跳证据链（M2-04 DoD3）。

**实现要点**（`crates/aether-tauri/src/event_bridge.rs`）：

- `EventSink` 出口抽象（生产 = Tauri `emit`；测试 = 记录/阻塞替身）；
- `forward` 消费 `EventPipeline::subscribe()`（broadcast 4096）：慢消费只累计
  `lagged` 诊断并继续消费，**不阻塞管线、不反压 reader**（D8）；
- 生产接线 `spawn_app` 在核心启动完成后注入（`lib.rs::build_backend`）。

## 2. 常量级决策三处留痕（代码注释 / 证据 / 测试）

> 本节为**常量级决策**（AGENTS §3 MAY：常量与实现边界可自行决定，但必须记录），不需要 ADR。
> 每项遵循「三处留痕」：① 代码注释说明为什么；② 本节写清**反事实与边界**；
> ③ 测试固化行为。与 §3–§7 的「已知边界」分章，不混。

### 2.1 决策 ①：自定义有界增量读取器（替代 stock `LinesCodec`）

- **决策**：`crates/aether-adapters/src/framing.rs` 使用自定义 `AetherLineCodec`
  （实现 `tokio_util` 的 `Decoder/Encoder` 语义），不直接使用 `LinesCodec`。
- **反事实**：若沿用 `LinesCodec`（`max_length=2MiB`），它会先把整行缓冲到上限才判定；
  >2MiB 行会被完整读入内存一次后才报错，1–2MiB 声称 `artifact_ref` 的契约违约帧也会
  完整入内存；ADR-003 要求的「>1MiB 普通行立即断连 / 引用帧 <1MiB 契约」无法在
  缓冲过程中执行。测试 `stock_lines_codec_would_buffer_line_that_custom_reader_rejects`
  以同一 >2MiB 行证明 stock 会完整产出、自定义读取器立即报错。
- **边界**：自定义读取器保留 LinesCodec 的行语义（LF 分隔、容忍 CRLF、UTF-8 校验；
  空白行跳过），仅在「上限判定与引用帧探测」上不同；≤上限帧两者输出一致
  （`custom_reader_matches_lines_codec_for_normal_frames`）。
- **代码注释**：`framing.rs` 模块头「为什么自定义有界增量读取器」段落。
- **测试**：`custom_reader_matches_lines_codec_for_normal_frames`、
  `stock_lines_codec_would_buffer_line_that_custom_reader_rejects`
  （`cargo test -p aether-adapters --lib`）。

### 2.2 决策 ②：`READ_CHUNK_BYTES = 64KiB` 读块限流

- **决策**：读侧包一层 `ChunkLimitedReader`，单次 `poll_read` 最多填充 64KiB，
  连接层用它包裹 stdin/stdout（`connection.rs` spawn 处）。
- **反事实**：不限制读取块时，`FramedRead` 的 `BytesMut` 随 `reserve` 翻倍增长，
  Windows 匿名管道一次 `ReadFile` 可返回大块数据——M1-09 实现期实测一次返回
  **1,572,916 字节**（1.5MiB 整行），直接绕过「超限即停」策略；限流后缓冲上界
  固定为 `MAX_FRAME_BYTES + READ_CHUNK_BYTES`（2MiB + 64KiB），与 OS 行为无关。
- **边界**：64KiB 高于常见 4–64KiB 管道块，无额外往返开销；该值只影响单次读粒度，
  不改变帧语义。若未来实测吞吐受损，调参属常量级（须更新本节与测试）。
- **代码注释**：`READ_CHUNK_BYTES` 常量文档 + `ChunkLimitedReader` 文档。
- **测试**：`stock_lines_codec_would_buffer_line_that_custom_reader_rejects`（断言缓冲
  上界 ≤ `MAX_FRAME_BYTES + READ_CHUNK_BYTES`）、`default_limits_match_d6_constants`
  （固化常量值）、`chunk_limited_reader_caps_each_read_and_preserves_eof`。

### 2.3 决策 ③：`artifact_ref` 探测边界（误报 / 漏报）

- **决策**：以**行顶层** `"type":"artifact_ref"` 为判别键（前缀扫描，字符串整体消费、
  嵌套不命中）；≥1MiB 且命中 → 契约违约断连；探测在增量缓冲的每一轮执行。
- **反事实**：若改为「扫描整行再判定」或「只扫描前 1KiB」，前者破坏有界读取、
  后者会把判别键后置的引用帧误当普通行放行（M2-09 依赖该契约）。
- **边界（本决策最易被忽视的部分）**：
  1. **漏报侧**：判别键位于 1MiB 之后、2MiB 内的行，会在读到键的当轮被增量探测命中
     （`artifact_probe_detects_discriminator_late_in_line`）；>2MiB 位置则在命中前先以
     `LineTooLong` 断连（契约要求引用帧 <1MiB，此路径合规）。
  2. **误报侧（接受）**：普通 1–2MiB 行若在顶层携带 `"type":"artifact_ref"`，会被判
     契约违约并断连；内存上界仍为 2MiB+64KiB（`artifact_ref_claim_false_positive_is_memory_bounded`）。
     合法引用帧按契约远小于 1MiB，误报代价可接受；若未来出现真实误报，须走 ADR 调整
     判别键（不得静默放宽）。
  3. 嵌套（如 `params.type`）与字符串内文本不误报
     （`artifact_probe_only_matches_top_level_type`）。
- **代码注释**：`probe_artifact_ref` 文档「边界（常量级决策 ③）」段落。
- **测试**：上述三个单测均位于 `framing.rs`。

### 2.4 决策 ④：Mock 工具调用清单（权威定义，供 M2-02 / M2-10 复用）

- **决策**：触发文本与事件序列固定为下表；`packages/adapter-mock/src/scenarios.ts`
  与 `scripts/test/m1-09/fixtures/tool-call-scenarios.json` 双份维护，并由
  `scenarios.test.ts`、Rust 集成测试（读取同一 JSON）与 Node e2e 三方断言一致。
- **权威定义**（触发 = `session.send.text`；事件序列包裹在 `run.started` → 终态之间）：

  | # | 触发 | 事件序列（精确 type） | error.code | 预置决策 | 终态 |
  |---|---|---|---|---|---|
  | ① | `tool:normal` | `tool.call_started` → `tool.call_completed` | — | — | `run.completed` |
  | ② | `tool:fail` | `tool.call_started` → `tool.call_failed` | `tool_execution_failed` | — | `run.completed` |

## 3. 边界 B1：Mock ④⑤ 预置 ↔ M2-10 真实回环（双向留痕）

> **本边界为 M1 与 M2 的交接契约**：M1-09 的 ④⑤ 是**自包含预置**（Mock 侧直接产出），
> M2-10 才在真实回环中重放。双向落点：本节 + 实施计划 M2-10 对应关系表 + Mock 代码注释。

| M1-09 Mock ④⑤ 预置（本任务，不经网关） | M2-10 真实回环（对应关系） |
|---|---|
| Mock 自包含产出 `permission.requested` → `permission.resolved` → 工具终态 | 适配器发 `permission.request` 通知 → 核心网关落 `permissions` 表（pending）→ `permission.resolve` → 适配器发 `permission.resolved` |

| 边界断言：零通知（B3 运行时）、零存储写入（B3 静态） | 边界断言：审计、pending 决议、异常路径（M2-10 DoD2） |

  （M2 侧）；`packages/adapter-mock/src/scenarios.ts` / `mock-adapter.ts` ④⑤ 代码注释。
- **变更记录**：本边界落地时将 ④⑤ 从「发通知 + 等 `permission.resolve`」修订为
  「自包含预置」（原因是上线口径要求「Mock 侧直接产出」且 B3 需断言零网关副作用）；
  `permission.resolve` 处理器保留但返回 `{resolved:false}`，由 M2-10 在 mock-only 路径内

## 6. 边界 B4：`process.rs` 生命周期关键词静态检查

- **断言口径**：对 **M1-09 基线提交 `962de37`** 的 `process.rs`，扫描其
  **可执行代码**（剥离行注释与可嵌套块注释）后不得包含：
  `setsid`、`CREATE_NEW_PROCESS_GROUP`、`JobObject`、`TerminateJobObject`、`台账`、

    断言对象是「未实现」而非「未提及」。
- **当前树演化守护**：若当前工作树 `process.rs` 的可执行代码已含关键词，则必须存在
  M1-10 承接模块 `crates/aether-adapters/src/supervisor/mod.rs`，否则判失败。
- **实现**：`scripts/test/m1-09/verify-m1-09.mjs` 的 `checkBoundaryB4ProcessBaseline`

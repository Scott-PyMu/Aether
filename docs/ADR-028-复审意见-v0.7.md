## 5. 需修改者明确

1. **provider 为空时 `model_state`**：按“任一启用 provider 存在 → active，否则 invalid”还是“无法判断 → missing”？需 UI/架构确认。
2. **provider 失效 + model 失效的 UI 优先级**：只读、禁用所有补选，是否作为唯一入口？建议是。
3. **补选并发**：有在途 run 时补选是 `session_busy` 还是排队后执行？
4. **状态复制**：Codex/DSH 真实 CLI 冒烟是否可在 M7-10 环境执行；若 SKIP，证据如何说明不阻塞结论。
5. **M7-10 量级**：三运行时/状态复制/21 行 E2E 是否仍为 L；超出时按计划调整。

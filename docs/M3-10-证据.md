- **DSH 声明依据（2026-09-30 修订，原「不支持者不声明」判断作废）**：DSH 0.1.5-rc.2 的 ACP `session/new|resume` 响应携带 `configOptions`，其中 `reasoning_effort`（`category=thought_level`，`type=select`，含 provider 默认项 `""` 与具体 effort）即思考深度面；ACP 会话级设置方法 `session/set_config_option` 为该面的写入通道（`docs/spike/M1-11-接入笔记.md` §ACP 会话配置 + 夹具实测）。故按 ADR-010 决策 2「适配器以 capabilities 字符串项声明支持」声明 `thinking_depth`：**声明与接线同源**（无 `reasoning_effort` 广告面则无从设置、不得声明）；ADR-010 §6-3 回退路径不变（若该运行时失败率上升 → 移除声明，UI 由能力驱动自动置灰，协议字段保留）。
- **DSH 映射与既有两运行时的口径差异**：Claude Code / Codex 为**固定**常量映射（预算/原生档位），DSH 为**按模型广告值列表**的定位映射（不硬编码 effort 名称，避免与 provider/模型档位命名漂移冲突，如 `xhigh`/`max` 类扩展档）；n=1（仅一个具体 effort）时各档同落该值。曲线表以四档广告值为准登记如上。
- **DSH 覆盖回位（会话级有状态设置的语义补齐）**：`session/set_config_option` 与 Claude Code 的 spawn env、Codex 的 `-c` 参数不同——它**改写 ACP 会话自身的配置**，若覆盖后不回位会泄漏到后续 run（`runs.thinking_depth` 记录与实际推理档位不符）。故实现为：**每次 run 启动按「`session.send` 覆盖 ?? 会话级」重算生效值并应用**（`applyReasoning`；与上次生效值相同则跳过，不产生多余 ACP 调用），覆盖 run 之后的下一次 run 自动回位到会话级（自愈，不依赖运行结束回写，失败/cancel/崩溃路径同样成立）；覆盖**不写入** `session.thinkingDepth`（ADR-010「仅本次 run」）。
- **Claude Code / Codex / DSH 映射实现与测试**：`claude-adapter.test.ts`（会话级 4 → 32768；覆盖 0 → 0；未声明 → 不注入）、`codex-adapter.test.ts`（会话级 2 → medium；覆盖 0 → minimal；未声明 → CLI 默认 low）与 `dsh-adapter.test.ts`（能力声明 + `configOptions` 提取/比例映射纯函数；会话级 4 → `high` 且响应返回前完成；覆盖 0 → `minimal` 且**下一次 run 回位 `high`**、再下一次同值跳过 = 设置记录恰为 `high / minimal / high`；无档位会话不设置 → 0 条记录）经环境门控调用观测（`FAKE_CLAUDE_INVOCATION_FILE` / `FAKE_CODEX_INVOCATION_FILE` / `FAKE_DSH_CONFIG_FILE`，仅测试设置，不影响既有夹具行为）。
- **真机预算验收衔接**：预算/effort 数值为常量级映射，DSH 的比例曲线为按广告值的定位口径（ADR §6「映射表写入任务证据」；跨适配器统一口径须另立 ADR）；真实端点行为回归在 M4-05（真实运行时安装产物冒烟）承接，失败率若上升按 ADR-010 §6-3 移除声明。

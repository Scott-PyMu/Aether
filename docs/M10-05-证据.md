## 1. 实现范围

- **核心模型**（`crates/aether-core/src/attachments.rs`）：限额常量、MIME 白名单、魔数/文件头尺寸解析（PNG/JPEG/WebP/GIF）、`MessageAttachment` 线协议载荷、`content_parts` 引用、文件名清洗。
- **存储**（`migrations/0012_attachments.sql` + `aether-store`）：`attachments` 只存元数据与相对路径；`UNIQUE(session_id, sha256)` 幂等；`BeginRunIdempotent` 同事务绑定 `message_id`；`provider_models.capabilities` JSON 数组。
- **应用层**（`crates/aether-app/src/attachment.rs` + `session_backend.rs`）：内容寻址 `<data_dir>/attachments/<sha[0..2]>/<sha>.<ext>`；临时文件 + `sync_all` + rename 原子写；全局去重不覆盖；25MP/8192 前置检查；单文件 10 MiB、单消息 8、单会话 200/1 GiB；24h 孤儿扫描（启动）。
- **能力门**：三官方运行时 hello/静态表声明 `multimodal`；模型 `vision` 三态（允许/`vision=false` 拒绝/未知警告 `multimodal_model_unverified`）；未声明运行时 `session_send.attachments` → `attachment_type_unsupported`，不创建 run/消息。
- **重试/恢复**：`run_retry` 与暂停恢复从 `messages.content_parts` 重新水合附件（校验归属/文件/sha256/size/像素/限额，重新执行运行时+模型能力门），任一失败结构化拒绝，不静默降级为纯文本；`references` 仍按 ADR-024 不重放。
- **线协议**：`session.send.attachments` 只传 `{kind,path,mime,size_bytes,sha256,artifact_ref:true}` 引用帧（数据体不进 D6）。
- **UI**：`attachment-picker` / `attachment-item` / `attachment-preview` 锚点；粘贴/拖拽/文件选择；`data-state=uploading|ready|failed`；失败 `data-error-code` + 重试/删除；缩略图 `aether-attachment://thumb/<sha256>`；CSP `img-src` 增协议。
- **Electron**：`attachmentProtocol.ts` + `attachmentWorker.cjs`（UtilityProcess，并发 2/队列 16/单图 10s/崩溃重试 1 次）；native 依赖真实文件 staging + `files`/`asarUnpack`。

## 2. DoD 逐条

### DoD-1 采集：格式/大小/数量限额 + 结构化拒绝 + 不阻塞 UI

- 魔数白名单仅 `image/png|jpeg|webp|gif`；SVG/PDF/文本拒绝（核心 `sniff_image` + app `sniff_file`）。
- 单文件 10 MiB、单消息 8、单会话 200、总量 1 GiB、25MP/8192（构造解码器前检查）。
- 结构化业务码：`attachment_type_unsupported`/`attachment_too_large`/`attachment_limit_exceeded`。
- UI 上传中不锁输入框；发送入口在存在 uploading 条目时禁用并提示（不静默丢弃）。

验证：`cargo test -p aether-app --test m10_05_attachments`（5/5，含非法类型/超像素/超大文件）；`cargo test -p aether-core --lib attachments`（8/8）。

### DoD-2 存储：内容寻址/外置文件/原子写/清理/路径白名单

- `attachments` 表只存元数据；`storage_path` 相对 `data_dir`；同一内容全局去重；已存在不覆盖。
- 原子写：`.tmp` 临时文件 → `sync_all` → rename；失败清理临时文件。
- 删除：DB 行删除 + 无其他 DB 引用时清理文件；会话删除 `ON DELETE CASCADE`；启动扫描 >24h 孤儿（含 thumbs/.tmp）。
- 路径校验：canonicalize 后必须在 `<data_dir>/attachments/`；拒绝绝对路径/`..`/逃逸。

验证：`cargo test -p aether-store --test m10_05_attachments`（4/4：schema/幂等/用量/绑定回滚/删除路径）；`cargo test -p aether-app --test m10_05_attachments`（4/4：落盘/幂等/删除清理）；`cargo test -p aether-core --lib attachments`（`resolve`/cleanup 单测）。

### DoD-3 适配器能力：`multimodal` + 不静默丢弃 + DTO/线协议

- 三官方运行时能力表加 `multimodal`；核心静态表同步（`static_capabilities`）。
- `session_send.attachments`（≤8 ULID、去重、归属/存在校验）；`BeginRunIdempotent` 同事务绑定；`RunRequest.attachments` 透传执行器；`session.send.attachments` 引用帧。
- 模型 `vision`：允许；`vision=false` 拒绝；未知 → 响应 `warnings[].code=multimodal_model_unverified`。
- **重试/恢复重放**：`AttachmentReplayResolver` 从 `content_parts` 重新读取 `attachments` 行，校验会话归属、文件存在、sha256/size、像素/限额，并重新执行运行时 `multimodal` + 模型 `vision` 能力门；失败 `AttachmentRejected` → 对应业务码，不静默发送纯文本；暂停恢复失败时保持 `paused` 且标记保留。

验证：
- `cargo test -p aether-control --test m10_05_attachments`（3/3：`content_parts` 落库 + 附件绑定 + `RunRequest` 引用帧）。
- `cargo test -p aether-daemon --test m10_05_attachments`（1/1：mock 运行时未声明 multimodal → `attachment_type_unsupported`，`messages_page` 0 条）。
- `cargo test -p aether-app --test ipc_validation`（15/15：附件 DTO 严格校验矩阵）。

### DoD-4 UI：缩略图/预览/删除/重试/无障碍/E2E

- 锚点：`attachment-picker`（容器 + `data-count`/`data-enabled`/`data-warning`）、`attachment-item`（`data-attachment-id`/`data-kind="image"`/`data-state`/`data-error-code`）、`attachment-preview`（`aether-attachment://thumb/<sha256>`）。
- 删除/重试用 `data-action`，不新增 testid（UI-UX 锚点组保持 1 组 3 testid）。
- 粘贴/拖拽/文件选择；能力未声明时入口置灰并提示。
- 历史消息按 `attachment_list` 建立 `attachment_id→sha256` 索引后展示缩略图（renderer 不接收原图 Buffer）。
- 失败提示：按 `business_code` 映射友好文案（文件丢失/能力不支持/超限/数量超限），明确“本次操作未执行”；retry 附件失败显示在对应消息气泡“重试”按钮下方，以红色纯文本提醒（`.run-retry-error`，`data-error="attachment_replay"` + `data-business-code`，无关闭/恢复按钮），resume 失败显示全局 `workbench-error`（新增 `data-business-code`）；附件条失败项显示短提示。

验证：`pnpm --filter @aether/desktop test src/m10_05_attachments.test.tsx`（9/9：上传/发送/能力门/失败重试/删除/粘贴拖拽限额/历史缩略图）；全量 `pnpm --filter @aether/desktop test` 66 文件 406/406。

### DoD-5 安全：不执行内容/文件名清洗/密钥 0 命中/解码资源上限

- 不做 SVG/HTML/脚本渲染；解码只在 UtilityProcess（受限进程，非沙箱），25MP/8192；核心不整图解码。
- 文件名清洗去路径/控制字符/双向文本控制符，长度 ≤255；EXIF 不作可信信息；缩略图剥离元数据。
- 附件二进制不进入日志/诊断/导出；日志仅 `sha_prefix`/错误码；诊断指标只含数量/字节数。
- 用户消息渲染保留纯文本（不解析 Markdown）。

验证：`cargo test -p aether-core --lib attachments::tests::sanitize_name_strips_paths_controls_and_bidi`；`node scripts/test/m10-05/decode-spike.mjs` 的损坏文件/透明/EXIF 用例；静态扫描 `attachments/` 无 `api_key`/PEM 写入（见 §6）。

### DoD-6 性能/容量：10 MiB 附件、10 并发、内存有界、DB 增长受控

- DB 只增元数据（无 BLOB）；单会话 1 GiB 上限。

## 7. 已知边界

- renderer 前置校验仅提示；权威判定在核心（魔数/像素/限额）。
- UtilityProcess 是**受限进程，非沙箱**（ADR-035 D-035-4 明示）。
- 附件发送引用帧为信任级边界：适配器按 canonical 路径读取（同 artifacts）。
- **重试/恢复**：已实现完整重放（文本 + 附件），并重新能力门/文件校验；`references` 仍按 ADR-024 不重放（内存态，首次发送后不落库）。

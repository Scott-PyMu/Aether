## 4. 25MP 内存基准与并发策略（Windows x64，Node 24，单进程）

| 场景 | 基线 RSS | 峰值 RSS | 增量 | 耗时 |
|---|---:|---:|---:|---:|
| 单图 25MP：PNG 解码 + 512px WebP | 182,964,224 B（174.5 MiB） | 428,584,960 B（408.7 MiB） | **245,620,736 B（234.2 MiB）** | 351 ms |
| 两并发 25MP | 287,428,608 B（274.1 MiB） | 780,034,048 B（743.9 MiB） | **492,605,440 B（469.8 MiB）** | 374 ms |

- ADR-035 §D-035-6 的估算为“2 并发约 380MiB”；本机实测 **469.8MiB**，高于估算约 24%。
- **并发策略（常量级调参，已写入 `decode-spike.mjs`）**：默认 **2**；大图 `pixels >= 20,000,000` 且机器总内存 **<8 GiB** → **1**。本机总内存 16 GiB，25MP 选择 2；合成低内存（4 GiB）25MP 选择 1、8MP 选择 2，均通过。
- M10-05 worker 仍按默认 2、队列 16、单图 10s、per-process 内存上限落地；低内存机器按上述策略降为 1，不改变 ADR 阈值。
- 峰值包含 PNG 输入缓冲（4.27MB 压缩、100MB 解码后 RGBA）与 WebP 编码；不同格式/图片内容会有差异，CI 需按同一夹具复测。

## 5. Electron / 打包 spike

### 5.1 已通过

- **Windows MSI 构建**：`AetherDecodeSpike 0.0.0.msi`，403,025,920 B，sha256 `b29f79dce73ea60861251af8632634db1f60eb94d92818b26b81b16fe44088a0`（最小 spike 应用 + `compression: store`，不代表生产包体；生产体积仍以 M9-11 阈值为准）。
- **asarUnpack**：`@napi-rs/image` 与 `@napi-rs/image-win32-x64-msvc` 均在 `app.asar.unpacked/node_modules/`；asar 内 `.node` 条目全部 `unpacked=true`。win32-x64 `.node` 为 **28,246,016 B**（约 27MiB）。
- **生产包体积实测（临时实验，已还原配置）**：把 native 依赖以**真实文件** staging 到 `apps/desktop/native-runtime/**` 并加入 `files`/`asarUnpack` 后，生产 MSI 为 **166,260,736 B**（158.6 MiB），较当前 `160,215,040 B` 增加 **6,045,696 B（约 5.8 MiB）**；MSI 压缩后 native 增量远小于未压缩 `.node`。
  - M9-01/G6 上限 `191,717,376 B`（1.5× HEAD）与绝对上限 `471,859,200 B`（450MiB）**均通过**；余量约 **24.3 MiB / 13.3%**。
  - 结论：**当前不需要修改 G6/G7 体积门禁**；M10-05 按真实文件 staging 后复测即可。若后续再引入其他 native 依赖导致超限，再走 ADR 调阈值，不得静默改 `thresholds.json`。
- **Electron Node ABI**：`ELECTRON_RUN_AS_NODE=1` 下由 unpacked 路径加载 N-API，Electron 45.0.0 / Node 24.22.0，成功生成 8×6 WebP。
- **打包配置结论**：生产 `apps/desktop/electron-builder.config.mjs` 当前只打包 `apps/desktop/dist`、`electron/dist`、`package.json`，**未包含** native 包；M10-05 必须：
  - 先把 `@napi-rs/image` + 当前平台 `image-*` 可选包 + `omggif` 以**真实文件** staging（例如 `apps/desktop/native-runtime/**`；实测 `apps/desktop/node_modules/@napi-rs/**` 的 pnpm junction 不会被 `files` glob 收录，asar 仍为 17 项）；
  - `files` 加 `apps/desktop/native-runtime/**/*`；`asarUnpack` 加 `apps/desktop/native-runtime/**`；
  - 只包含**当前平台**的 native 可选包，禁止把全部 `@napi-rs/image-*` 平台包打入；
  - main 侧不要用 Vite 打包 native `.node`（保持 external/运行时 require）。

### 5.2 Windows UtilityProcess：通过

- 首次直接启动打包应用时，Electron GUI 初始化崩溃（`2147483651` / WER `0xC0000005`）；用最小 Electron 应用复现后确认是**默认/损坏的 Electron user-data 目录**导致，不是 spike 代码或 `@napi-rs/image` 问题。
- 使用**全新 `--user-data-dir`**（并加 `--no-sandbox --disable-gpu`）后，打包应用 `AetherDecodeSpike.exe --spike` 通过：
  - `utility_process.status=pass`；worker `app_root_is_asar=true`、`is_packaged=true`；
  - `native_package=image-win32-x64-msvc`、`native_node_exists=true`（Electron 的 asar 逻辑路径指向 `app.asar`，物理文件在 `app.asar.unpacked`，§5.1 的磁盘断言已通过）；
  - 四格式 PNG/JPEG/WebP/GIF 全部生成 WebP；25MP 上限允许、25MP+1 与最长边 8193 拒绝。
- 复跑命令：

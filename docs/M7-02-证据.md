**设计驱动更新（P0 断言，留痕）**：`crates/aether-control/tests/m2_05_cancel.rs` 的 20 会话取消风暴用例——并发闸门生效（16GB → 上限 10）后 10 个 run 立即派发、10 个进入全局 FIFO；断言改为闸门口径（派发数=10、`gate.active/queued` 快照、dispose 全清 FIFO、已派发 run 全部取消），用例语义（20 会话并发 dispose + 取消级联零遗漏）不变。驱动来源：ADR-022（已批准）；测试入口显式注入 `FixedFreeRam::new(16.0)`。

**ADR-022 附录 A-6 合成顺序实现口径（单写者）**：run 终态 → 释放槽位 → 全局 FIFO 按序推进队首（仅新 run 准入可行时）→ 等待槽 run 提升判定（有空槽 → 派发；饱和 → FIFO 尾部；降级 → 不派发不排队，由收口方连带取消）。`queued` run 被 interrupt：从 FIFO 移除 + 取消；等待槽**不**连带清空（A-6 行 3），随后按闸门判定提升（饱和 → FIFO 尾部）。

### DoD3 并发闸门（参数注入/超限排队 + UI 队列位置/不超卖）

- 参数注入（8GB 模拟）：`refresh_gate_limit() == Some(4)`（`clamp(floor(7/1.5),2,10)=4`）——`m7_02_gate` 与 `gate` 单测断言。
- 排队与响应：6 会话 1 run/会话 → 前 4 立即派发；第 5/6 ack 携 `queue:{position:1,limit:4}` / `{position:2,limit:4}`；`executor.call_count()==4`（不超卖）。
- health：`health.concurrency_gate == {"limit":4,"active":4,"queued":2}`（`backend.health()` 真实报告）。
- FIFO 推进：放行 run#1 → 队首（第 5 个 run）派发（`run_ids()[4]` 逐字比对）；`active==4`、`queued==1`。
- A-6 矩阵（`waiting_slot_and_queued_interrupt_follow_a6_matrix`）：`running` 时再发 → 等待槽（无 `queue` 字段）；第 3 条 → `session_busy`；queued run interrupt → `cancelled_waiting_run == None`（等待槽不连带清空）、a2 晋升（饱和 → FIFO 尾部）、FIFO 顺序 B 先于 A；dispose 全清（`dispose_clears_queued_runs_and_fifo`：排队 run 与提升残余 run 均 `cancelled`、FIFO 归零）；`run_retry` 受限（`run_retry_respects_gate`：重放 run 入 FIFO、队首推进）。
- UI 队列位置（jsdom E2E 级）：`apps/desktop/src/m7_02_queue_position.test.tsx`——

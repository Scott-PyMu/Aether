## 2. 实现

### 2.1 权限回环（daemon 业务层，D9）

- 复用 M3-08 的生产装配：`AdapterRunExecutor` → `PermissionServiceGate` → `PermissionService`
  （策略矩阵 / 审批持久化 / 300s 超时 / 审计）；M9-06 不新增第二条决议路径。
- **取消树接线（补齐 M2-05 设计口径）**：
  - `AdapterRunExecutor` 登记「核心会话 → 在途 run 取消令牌」（`CancelTokenGuard`，run 结束摘除）；
  - `SessionMappingGate`（适配器会话 id → 核心会话 id）把令牌传入
    `PermissionServiceGate::decide_with_cancel`；
  - `PermissionService::request_cancellable` 命中取消树时按 deny 收口：
    `permission.resolved(deny)` + 审计 `permission.cancelled` + 唤醒回环 →
    适配器收到 `permission.resolve(deny)`。
  - 效果：`session_interrupt` / `session_pause` / `dispose` 不再遗留最长 300s 的待审批票据；
    决议仍只经 `permission_resolve`（UI 路径不变）。
- 300s 超时、allow/deny、零直通探针（`executor.permission_loop_stats().zero_passthrough`）保持原语义。

### 2.2 `permission.pending` 通知（DoD-5）

- `crates/aether-app/src/permission_notice.rs`（新增，transport-agnostic）：
  - 只订阅**落盘后**广播中的 `permission.requested` / `permission.resolved`
    （附录 B 现有类型，不新增事件类型）；
  - 每次重算 `permissions_pending` 计数（唯一事实源），发出 `{count, session_id?}`；
  - 广播 lag → 立即补发一次全局计数；计数/出口失败只计数，不 panic、不影响轮询/决议；
  - 关闭预算 250ms（仅提示通道；远小于事件桥 2s，不挤占 T11 退出预算），**先于**事件桥停止。
- `crates/aether-daemon/src/serve.rs`：
  - 管线可用后启动通知桥（与 M9-05 事件桥同一 `spawn_warm` 装配）；
  - `permission.pending` 走唯一 stdout JSONL 出口（无 `id`，不携带决议字段）。
- 前端：`permission.pending` 只是刷新提示；`apps/desktop/src/permission.ts` 仍只调用
  `permissions_pending` / `permission_resolve`（静态检查见 §3.7）。

### 2.3 壳本地选择器（DoD-3）

- `apps/desktop/electron/localCommands.ts`（新增，无 Electron 依赖）：
  - `ref_pick`：`{kind:"file"|"directory"}` 严格解析 → `dialog.showOpenDialog` →
    `fs.realpathSync.native` canonical 路径 → `{path}`；取消 → `{path:null}`；
  - `startup_pick_target`：无参数（`null`/`{}` 等价）→ **通用目录选择器** →
    `{target_dir}`；M9 仅不用于启动迁移；
  - 参数错误与 `aether-app` 同码（`unknown_field`/`missing_field`/`invalid_type`/
    `invalid_enum`/`invalid_json`）；不可 canonicalize/相对路径 → `path_rejected`；
  - 路径仍由 daemon 在 `artifact_add` 等命令复核（选择器不构成信任）。
  - M9-07 在 main 注入真实 `dialog` 实现（本任务不创建窗口）。

### 2.4 `dialog.pick` 仅协议预留（DoD-4）

- `crates/aether-rpc/src/server_request.rs`（新增，叶子设施）：
  - `ServerRequest` / `DialogPickParams` / `DialogPickResult` 严格形状；
  - `PendingServerRequests`：`register` / `take_response` / `expire` / `cancel`，
    默认 300s、对话框 120s；超时/取消后的响应按 id 丢弃并计数（有界退休窗口）；
  - **不接产品路径**：`ref_pick`/`startup_pick_target` 固定壳本地，59/4 不变；
    `aether-app`/`aether-daemon`/renderer 对 `dialog.pick` 0 引用（`pnpm verify:m9-06` 静态断言）。
- fixture：`scripts/test/m9-06/fixtures/dialog-pick.json`（正常/取消/超时/迟到/非法形状）。

### 2.5 未改动面

- 63 命令（59 daemon + 4 shell）、`IpcErrorCode` 32 枚举、9 业务码、EventEnvelope 9 字段、
  附录 B 23 事件类型、迁移 0001–0009、`packages/protocol` 生成物均未修改。
- `aether-control` 核心语义未改写；取消路径复用既有 `request_cancellable`

## 4. 已知边界 / 未验证

1. **macOS/Linux**：本机仅 Windows x64；权限/通知/选择器代码无平台分支（路径 canonicalize
   由 `fs.realpathSync.native` 平台实现）。macOS/Linux 进程级运行由 **M9-13** 平台矩阵覆盖。
2. **进程级适配器 E2E 的边界**：`aetherd` 的运行时注册清单要求构建期摘要（ADR-015），
   测试二进制无法注入 Bun Mock 适配器；因此 DoD-1 的适配器回环 E2E 在
   **daemon 业务层**（`aether-app` 的 `IpcState::dispatch` + 真实监督器/适配器进程/权限服务，
   与 `boot::build_backend` 同一装配）执行；**JSON-RPC 进程级**的权限命令与
   `permission.pending` 通知由 `m9_06_permission_pending` 与 M9-04 路由矩阵覆盖。
3. **`m3_08_memory` 既有失败**：本机运行 `cargo test -p aether-tauri --test m3_08_memory`
   为 2 passed / 5 failed（记忆工具真实原子写未生效）。已用 `git checkout HEAD --`
   回退本任务改动的两个文件后复跑，**同样 2/5 失败**，确认与本任务无关（既有环境/夹具问题）；
   不影响 M9-06 的权限回环/选择器/通知结论。该失败需在 M9-13 前另行定位。
4. **M9-07 接线**：真实 `dialog.showOpenDialog` / preload 白名单 / 窗口安全基线属 M9-07；
   本任务只交付无 Electron 依赖的壳本地处理模块与测试。
5. **`permission.pending` 消费方**：M9-06 只交付通知与计数语义（ADR-029 §16.4 登记）；
   renderer 是否用通知做即时刷新由 M9-07/M9-08 接线；本任务保证轮询/决议路径不变。
6. **并行工作区**：本机工作区同时存在 M9-07 未提交改动（`apps/desktop/electron/shellLocal.ts`
   等）；M9-06 未修改这些文件。M9-07 的壳本地命令与 M9-06 `localCommands.ts` 的选择器
   语义重叠，建议在 M9-07 合并前收敛（见 §3.4 协调项）。

## 1. P0（必须修正后才能签署）

### P0-1 首启“数据目录为空”判定与现有 `logs/` 等目录冲突

**问题：**  
D-039-1 §1 与 D-039-6 规定：

- “数据目录为空 → 新装初始化；除此之外 `CURRENT` 缺失/损坏 → 拒绝启动。”
- 旧扁平布局 `<data_dir>/aether.db` 且无 `CURRENT` 也拒绝。

但 Electron main 在 spawn daemon 前就创建 `<data_dir>/logs/shell.log`：

- `apps/desktop/electron/shellLog.ts:66`：`mkdirSync(logDirFor(options.dataDir), { recursive: true })`；
- `apps/desktop/electron/app.ts:253`：启动即 `createShellLogger({ dataDir: initialDataDir.dataDir })`；
- `apps/desktop/electron/dataDir.ts:159`：`<data_dir>/logs`；
- `backups/`、`attachments/`、`staging/`、`run/` 也可能先于 DB 存在。

因此**真正首启时数据目录并不是“空”的**，而是至少含 `logs/`；按 v0.3 文本，`CURRENT` 缺失 → 拒绝启动。这会直接阻断新装首次启动。

**依据：**  
D-039-1 §1；D-039-6 “数据目录为空/旧布局检测”；`apps/desktop/electron/shellLog.ts`、`app.ts`、`dataDir.ts`；M9-07 启动路径。

**风险：**  
新装首次启动失败（S-12），用户无法进入应用；测试/真实安装都会复现；属于 P0 启动阻断。

**建议：**  
把“数据目录为空”改为**“DB 布局为空”**：

- 新装条件：不存在 `<data_dir>/aether.db`、`<data_dir>/CURRENT`、`<data_dir>/generations/*`；忽略 `logs/`、`backups/`、`attachments/`、`staging/`、`run/`。
- 旧布局/损坏条件：存在任一 DB 布局工件但 `CURRENT` 缺失/损坏 → 拒绝启动（保持 fail-closed）。
- 增加 fresh `userData` 测试：预先创建 `logs/`（模拟 Electron 日志）仍能初始化；只存在 `logs/` 不得触发 S-12。
- 在 D-039-6/附录 A 固化“DB 布局工件”清单。

## 2. P1（高风险，需在 v0.4/实施前闭环）

### P1-1 `backup_restore` 外部路径校验仍只接受 `.db`/`.aebk` 文件

**问题：**  
D-039-5 §4 冻结的新语义是：

- `backup_restore.source.external.path` = **包含 `manifest.json` 的目录**，或 **`manifest.json` 文件路径**；
- 开发阶段**不接受**旧单文件 `.db`/`.aebk` 路径。

但现有实现/契约仍是：

- `crates/aether-app/src/ipc/dto.rs:1440-1448`：`BackupSource::External` 文档写“外部 `.db` 路径”；
- `dto.rs:1463-1469` / `1492-1494`：`canonical_external_path()` / `validate()` 调用 `validate_external_backup_candidate`；
- `crates/aether-app/src/ipc/path.rs:62-83`：只接受**文件**且后缀为 `.db`/`.aebk`，明确拒绝目录。

因此 v0.3 的“请求不变”只改了 DTO 字段，**没有覆盖路径校验语义**；新整套恢复路径（目录/manifest.json）会在 `validate()` 阶段被拒绝，旧 `.db` 反而仍能通过路径校验。

**依据：**  
D-039-5 §4；`crates/aether-app/src/ipc/dto.rs`；`crates/aether-app/src/ipc/path.rs`；M9-01/D7 `backup_restore`。

**风险：**  
M10-09 无法实现新整套恢复；旧 `.db` 可能进入后端校验；契约与测试不一致；M9-01 重录范围遗漏。

**建议：**  
v0.4/实施前明确并落地：

- 新增 `validate_external_backup_set`（目录或 `manifest.json` 文件）或在 `BackupSource::External` 上区分 `SetPath`/`ManifestPath`；更新 DTO 文档与 `CommandRequest::validate`。
- 后端显式拒绝旧 `.db`/`.aebk`：`invalid_value` + 消息含 `backup_candidate_invalid`；不得只靠路径后缀。
- 增加测试：目录、manifest.json、旧 `.db`、旧 `.aebk`、不存在路径、非备份目录；写入 M10-09 DoD 与 M9-01 重录。

### P1-2 旧 generation 保留策略缺省值/空间告警未定义

**问题：**  
D-039-8 §1 规定“旧 generation 至少保留最近一份，不自动删除；清理须用户确认/维护任务”。每次恢复/导入都会生成一个完整的约 5.22 GiB `.pre-*` generation；重复操作会累积多份，且没有默认清理、容量告警或磁盘预算。ADR-020 的备份保留只覆盖备份集，不覆盖 generation。

**依据：**  
D-039-8 §1；D-039-5 备份/恢复；D-039-4 容量口径；ADR-020 保留策略。

**风险：**  
磁盘被旧 generation 填满；后续备份/恢复/写入失败；用户不知道哪些可删；与“本地优先、可恢复”目标冲突。

**建议：**  
v0.4 给定缺省策略（不新增设置键，使用内部常量）：

- 成功后保留最近 **1** 份旧 generation；更早的 `.pre-*` 在启动成功/备份成功后自动清理（或标记可清理）。
- 保留当前 generation 与最近一份旧 generation；不得删除 `CURRENT` 指向的 generation。
- 容量巡检加入 generation 总量；超过阈值（如主库+分片+旧 generation > 1.5× live）告警；诊断包列出各 generation。
- 故障注入：清理中断不得破坏当前 generation；证据记录清理前后磁盘。

### P1-3 `CURRENT.generation`/`shards.json.path`/manifest 路径缺少目录约束

**问题：**  
D-039-8 使用 `CURRENT.generation` 拼接 `generations/<generation>`，`shards.json` 记录 `shards[].path`，备份 manifest 记录相对路径；但 v0.3 没有明确：

- `generation` 必须是 `gen-<ULID>` 且只能落在 `<data_dir>/generations/`；
- `shards.json` 的 `path` 必须是 generation 内相对路径，禁止绝对路径/`..`；
- 备份 manifest 的 `path` 必须是备份集内相对路径，禁止 `..`/绝对路径；
- 符号链接/重解析点是否拒绝。

本地用户可以编辑这些 JSON；损坏/恶意文件可能让 daemon 打开或复制数据目录外的 DB，属于数据完整性/安全边界问题。

**依据：**  
D-039-1 §1（`CURRENT`/`shards.json`）；D-039-8 §1（generation/journal）；D-039-5 §3（manifest 相对路径）；AGENTS §2.7（路径 canonicalize 后前缀比较）。

**风险：**  
打开/恢复/备份数据目录外的文件；数据泄露或覆盖；损坏的 `CURRENT` 导致意外路径；与 D9 路径校验口径不一致。

**建议：**  
v0.4 明确并在 M10-09 证据中断言：

- `generation` 正则 `^gen-[0-9A-Z]{26}$`；`canonicalize` 后必须前缀匹配 `<data_dir>/generations/`；拒绝 symlink/junction（或解析后仍在根内）。
- `shards.json` 的 `path` 只允许相对路径，禁止绝对路径、`..`、空段；解析后必须在 generation 内。
- `manifest.json` 的 `path` 同样相对、无 `..`；恢复复制前 canonicalize + 前缀校验。
- 失败映射到 `db_open_failed`/`backup_candidate_invalid`；加入故障注入（`../`、绝对路径、symlink）。

## 4. 修改者 v0.4 清单

### 4.1 必须改

1. **P0-1**：把“数据目录为空”改为“DB 布局为空”；忽略 `logs/`/`backups/`/`attachments/`/`staging/`/`run/`；补 fresh userData（含 logs）首启测试；更新 D-039-1/D-039-6/附录 A。
2. **P1-1**：落地 `backup_restore` 外部路径校验（目录/manifest.json），旧 `.db`/`.aebk` 显式拒绝；更新 DTO/`path.rs`/D7/M9-01 测试；写入 M10-09 DoD。
3. **P1-2**：定义旧 generation 缺省保留（1 份）+ 自动清理/容量告警；不新增设置键；更新 D-039-8/附录 A/诊断包；故障注入。
4. **P1-3**：为 `CURRENT.generation`/`shards.json.path`/manifest path 增加 canonicalize + 前缀约束 + symlink 拒绝；补故障注入；更新 D-039-1/D-039-5/D-039-8。
5. **P2-1～P2-5**：按 §3 修正/补测试。

### 4.2 不需要改

- A 方向、N=8/1.5 GiB、单写任务 + 每片连接、无数据迁移、严格 sidecar、1.5s 三指标、两阶段清理、`health.storage_check`/`maintenance`、`backup_*` 字段冻结、D-039-8 tombstone/generation/journal、M10-09/10/11 任务划分与四角色签核：均保持。
- M10-08 不重开；0001–0013 不改；0014 只新增。

### 4.3 签署条件

- P0-1 闭环；
- P1-1/P1-2/P1-3 有可执行修正与测试/证据；
- P2 项至少修正表述或登记为 M10-09 DoD；
- 四角色（架构/安全/QA/产品）签核。

## 1. 总体评价

**文档完整性：良好。**  
v0.4 已形成“背景/证据 → 唯一决策 A → 分片/写模型/读路由 → 启动检查/1.5s 预算 → 保留清理/收缩 → health/维护态 → 无迁移初始化/错误映射 → 跨库维护协议 → 影响/风险/回退 → 任务/DoD/验收矩阵 → 四角色签核”的完整闭环；关键契约（命令/事件/设置键/迁移/业务码/`health`/`backup_*`）均有登记。

**一致性：良好。**  
- A 方向唯一，§5 仅保留已否决备选；  
- 5.35×/3.76× 口径已区分，产品统一 3.76×；  
- `storage_state`（降级）与 `storage_check.write_gate`（启动准入）分维，D4/UI 单一口径已写清；  
- `backup_*` 契约、外部路径校验、旧 `.db` 拒绝、旧 `single_file` UI 禁用已冻结；  
- generation/`CURRENT`/journal/旧 generation 清理/路径约束/错误映射/故障注入已闭环；  
- 命令 87/事件 0/设置键 11/迁移 0014/业务码 35 与 M10-07/M10-06 基线一致。

**最大风险（实施期，不再是文本缺口）：**  
1. `initialize ≤1.5s` 与 9 个 DB 打开/迁移的真实 release 表现，必须由 M10-10 复测；若达不到，按 AGENTS §7 报告，不得改回 2s/8s。  
2. `sidecar` 跳过 `quick_check` 的页级漏检残余风险，需安全/QA 签核接受；故障注入失败即回退每次阻塞检查。  
3. 跨库导入/删除/恢复的 journal/`CURRENT` 切换是数据完整性关键路径，必须用故障注入证明“无半套、无孤儿事件、无可见空会话”。

**安全专项：** 未发现“把权限控制误述为沙箱”；不新增外部信任边界/命令面/第三方依赖；路径约束（generation 正则、前缀、symlink/junction 拒绝）已覆盖；密钥/审计/备份 manifest 脱敏要求保留。主要安全/数据风险仍是完整性检查绕过与跨库切换原子性，已由 sidecar/并行检查/journal/整套回滚/故障注入控制。

## 3. P2（不阻塞文本通过，随 v1.35/M10-09 处理）

| 编号 | 问题 | 依据 | 建议 |
|---|---|---|---|
| P2-1 | `backup_restore` staging 空间预检未明确；staging 需要复制整套 generation，空间不足时可能到复制阶段才失败 | D-039-5 §5；D-039-8 §1 | 恢复前预检 `<data_dir>/staging` 可用空间 ≥ 备份 generation 大小 ×1.1；不足则拒绝并保留当前库；写入 M10-09 DoD |
| P2-2 | `.failed-*` generation 未纳入旧 generation 清理/诊断列表；恢复失败后可能累积 | D-039-8 §1；清理仅写 `.pre-*` | 将 `.failed-*` 纳入安全清理/诊断（保留最近 1 份或标记可删）；不得删除当前/被 journal 引用的 generation |
| P2-3 | `archive_export` 对 `deletion_pending=1` 会话的处理未明确；`session_export` 已隐藏，但全库归档可能仍包含 pending | D-039-8 §2；ADR-021 归档 | 明确 `archive_export` 排除 pending 会话或标记 `pending_deletion`；加测试，避免“已请求删除”数据被导出 |
| P2-4 | 首启初始化在“已创建 `generations/`、未写 `CURRENT` 即崩溃”时只能 fail-closed 拒绝；无恢复提示/清理入口 | D-039-6；附录 A | 在 S-12 文案/诊断中提示“删除半成品 generation 或重建数据目录”；可选：启动检测“无 CURRENT + 单 generation + 无 journal”时提供安全清理（需独立判断，不自动切换）；不阻塞本 ADR |

> P2 项均不改变 A 方向、契约计数、验收阈值；可在设计 v1.35/P2 v0.14 或 M10-09 证据中处理。

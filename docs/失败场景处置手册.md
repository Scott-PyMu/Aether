# 失败场景处置手册（P0，30 场景）

> 与《实施计划与验收标准》§6 覆盖矩阵一一对应。每场景给出：**症状 → 系统自动应对 →
> 你的操作**。自动应对均有演练证据（`scripts/test/.gitignore` 外的归档见
> `docs/M4-01-证据.md` / `docs/M4-02-证据.md` / `docs/M4-03-证据.md`）。
> 原则：先看自动应对是否已恢复；需要人工介入时按「你的操作」执行；不要手工改数据库。

## 进程类（D2/D5；演练 M4-01）

| # | 场景 | 症状 | 系统自动应对 | 你的操作 |
|---|---|---|---|---|
| 1 | 任务 panic | 单个会话流中断，出现「运行失败」 | 隔离该会话任务并标记 failed，其余会话不受影响 | 点消息旁「重试」（Mode R 原生恢复 / Mode N 重放输入） |
| 2 | 核心 OOM | 应用变慢/退出 | RSS 巡检告警 → delta 限流；重启后从 WAL 恢复 | 释放内存后重启应用；用诊断包确认 `core_rss_alert/throttle` |
| 3 | 退出卡死 | 关应用长时间不退 | 关闭序列硬超时逐级强杀（≤10s） | 无（保证能退出）；下次启动自动孤儿清理 |
| 4 | UI 侧卡顿 | 界面卡、事件延迟 | 帧级批处理；15s 无 health 提示「核心未响应」 | 按提示重启 UI；数据不受影响（断点补读） |
| 13 | 启动即崩 | 运行时不可用，显示原因 | 抓 stderr 尾 50 行 → `disabled + start_failed` | 修复运行时配置后点「重试」 |
| 14 | 非官方适配器 | 运行时被拒 | 拒绝加载 `untrusted` + 审计 | 无（P3 前不支持第三方；不得手工放置二进制） |
| 15 | 运行中崩溃 | 在途回答中断 | 30s 内自动 Ready；在途 run 标 failed 可重试 | 点「重试」继续（原生恢复或重放） |
| 16 | 卡死无响应 | 适配器不再响应 | 10s 心跳 ×3 次失败（≤45s）→ 自动重启，120s 内 Ready | 无（自愈）；长时间未恢复则重启应用 |
| 17 | 孤儿进程 | 重启后旧适配器仍在 | 启动清理三条件（PID+时间+令牌）整树回收 | 无；异常残留用任务管理器按 PID 台账清理（`~/.aether/run/adapters.json`） |
| 18 | 输出洪水 | 内存涨/延迟升 | 行级处理 + 2MiB/帧硬上限断连记错；RSS 告警 | 无；检查适配器版本（可能被篡改/异常输出） |
| 19 | 双开同一适配器 | 二次启动无响应 | 单实例锁：第二实例退出并聚焦已有窗口 | 无（使用已有窗口即可） |

## 存储类（D3/D4；演练 M4-02）

| # | 场景 | 症状 | 系统自动应对 | 你的操作 |
|---|---|---|---|---|
| 5 | 磁盘满 | 保存失败、只读横幅 | 连续 3 次写失败 → `persist_degraded`（只读）；UI 明示 | 清理磁盘，或把备份/导出切到外部路径；修复后**重启应用**（无热恢复） |
| 6 | 库损坏 | 启动进入安全模式 | 拒绝写入；只读打开 + 可读导出 + 备份入口 | 从备份恢复（备份页「恢复」）；必要时导出可读数据 |
| 7 | WAL 膨胀 | 磁盘占用高 | >256MB 强制 `wal_checkpoint(TRUNCATE)`；读锁失败退避重试 | 无；持续不降临界值时重启应用，关闭序列会归零 WAL |
| 8 | 写队列积压 | 新任务被拒（`storage_backpressure`） | L1 告警、L2 拒新 run；队列回落自动恢复 | 等几秒重试；频繁出现则导出诊断包上报 |
| 9 | 双开写库 | 第二实例提示 | 单实例锁阻止；`busy_timeout` 兜底 | 关闭多余实例 |
| 10 | 持久化失败 | 只读横幅 + 运行中断 | 3 次写尝试失败（`attempt=n/3`）→ 只读 + 在途 run cancelled；未落盘不广播 | 修复磁盘/目录/权限后**重启应用**；降级期可用诊断/备份 |
| 11 | sequencer 崩溃 | 会话事件停更后恢复 | 自动重启任务，seq 从 `max+1` 恢复 | 无（自愈） |
| 12 | 补读缺口过大 | 提示「历史消息过多」 | 拒绝自动补发（>10k），不重启核心 | 在提示中点确认：清缓存并重载最近 500 条 |

## 协议/并发类（D6/D8；演练 M4-03）

| # | 场景 | 症状 | 系统自动应对 | 你的操作 |
|---|---|---|---|---|
| 20 | 半行/断流 | 适配器异常退出 | 丢弃残行 → 触发监督重启 | 无（自愈）；反复出现则检查适配器日志 |
| 21 | 无效 JSON | 事件丢失计数 | 跳过 + 计数；连续 20 次判不健康重启 | 无（自愈） |
| 22 | 请求超时 | 操作超时错误 | 按方法超时表取消并回结构化错误 | 重试 |
| 23 | 版本不匹配 | 运行时停用 + 升级提示 | `disabled + version_mismatch` | 升级适配器/运行时后重启应用 |
| 24 | stdout 混入日志 | 事件偶发丢失 | 同无效 JSON 计数；有效帧后恢复 | 无；适配器开发者须保证日志走 stderr |
| 25 | 慢 UI 消费者 | 消息短暂缺口 | `gap` 标记 + 自动补读；控制事件不丢 | 无（自动补齐） |
| 26 | 适配器出站积压 | 发送确认慢 | ack 快路径（落库即返回）；高水位拒新 run | 稍后重试 |
| 27 | 取消风暴 | 批量中断慢 | 取消树级联；20 并发停止 ≤10s | 无 |
| 28 | 死锁/任务不退出 | 会话卡住 | 10s 看门狗 dump + 强制清理（dump 进诊断包） | 无；需排查时导出诊断包 |
| 29 | 广播通道满 | UI 短暂丢帧 | `Lagged` 计数 + journal 补读最终一致 | 无 |
| 30 | 控制投递积压 | 适配器被隔离 | 熔断重启 + journal 零丢失恢复；存储高水位自动解除 | 无；反复出现导出诊断包上报 |

## 通用排障入口

1. **顶栏/横幅**：核心未响应、存储降级、容量阈值提示；
2. **诊断页**：导出诊断包（已脱敏，不含密钥）；含日志汇聚、任务 dump、容量与健康状态；
3. **备份页**：手动备份（保留 10 份）、外部路径备份/恢复；恢复含核心重启；
4. **数据目录**：默认 `%APPDATA%\Aether`（Windows）/ `~/Library/Application Support/Aether`（macOS）；
   同步盘/网盘目录会被拒绝启动（仅迁移/退出）；
5. **适配器台账**：`~/.aether/run/adapters.json`（PID 台账；排障时参考，勿手改）；
6. **支持边界**：P0 不提供运行期热恢复、不提供第三方适配器加载、不提供自动审批规则。

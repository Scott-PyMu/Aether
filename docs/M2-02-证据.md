## 3. 边界与偏离记录

1. **`session.create` 可选参数 `native_id`（Mode R 接口细节）**：D6 固定方法集与超时不变；
   本参数为**新增可选成员**（不传 = 全新会话；传 = `--resume` 恢复，返回 `resumed=true`），
   与「JSON-RPC 外层未知成员忽略 / 只增不改语义」的兼容策略一致；`native_id` 的持久化位置
   仍按 ADR-005 为 `sessions.config.native_id`（由核心写入）。真实 CLI 对 UUID 有要求，
   适配器对非法 `native_id` 返回 `-32602`。
2. **`AdapterProcess::spawn_with_env` + `RuntimeManifest.env`（新增，附加能力）**：
   监督器 spawn 支持附加环境变量（密钥引用/夹具注入）；`spawn()` 行为等价于空 env。
   不改变 D5 启动契约（`--launch-token` 仍由监督器追加）；M2-02 用于向夹具注入
   `FAKE_CLAUDE_HOME` / `FAKE_CLAUDE_PID_FILE`。
3. **连接通知接口 `&self` 化**：`AdapterConnection::next_notification` /
   `try_next_notification` / `wait_for_disconnect` 由 `&mut self` 改为 `&self`
   （通知队列加异步互斥），使连接可经 `Arc` 共享给会话客户端；调用方无行为变化。
4. **`RuntimeSupervisor::connection()`（新增只读访问器）**：核心侧取得运行中适配器的
   线协议连接（M2-02 会话客户端；后续 M2-10/M3-02 复用）。无运行进程返回 `None`。
5. **D9 边界（Claude print 模式工具调用）**：适配器不拦截、不伪造权限回环；只上报观察到的
   工具事件。该边界与设计 §2.1 第 4 条一致（适配器进程内行为属信任级，P3 沙箱后兜底），
   已在接入笔记与本节显式记录；④⑤ 类权限场景由 Mock 验证（M2-10 闭环）。
6. **CLI 参数顺序**：`--claude-arg`（夹具脚本路径）**前置**于业务参数——测试以
   `--claude-bin node --claude-arg <fake.mjs>` 注入替身时脚本路径必须紧跟 node
   （Node 选项解析顺序）；真实 CLI 附加参数顺序不敏感。
7. **常量化参数**（AGENTS §3 MAY，记录于本证据）：
   - 适配器默认 run 硬超时 `DEFAULT_RUN_TIMEOUT_MS = 30min`（核心 120s 断流看门狗优先，
     该值仅兜底回收 CLI 进程）；
   - CLI stdout 连续坏行阈值 `CLI_INVALID_LINE_THRESHOLD = 20`（与 D6「连续 20 次无效帧」同口径）；
   - T5a 单测压缩心跳（200ms/150ms）与退避（200ms）仅测试配置；**30s 墙钟断言不压缩**。
8. **夹具 `fake-claude` 与真实 Runtime 的关系**：夹具只复刻官方 stream-json 事件形状与
   `--session-id`/`--resume` 语义（对齐 M1-11 实测样本）；真实端点的完成率/恢复由 M1-11
   spike（20/20、Mode R）与 DoD4 opt-in 脚本承担，二者不可互相替代。

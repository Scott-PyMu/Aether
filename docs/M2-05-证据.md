## 2. DoD 逐条证据

### DoD1 取消风暴：20 会话并发 dispose → 全部 10s 内退出（集成）

```
$ cargo test -p aether-control --test m2_05_cancel -- --nocapture
running 5 tests
[m2-05 DoD1] 20 会话并发 dispose：dispose 全部返回耗时 2.3364689s；任务全部退出耗时 57.4µs；dump 数 = 0
test dod1_cancel_storm_twenty_sessions_dispose_within_10s ... ok
...
test result: ok. 5 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 4.71s
```

断言链（`m2_05_cancel.rs`）：

1. 20 会话各 1 个在途 run（取消响应型执行器：`select! { 许可 → completed, 取消令牌 → cancelled }`）；
2. 20 路并发 `dispose` 全部返回 `cancelled` 终态（有在途 run 口径）；
3. **取消树级联**：20 个 run 令牌全部 `is_cancelled`（`cancelled_count == 20`）、run 行
   `cancelled`、20 个会话取消节点 `is_cancelled`、会话行终态；
4. **全部任务 10s 内退出**（实测 57.4µs；`sweep_tasks_once` + `active_task_count == 0`），
   **零 dump**（取消响应路径不触发强制清理）。

> 说明：20 路 dispose 的 2.34s 为单写队列 group commit（16ms/批）串行落盘耗时，非任务退出
> 延迟；任务退出在 dispose 返回后 57µs 内完成。

### DoD2 interrupt 后会话回 idle 且可续聊（API-E2E）

```
[m2-05 DoD2] interrupt → idle → 续聊完成；权限等待取消决议：decision=Deny timed_out=false reason=会话取消（取消树级联）→ deny（已审计）
test dod2_interrupt_returns_idle_and_conversation_continues ... ok
```

断言链（真实存储 + 事件管线 + 权限服务；无 mock 存储）：

1. `send` → 在途 run；`message.delta` 流式事件被管线受理（`Persisted|Buffered`）；
2. 权限等待绑定在途 run 令牌（`active_run_cancel_token`），`fs.write` 工作区内 → ask，
   pending 持久化（`permissions_pending == 1`）；
3. `interrupt`：run 行/事件 `cancelled`（payload `reason=user_interrupt`）；**权限等待 ≤2s
   内被级联取消** → `decision=Deny`、`timed_out=false`、原因含「取消」；
4. 会话回 `idle`（读库断言）；被中断 run 无 `message.completed`；
5. 审计含 `permission.cancelled`（result=`cancelled`）；
6. **可续聊**：第 2 条 `send` 受理 → 执行器放行 → run `succeeded` → 会话回 `idle`；
   消息行 = 用户 ×2 + 助手终稿 ×1（被中断 run 无终稿）。

**父取消级联（D8「父会话取消级联」）**：

```
[m2-05 DoD2-级联] parent=completed；child/grandchild run=cancelled；会话=terminal；取消节点已级联
test parent_dispose_cascades_to_child_and_grandchild_sessions ... ok
```

`dispose(parent)`（父空闲）→ 父 `completed`；两层后代（`parent_session_id` 链）各在途 run
被级联取消、会话转终态、取消节点级联取消、终态后拒绝新 run（`session_closed`）。

### DoD3 不响应任务注入 → 10s 记录任务 dump 并强制清理，dump 进诊断包（集成）

```
[m2-05 DoD3] task dump（诊断包源）= {"action":"forced_cleanup","dumped_at_ms":1010000,"elapsed_ms":10000,"orphaned_at_ms":1000000,"run_id":"01M319J97AWSNDV726PXKJY75V","session_id":"01M319J95QA2YBAWRKHNQNXVHZ","started_at_ms":1000000,"task":"session:01M319J95QA2YBAWRKHNQNXVHZ run:01M319J97AWSNDV726PXKJY75V"}
test dod3_unresponsive_task_dumped_and_force_cleaned_after_10s ... ok
```

断言链（`ManualClock` 注入；阈值 = `LifecycleConfig::default().task_force_cleanup_ms = 10_000`）：

1. 不响应型执行器（忽略取消令牌、永不返回）在途；`interrupt` 后 run 行/事件已终态，
   **任务仍在册**（`active_task_count == 1`）、无 dump；
2. 取消后 9_999ms：`sweep_tasks_once` 空、无 dump、任务仍在册；
3. **恰好 10_000ms**：记录 1 条 dump —— 任务名 `session:<id> run:<id>`、
   `started_at_ms/orphaned_at_ms/dumped_at_ms` 齐全、`elapsed_ms=10_000`、
   `action=forced_cleanup`；
4. `JoinHandle::abort` 生效后任务出册（`active_task_count == 0`）；dump 保留在诊断缓冲、
   重复巡检不重复记录；`serde_json` 序列化字段可导出（**M3-05 诊断包消费源**）。

**「按 bug 上报」经 tracing（M2-07 运行期日志汇聚端输入）**：

```
$ cargo test -p aether-control --test m2_05_watchdog_log -- --nocapture
captured watchdog log: 会话任务 dump：取消后 10000ms 未退出（阈值 10000ms），已强制清理（D8 看门狗）
test watchdog_dump_is_reported_via_tracing ... ok
```

## 4. 边界与偏离记录

1. **`tokio-util` 直接依赖（`default-features=false`）**：设计 D8 表述为「会话级
   `CancellationToken`」，采用其标准实现（父/子节点级联语义经库内 tree node 保证）。
   该 crate 0.7.19 已在 `Cargo.lock`（aether-adapters 经 `codec` 特性使用，MIT/Apache-2.0），
   本次仅新增 `aether-control → tokio-util` 依赖边（`Cargo.lock` 仅 1 行），**未新增任何
   crate 包**；`cargo deny check licenses/bans/sources` 全绿。
2. **强制清理的层级**：`TaskWatchdog` 的强制清理是 **tokio 任务级 `JoinHandle::abort`**，
   用于回收不响应取消的会话执行任务；适配器**进程树**回收仍属 D5/M1-10（进程组/Job
   Object/`taskkill`），两者不混用（AGENTS §2.5 不受影响）。
3. **dump 进诊断包的衔接**：M2-05 交付 dump 的**诊断缓冲**（`SessionManager::task_dumps()`，
   环形上限 64，常量级参数）与 `tracing::error!` 上报；运行期日志汇聚端归 M2-07、
   诊断包导出归 M3-05（与 D11「P0 诊断包日志来源于运行期 tracing 汇聚端」一致）。
   本任务以集成断言证明 dump 字段完整、可序列化、可重复导出。
4. **`waiting_permission` 的取消返回路径**：状态机白名单（冻结，19 条边）不含
   `waiting_permission → idle`；M2-05 的 `interrupt`/run 终态收口在
   `waiting_permission` 下走 **`waiting_permission → running → idle`** 两条合法转移
   （各落行 + `session.status_changed`）。该状态由 M2-10/M3-03 接线（P0 尚无写入路径），
   M2-05 先行保证取消路径合法（集成用例 `interrupt_from_waiting_permission_settles_via_running`
   以直接落库构造前置）。
5. **权限等待可取消的绑定口径**：`PermissionService::request_cancellable` 由调用方传入
   run 令牌（`SessionManager::active_run_cancel_token`）；`interrupt` 取消 run 令牌、
   `dispose`/父取消经会话节点级联。权限服务不写会话状态（D9 状态归属 M2-10/M3-03），
   M2-05 只保证「等待被唤醒 + deny 收口 + 审计」，`request` 原签名保持兼容（委托
   `request_cancellable(…, None)`）。
6. **取消/决议并发的仲裁**：以「票据从审批队列摘除」为唯一仲裁点——取消方摘到票据则
   deny 收口；已被决议路径摘除则回落到等待实际决议（不丢决议、不产生双决议/死锁）。
   取消决议 `timed_out=false`，与 300s 超时 deny 可区分（审计动作分别为
   `permission.cancelled` / `permission.timeout`）。
7. **未新增事件类型/表结构**：dump 的 `action=forced_cleanup` 为诊断缓冲字段而非事件
   payload；权限取消复用附录 B `permission.resolved` 事件与既有 `audit_log`（新增审计
   action 字符串 `permission.cancelled`，非事件类型）；`SessionQuery.parent_session_id`
   为只读过滤参数，无 DDL 变更、无迁移。
8. **后台任务数量不变**：`sweep` 接入既有看门狗循环（`spawn_background` 仍为 3 个任务，
   M2-01 用例断言不回归），未新增全局状态。

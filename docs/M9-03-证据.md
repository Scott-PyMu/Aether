## 3. DoD-1：`initialize` 结构与 `DaemonPhase`

请求（`InitializeParams::from_value`，未知成员忽略 = minor 增量）：

```json
{"protocolVersion":"1.0","appVersion":"0.1.0","client":"electron",
 "clientCapabilities":["events","permissions","dialogs","browser-view"],
 "requiredCapabilities":["events","permissions"]}
```

响应字段**冻结为 6 项**（单测 `initialize_result_has_frozen_field_set` 断言键集合）：
`protocolVersion` / `daemonVersion` / `coreVersion` / `dataDir` / `phase` / `daemonCapabilities`。

- `daemonCapabilities = ["events","permissions","dialogs"]`；`browser-view` 为 **client-only**（不要求 daemon 声明，`requiredCapabilities` 不校验）；
- major 不匹配 → `-32001 protocol_mismatch`（`data.reason`，单测 `major_mismatch_is_protocol_mismatch`）；
- `requiredCapabilities` 未满足 → `-32006 capability_missing`（`details` 列出缺失项）；
- `DaemonPhase` 产出 8 值：`starting`/`detecting`/`opening`/`warming`/`ready`/`degraded`/`shutting_down`/`failed`；`migrating`/`blocked` 为**保留值**（M9 不产生，单测断言不在 `PRODUCED` 内）；
- 重复 `initialize` → `invalid_request`（`reason=duplicate_initialize`）；重复 `request id` → `invalid_request`（`reason=duplicate_request_id`，窗口 4096）。

## 4. DoD-2：`params` 形状冻结与 golden fixtures

根因口径（ADR-029 §4.3 / P1-5 裁定）：`params` = **内层请求 DTO**，去掉 Tauri `{ payload }` 包装；无参方法 `omit`/`null`/`{}` 等价（`aether-app::validate::parse_no_params`）。

fixtures（`scripts/test/m9-03/fixtures/`，`expectations.json` 为机器可读期望）：

| 文件 | 行 | 覆盖 |
|---|---:|---|
| `initialize.jsonl` | 1 | 握手 golden（5 字段请求） |
| `params.jsonl` | 5 | `startup_get` 省略 / `null` / `{}`；`session_create` `{payload:{…}}`；内层 DTO 直传 |
| `transport.jsonl` | 7 | 畸形 JSON / 非对象 / `jsonrpc` 错 / 缺 `method` / 首次 id / 重复 id / 未知方法 |
| `shutdown.jsonl` | 2 | `shutdown` 回执；关闭后请求 `-32004` |

逐条断言（`crates/aether-daemon/tests/m9_03_stdio.rs::params_shapes_are_equivalent_and_payload_wrapper_is_rejected`）：

- `id=11/12/13`（省略/null/`{}`）结果**逐字节相等**（deep-equal `result`）；
- `id=14`（`{payload:{…}}`）→ `-32602` + `aether_code=unknown_field` + `details.field=payload`；
- `id=15`（内层 DTO `{runtime_id,title}`）→ 严格解析通过（后端拒绝也**不得**是 `unknown_field/invalid_json/missing_field`）。

### 5.2 握手时延（目标/硬超时）

`initialize_handshake_meets_hard_timeout_and_records_target`（进程级，真实 spawn，多次运行）：

```text
initialize 握手耗时 189ms / 310ms（目标 ≤2000ms）
test result: ok. 1 passed; 0 failed
```

- **目标 ≤2s**：实测 **189–310ms**（debug 构建、空注册目录、含数据目录/锁/A4/DB 打开/checksum 校验 + A3 探针）；
- **硬超时 ≥10s**：测试断言 <10s（超时重试 1 次 + S-12 由 Electron main 承接，M9-07）；
- `initialize` **不等待适配器预热**：响应 `phase=warming`，预热完成另推 `daemon.status ready`；
- `startup_get` 契约与迁移期壳一致：`phase`/`data_dir`/`security_level`（`os|degraded`，A3 自检在预检后同步执行）。

### 5.3 stdout 只允许 JSONL / stderr 只放日志

`initialize_shutdown_and_stdout_is_jsonl_only` 断言 stdout 每一行都是 `{"jsonrpc":"2.0",…}`；stderr 含 `aetherd 启动` 运行期日志。daemon 自建订阅器（`LogSink` 层 → `<data_dir>/logs/aetherd.log` + 环形缓冲，stderr 层 → 父进程 drain），**不写 stdout**。

### 5.4 帧/请求边界（DoD-7）

| 场景 | 行为 | 用例 |
|---|---|---|
| 畸形 JSON | `-32700` + `aether_code=invalid_json`，连接继续 | `transport.jsonl` 行 0 |
| 非对象 / `jsonrpc` 错 / 缺 `method` / `id:null` | `-32600` | `transport.jsonl` 行 1–3 |
| 重复 `request id` | `-32600`（`reason=duplicate_request_id`），**不重复触达业务层** | `transport.jsonl` 行 5 |
| 未知方法 / 壳本地命令误入 | `-32601`（`aether_code=not_implemented`） | `transport.jsonl` 行 6、`serve::tests` |
| 未 `initialize` 业务请求 | `-32002`（`aether_code=core_not_ready`） | `pre_initialize_business_request_is_core_not_ready_then_initialize_works` |
| 帧 >2MiB（含 2MiB+1、10MiB 单行） | `-32003`（`aether_code=too_large`，`details.limit=2097152`）；**只失败本请求** | `oversized_frame_only_fails_the_request`（同 pid 继续服务） |
| `shutdown` 后新请求 | `-32004`（`reason=shutting_down`） | `shutdown.jsonl` 行 1（`aether-rpc` 回放） |

`daemon.status_notifications_follow_phase_transitions` 断言 `ready` 与 `shutting_down` 两个通知（通道登记 §16.4）。

## 7. DoD-5：致命启动检查（三组 fixture）

预 `initialize` 顺序（`crates/aether-daemon/src/bootstrap.rs`，与 ADR-029 §3.5-4 一致）：
解析数据目录 → OS 独占锁 `<data_dir>/.aetherd.lock` → A4 判定 → DB 打开（**不含 `quick_check`**）→
已应用迁移 checksum 校验（**不执行迁移**）。
`aether-store::preflight`（新增）只做「打开 + checksum 比对」，退出码 23 为保留码位（M9 不触发）。

| 组 | 场景 | 首帧（`id:null`，`-32005`） | 退出码 | 用例 |
|---|---|---|---:|---|
| 致命 | 数据目录解析失败 | `aether_code=internal` | 24 | `bootstrap::tests`（穷尽映射） |
| 致命 | A4 同步盘（Windows `OneDrive` 前缀命中） | `startup_blocked` + `sync_dir_blocked` + `phase=failed` + `log_path` | 21 | `a4_sync_dir_is_fatal_exit_21` |
| 致命 | 数据目录锁被占用（第二实例） | `internal` + `data_dir_locked` | 20 | `second_daemon_on_same_data_dir_exits_20_with_first_frame_error` |
| 致命 | DB 无法打开（非 SQLite 文件） | `internal` + `db_open_failed` | 22 | `db_open_failed_is_fatal_exit_22` |
| checksum | 已应用迁移 checksum 被篡改 | `internal` + `schema_checksum_mismatch` | 22 | `applied_migration_checksum_mismatch_is_fatal_exit_22` |
| 安全模式 | DB 可打开但 `quick_check` 失败 | **无首帧 error**；`health.storage_state=persist_degraded`，进程存活 | 0（可干净退出） | `quick_check_failure_enters_read_only_safe_mode_without_exiting` |

安全模式样本构造（确定性）：建库 + 迁移 → 写 120 行 2KB 探针表 → `wal_checkpoint(TRUNCATE)` → 覆写末页 256 字节 → 删除 `-wal`/`-shm`；预检只读 `schema_migrations` 通过，预热阶段 `Store::open` 的 `quick_check` 失败 → `persist_degraded`。

A4 为**致命**：不打开库、不写业务数据（仅创建进程互斥用的 `.aetherd.lock`，handle-based，退出即释放）、不提供迁移入口（`startup_get`/`startup_migrate` 保留在 63 内但 M9 不暴露）。

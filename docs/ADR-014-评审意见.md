### 0.1 运行时权限模型（实测依据）

来源：`docs/spike/M1-11-接入笔记.md:152-158`；DSH 侧为 `dsh-sandbox-local` / `dsh-sandbox-windows-acl` / `dsh-permission-presets` + `read-only / workspace-write / danger-full-access` 文件策略 + `ask / never` 审批策略。P0 代码**已存在**投影开关：`packages/adapter-codex/src/cli.ts:12,60`（`--sandbox`，缺省写死 `read-only`）、`codex-cli.ts:61-72`（resume 走 `-c sandbox_mode=`，ADR-008 `:50` 已知坑 7）、`packages/adapter-claude-code/src/claude-cli.ts:80`（`--permission-mode`，缺省 `default`）。

| 运行时 | 三档 | 审批策略 | 全放行 |
|---|---|---|---|
| **Codex** | `--sandbox read-only` / `workspace-write` / `danger-full-access` | `approval_policy` | `--dangerously-bypass-approvals-and-sandbox` |
| **Claude Code** | `--permission-mode plan` / `acceptEdits` / `bypassPermissions` | `--allowedTools`/`--disallowedTools` | `--dangerously-skip-permissions`（root 下 `auto`） |
| **DSH** | 文件策略 `read-only` / `workspace-write` / `danger-full-access` | `dsh-permission-presets` + `dsh-user-approval` | preset/settings |

**共同执行逻辑**：①档位约束"写的作用域"，不约束读；②`workspace-write` = 工作区内写免逐次审批，需审批的是策略外动作（区外写、越权命令）；③顶档 = 无沙箱（任意路径读写 + 命令执行 + 联网）。

### 0.2 建议合入的 D9 三档矩阵（按 R10/R11 定稿）

| 资源:动作 | `read_only`（仅查看） | `workspace_write`（工作区内修改，缺省） | `danger_full_access`（完全权限） |
|---|---|---|---|
| `fs.read`（工作区内 / 外） | allow / allow | allow / allow | allow / allow |
| `fs.write`（工作区内） | deny | **allow** | allow |
| `fs.write`（工作区外） | deny | **ask**（300s → deny + 审计） | **allow**（R8） |
| `exec`（上报型工具调用） | deny | deny | **allow**（R11；**仅门层**，R13） |
| `net`（上报型工具调用） | deny | deny | **allow**（R11） |
| `browser` / `mcp` | n/a | n/a | n/a（功能未启用） |
| 记忆文件白名单 | deny | 被区内 `allow` 覆盖（留审计 + 1MB 上限） | 同左 |

- **放行 ≠ 旁路**：顶档 `allow` 仍 100% 经网关并落审计（`crates/aether-control/src/permission.rs:353-383`，`permission.allowed_by_policy`）；M2-10 零直通口径不变（AGENTS §2.7）。
- **R13 阶段口径**：本档开放的是**门层判定**（上报型 `exec` 调用可被判 `allow`）；**内嵌终端面板 PF-05 仍维持 P3**（设计 §4#9 `:617`、附录 A `:743`、需求 `:117`/`:165` 加注"仅门层开放"），不构成 P3 能力提前，故无需 §4 对价。

## 1. 总体结论

**文档完整性（较好）**：决策表、影响面、版本表、未决项、回退条件、范围对价、原型依据、变更记录齐备；ADR 编号无冲突。

**引用准确性（核验通过项）**：命令面 36（设计 D7 `:465`＝代码 36 条）、36+15=51；错误码 16→20→22；D9 现状引用全部对得上；帧上限不变；`session.updated`/`runtime.status_changed` 为既有类型且零发射；原型 8 处行引用 8/8 准确；与 ADR-003/004/006/007/008 无实质冲突。

**一致性状态（不通过）**：**3 项 P0、5 项 P1、18 项 P2**，全部为文本改写与断言同步：

1. **矩阵与不变量须按 R10/R11 改写**（问题 1）：档位值名对齐运行时、区外读放行、缺省档区内写 `allow`、顶档 `exec`/`net` 放行、不变量 3/7 重写、§1.3 增 Q7 行（含覆盖 Q4 的说明）。
2. **决策 3 须补五段式**（问题 2）：顶档"运行时全权"必须写入风险段，失效条件须给出收紧路径。
3. **R11 触碰的三处基线须同步**（问题 26）：D9 决策与矩阵、§4#9/PF-05 阶段标签（R13 已定口径）、既有断言（`policy.rs:370-383`、`m2_03_permission.rs:172-187`）与计划 `:22`/`:202`/`:208`②。

**最大风险**：**顶档 = 运行时全权（任意路径读写 + 命令执行 + 联网）**。R11 后本门在顶档不做能力收敛，控制手段仅"会话级显式选择 + 缺省档收紧 + 投影 + 审计 + 降级失效 + 常驻文案（R14）"，**不构成技术隔离**；UI/文档不得出现"完全权限仍无终端/网络通道"式表述。

**结论**：**不通过**；决策 3 安全评审**有条件通过**（§6 C1–C9）。产品裁定已全部完成（R1–R14），无待决策项；§8 给出按文件的改写清单，可直接施工。

## 6. 决策 3 独立安全评审结论（草稿，待签署）

> 依据：计划 `:130`（M5-01 DoD1）；`评审要求.md` §六；《设计文档》§2.1 `:154`、D9 `:521-546`。本结论由评审方（安全视角）出具，不替代产品裁定（§0 R1–R14）。

**结论：有条件通过。**

| 条件 | 内容 | 落点 |
|---|---|---|
| C1 | 矩阵与 R10/R11 一致（§0.2），档位值与运行时同名同序；不变量 3 覆盖所有 `ask`、不变量 7 限定 `deny` 类 | 附录 B；DoD8① |
| C2 | 档位降级即失效（R4） | 附录 B；DoD8 |
| C3 | 权限基准不因会话改派重算（R5） | 附录 B；M7-08 DoD2 |
| C4 | 零直通与审计不削弱：含顶档 `allow`（`exec`/`net`/区外读写）在内 100% 经网关并落审计；M2-10 回归不变 | 附录 B；DoD8；M2-10 |
| C5 | UI 边界声明**常驻一行**（R14），文案见问题 7；不得出现"无终端/网络通道"式表述 | 附录 F；DoD8⑨ |
| C6 | 五段式补齐（含顶档语义与失效条件） | ADR-014 决策 3 风险段 |
| C7 | 需求载体（问题 11）与范围对价（问题 4）就位 | 需求 v0.11；ADR-014 §7 |
| C8 | 档位**投影**（R12、§0.3），映射表登记进 P1-A10/M7-06 并经实测断言；仅新会话生效 | M7-06 DoD1；DoD8 |
| C9 | D9 冻结条款随 R11 修订（附录 D-3）+ **PF-05 阶段标签按 R13 加注"仅门层开放"**；断言按档位三态改写并标注驱动来源 | 设计 D9/§4#9/附录 A；需求 PF-05；M6-01 DoD8；问题 26 |

**残留风险声明（条件全部落地后仍存在）**

1. **信任级边界**：适配器进程内行为（含其自身执行的命令与文件操作）不受本门约束；`read_only` 档亦不能阻止（设计 §2.1 `:154`）。
2. **顶档 = 运行时全权**：任意路径读写 + 命令执行 + 联网；本门不做能力收敛（R11）。控制手段仅"会话级选择 + 投影 + 审计 + 降级失效 + 常驻文案"，**不构成技术隔离**。
3. **`allow` 判定无弹窗** → 事前不可见目标路径（事后审计）；TOCTOU 在顶档无审批兜底。
4. **出站不做限制**（R6）：连通性测试与顶档 `net` 均可将请求（含凭据）发往任意主机（含内网/环回）；产品接受风险，须留痕。

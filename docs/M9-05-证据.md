## 2. 实现

### 2.1 daemon：落盘后事件 → `aether.event`

- `crates/aether-app/src/event_bridge.rs`（新增，transport-agnostic）：
  - `EventFeed`（生产实现 = `EventPipeline`；`subscribe` 只接收**落盘后**广播，`readback` 复用 D4 补读）；
  - `EventBridge`：有界 `mpsc(4096)` + writer/forwarder 两个任务；
  - **可丢集合**严格为 `message.delta` / `usage` / `log`（ADR-029 §4.7 原文）；
  - 控制事件队列满 → `EventPipeline::readback(last_delivered)`；重复事件按 `(session_id, seq)` 去重；
  - 连续 3 次补读失败 → 重建**事件订阅**（不重启 daemon）+ 写审计 `event.bridge.escalated`；
  - `readback_gap_too_large` 不自动重试（UI 走 `messages_page` 同码提示）；
  - 关闭预算 `DELIVERY_SHUTDOWN_TIMEOUT = 2s`：daemon 关闭序列**先停事件桥，再停管线**。
- `crates/aether-daemon/src/serve.rs`：
  - `EVENT_METHOD = "aether.event"`；`params` = EventEnvelope 9 字段，通知无 `id`；
  - 预热完成、后端注入后启动事件桥（`spawn_warm`）；关闭时先停桥并记录指标；
  - 启动/关闭与 M9-03 的 `daemon.status` 通知共用唯一 stdout writer（帧级互斥）。
- `crates/aether-app/src/boot.rs`：`BackendBundle` 增加 `write: Option<WriteQueue>`（仅用于升级审计出口）；`pipeline` 原语义不变。

### 2.2 Electron main：`aether:event` 单通道

- `apps/desktop/electron/eventBridge.ts`（新增，无 Electron 依赖）：
  - `EVENT_IPC_CHANNEL = "aether:event"`、`EVENT_BATCH_INTERVAL_MS = 16`、`EVENT_QUEUE_CAPACITY = 4096`；
  - 单队列 FIFO；16ms 合并发送，批内顺序不变；
  - 队列满：delta 类可丢并计数；控制事件先丢队列内 delta 让路，仍满则 flush + journal 补读；
  - 连续 3 次补读失败才 `audit` + `rebuildConnection`（M9-07 提供实际重连；本任务以回调测试）；
  - `readback_gap_too_large` 不升级；renderer 15s 健康判定沿用既有 `src/health.ts`。
- `apps/desktop/electron/eventBridge.test.ts`：8 个用例（FIFO/16ms、可丢集合、控制让路、补读去重、3 次升级审计、gap 不升级、dispose、补读顺序）。

### 2.3 未改动面

- EventEnvelope 9 字段、附录 B 23 类型、`events` 表结构、迁移 0001–0009、63 命令、
  `error_codes.json`（32 + 9）均未修改；`packages/protocol/src/bindings.ts` 等生成物未手改。
- `aether-tauri` 迁移期壳保持可用；事件桥由 daemon/Electron main 接线，不在核心 crate 内绑定传输。

## 4. 已知边界 / 未验证

1. **macOS/Linux**：本机仅 Windows x64；事件桥使用 stdio/广播/DB，无平台分支，
   但 macOS/Linux 的进程级运行未在本任务执行（由 M9-13 平台矩阵覆盖）。
2. **Electron main 实际重连**：`MainEventBridge.rebuildConnection` 在 M9-05 以回调交付并测试；
   真实 daemon 客户端重连由 **M9-07** 接线（本任务不创建窗口/不 spawn daemon）。
3. **权限/暂停/审计回环**：属 M9-06；本任务只保证事件投递与升级审计，不改变 D9 路径。
4. **daemon 侧「连接重建」口径**：stdio 只有一个连接，M9-05 的「连接重建」实现为
   **事件订阅重建 + journal 补读**（进程与既有 JSON-RPC 连接不重启），符合 ADR-029
   「不重启 daemon」的硬约束；main 侧由 `rebuildConnection` 回调承担。
5. **10×50 的 delta 速率口径**：桥层用注入事件源按 50/s 精确发布；真实 `EventPipeline`
   对 `message.delta` 有 16ms/8KB 合并（D8 既有设计），端到端落盘率低于输入速率，
   该差异不是事件桥引入，且控制事件零丢失断言不受影响。
6. **全 workspace 测试链接与 Tauri 测试**：本轮 `cargo test --workspace --no-run` 在链接
   `aether-tauri` 大测试目标时 rustc OOM（`STATUS_STACK_BUFFER_OVERRUN`，环境内存压力）；
   已用 `CARGO_BUILD_JOBS=1 cargo check -p aether-tauri --tests` 验证测试目标编译通过，
   并按 target 低内存**实际执行** M9-05 相关 Tauri 测试 45 条（§3.7，45/45 通过）。
   仅**全量 Tauri 套件**（55 个 target）留给 M9-13 在 CI/高内存环境执行；不使用
   `cargo check --tests` 替代已执行的相关测试。

## 1. ADR-028 v0.3 修订清单

### A1. 版本与状态

- 版本：`v0.2` → **`v0.3`**。
- 状态：改为 **“修订中（评审 P0×2/P1×7 整改），待复审”**；删除“已通过”。
- “Phase 1 已实现”可保留，但必须加注：**“需按 v0.3 整改后复审，不作为验收基线”**。
- §8 变更记录新增 v0.3 行，逐条列出 7 项裁定。

### A2. 术语与事实修正

- 全文“**一次性 token**”改为“**应用级 token（每次应用启动轮换；同一启动内连接复用）**”。涉及：
  - §2.1-2 第 2 条；
  - §3-1；
  - §4 实现落点表；
  - §7-4。
- 全文“**审计**”改为“**运行日志（tracing）**”。涉及：
  - §2.1-2 第 5 条；
  - §7-5。
- 明确写一句：**不写数据库、不新增事件类型、进程重启后不可查、不作为合规审计**；若后续要求持久审计，另立 ADR。

### A3. 新增“信任边界与补偿”小节（建议 §2.3）

必须写明：

- **信任假设**：适配器进程本身可信；token 为应用级共享；`runtime_id` 由客户端自报，仅作标签，不构成强认证。
- **已接受残余风险**：同用户恶意进程或被篡改的官方适配器，可读取 token 并向 broker 请求任意 provider 的凭据。
- **补偿措施**：
  - token 不落盘、不进日志/诊断包/导出/测试夹具；
  - broker 仅本机、仅当前用户；
  - 仅官方 runtime label 可请求；
  - **所有官方适配器的 CLI 子进程统一剥离 `AETHER_CREDENTIAL_BROKER`**（不是只 Claude）；
  - 每次会话/每次 run 重新取密钥；
  - 创建前 fail-fast；
  - 密钥扫描 0 命中。
- **后续改造触发条件**：第三方适配器接入（P3）、安全评审要求 per-adapter token、或出现越权事件；届时另立 ADR，改为 per-adapter token + runtime/protocol 范围。

### A4. §2.1-2 Credential Broker 改写

- 适配器每次 run 按 `provider_id + protocol` 取密钥；broker 和适配器均不缓存。
- `session_create` 做一次“可解析性预检”（读取后立即丢弃），不把 key 存入会话状态。
- broker 启动失败或未接线：**multi_provider 会话创建直接失败**，不再“回退单供应商 env”。
- 删除“适配器 spawn 时获得 broker 地址 + 一次性 token”中的“一次性”。
- 增加：`runtime_id` 必填；建议增加 runtime → protocol 白名单（Claude→anthropic、Codex→openai、DSH→dsh）作为低成本补偿，但不改变信任模型。

### A5. §2.1-3 端点补全规则

把“端点缺失/不可用时返回错误”细化为明确的解析顺序：

| 运行时 | 协议 | 显式端点 | 次选 | 官方默认 |
|---|---|---|---|---|
| Claude Code | `anthropic` | `endpoints.anthropic` | `base_url`（DeepSeek 自动补 `/anthropic`） | `type=anthropic` → `https://api.anthropic.com`；`type=deepseek` → `https://api.deepseek.com/anthropic` |
| Codex | `openai` | `endpoints.openai` | `base_url` | `type=openai` → `https://api.openai.com/v1`；`type=deepseek` → `https://api.deepseek.com` |
| DSH | `dsh` | `endpoints.dsh` | `base_url` | `type=deepseek` → `https://api.deepseek.com` |

- 其他类型（如 Google）没有统一官方默认：**必须显式配置端点，否则 `invalid_value`**。
- 明确修复：**DeepSeek 显式 provider + `{}` endpoints + Claude Code 必须解析到 `/anthropic`**，不能返回“无端点”。

### A6. §2.1-4 选择语义改写

删除“缺省 `provider_id` 沿用现有单供应商路径”这一句，替换为：

- **声明 `multi_provider` 的运行时**：`provider_id` 必填；缺失 → `invalid_value("请选择供应商")`；**不得按 `(updated_at, id)` 或其他规则静默选默认**。
- **未声明 `multi_provider` 的运行时（Codex/DSH，Phase 1）**：保留 M7-06 单供应商路径；但其默认选择必须**回退为按 `provider_type` 匹配**，不能因为新增端点字段而改成按端点匹配。UI 必须显示“当前生效供应商”；Phase 2/3 接入 per-session 后改为同一套“必选 + 记忆”。
- **UI 记忆**：首次成功创建后记住 `(agent, provider)` 组合；下次新建会话默认预填；用户可修改。
- **失效处理**：记住的 provider 被停用/删除时，清空并要求重选，**不得回退到其他 provider**。
- **自动路由**：ADR-022 的自动路由保留为显式选项；选择自动路由时，provider 仍需显式指定；若路由结果与 provider 协议不兼容，创建失败并提示。

### A7. §3 硬约束补强

- 第 1 条：token 改为“每次应用启动随机生成、连接间复用”。
- 第 5 条：缺少 provider/端点/模型/key/broker → **创建会话前拒绝**，不得推迟到 CLI/API 层。
- 第 6 条：legacy 兼容保留，但**不得静默切换供应商**。
- 新增：**所有官方适配器必须把 token 从 CLI 子进程 env 中剥离**。
- 新增：**不新增命令/事件/错误码/迁移**；错误统一用既有 `invalid_value` / `core_not_ready`。
- 新增：**broker 不做数据库审计**。

### A8. §5 影响

- 删除或限定“缺省路径兼容”的表述。
- 更新文档版本链：设计 v1.19、需求 v0.13、P1 计划 v0.8。
- 明确迁移 `0009` 不变，不新增迁移。

### A9. §6 回退条件

- 删除“broker 不可用 → 回退单供应商 env”。
- 改为：
  - broker 不可用 → multi_provider 会话创建失败；
  - 回退动作 = 关闭 `multi_provider` 能力 / 回退版本，保留端点字段；
  - 若未来改为 per-adapter token，另立 ADR。

### A10. §7 DoD 重写

建议改成 7 条：

1. 迁移 0009 + `providers.endpoints` 读写/回显；`{}` 回退按类型。
2. UI 预设端点 + 空端点自动补全预览；DeepSeek 双端点。
3. `session_create.provider_id`：multi_provider 必填、provider/model/endpoint/capability 校验、无默认、失败无部分会话。
4. broker：应用级 token 语义、runtime/protocol 白名单、按需读取、日志不含密钥；**三个官方适配器 CLI env 均无 token**。
5. **应用级 E2E**：走 `session_create`/`session_send` 命令层 + 真 broker + 真适配器 + 假 CLI + 本地 mock 上游；两会话并发、两 provider、不同 key/base_url；含负向用例。
6. **证据文件 `docs/M7-10-证据.md`**：命令、结果、日志、脱敏证明、裁定落实表。
7. 回归：M7-06/M3-11/会话创建/设置测试不回归。

### DoD③ 进程组与 Windows Job Object；终止序列逐步硬超时，每步平台断言

- 验证方式：单测（硬超时：脚本化「永不退出」目标，逐步骤 `timeout_ms` 与预算一致，
  graceful 失败落到 force、RPC 失败继续）；集成（真实进程树 + 平台机制断言）。
- 真实输出（Windows 本机，`--nocapture`）：

```
$ cargo test -p aether-adapters --test m1_10_termination -- --nocapture
[m1-10] Windows 终止机制序列：["shutdown_rpc", "taskkill_tree", "terminate_job_object"]
test termination_sequence_platform_mechanisms_reap_whole_tree ... ok
test force_kill_reaps_tree_via_job_object_or_process_group ... ok
test graceful_step_is_bounded_and_platform_correct ... ok
test non_linux_platform_assertion_is_explicitly_skipped ... ok
test result: ok. 4 passed; 0 failed
```

说明（平台行为，实测）：
- Windows 控制台进程上 `taskkill /PID x /T`（无 `/F`）返回 EC 128
  （"can only be terminated forcefully"），**属预期**；序列随即执行步骤 3
  `TerminateJobObject` 整树回收（机制名 `terminate_job_object`），父+子进程全部消失；
  步骤 4 `taskkill /PID x /T /F` 为兜底（代码路径 `taskkill_tree_force`）。
- 硬超时证据：`taskkill` 以 `tokio` 子进程运行，超出步骤预算即被中止
  （`process.rs::taskkill_bounded`，预算 = 步骤硬超时 − 250ms 余量）；
  单测 `full_sequence_steps_run_in_d5_order_when_target_never_exits` 断言 RPC 5s /
  graceful 5s / force 3s / fallback 2s 的逐步硬超时，总预算 ≤15s（D5 重启预算）。
- Unix（`#[cfg(unix)]`，本机未运行，见「未验证项」）：`ProcessSession` 调 `nix::unistd::setsid`
  （process-wrap 8.2.1 源码），终止为 `SIGTERM`→`SIGKILL` 到 `-pgid`；Linux 断言
  `pgid == pid`（`/proc/<pid>/stat` 第 5 字段）。
- Windows `CREATE_NEW_PROCESS_GROUP`：spawn 经 `CreationFlags(0x00000200)` + `JobObject`
  （`process-wrap::tokio`）；常量断言 `windows_creation_flag_is_new_process_group`。
  Job Object 归属为行为断言（整树回收），非沙箱（ADR-004，代码注释明示）。

## 4. 未验证项与边界（明确标注）

1. **Unix 平台断言未在本机运行**：`linux_spawn_uses_setsid_process_group`（`/proc` pgrp 断言）
   为 `#[cfg(target_os = "linux")]`，本机 Windows 显示 `SKIP`。
   **（2026-09-18 更新：已由 CI 三平台矩阵关闭——ubuntu-latest/macos-latest 真实执行并通过，
   见 §5；macOS 断言为 `#[cfg(target_os = "macos")]` + `ps -o pgid=` 交叉验证。）**
2. **资源告警的真实超限路径未在集成触发**：无 1GB/200% 夹具；逻辑由
   `resources.rs` 单测覆盖（RSS/CPU 持续 60s、回落复位、边界相等不算超限），
   集成仅断言采样可读且不误报。
3. **`runtime_retry`/`runtime_enable` 的 IPC 接线未在本任务完成**：
   命令面 DTO/参数格式校验由 M1-08 交付（`ipc/dto.rs`、`ipc/commands.rs` 已注册并测试）；
   本任务交付命令语义（白名单 + 状态校验 + 转移断言）。将监督器注入 `IpcBackend`
   属 **M2-01**（依赖 M1-05、M1-10）范围；本任务不改动 `aether-tauri`（避免与并行任务冲突）。
4. **`CREATE_NEW_PROCESS_GROUP` 无运行期可见性断言**：Windows 未提供安全只读查询
   （`GetProcessTimes`/Job 查询不含创建标志；工作区 lint 禁止 unsafe FFI），
   以常量单测 + Job Object 行为断言（整树回收）组合覆盖。
5. **覆盖率门禁未在本机复跑**：`pnpm ci:local`（含 `cargo llvm-cov`）由批次出口统一执行；
   本任务新增模块自带单测/集成，未修改既有测试断言。
6. **Mock 适配器 CLI 尚未接受 `--launch-token`（交接项，不属本任务文件范围）**：
   D5 要求监督器 spawn 时注入 `--launch-token=<ULID>`；本任务以夹具 bin 全量验证该契约。
   `packages/adapter-mock` 的 `parseArgs` 目前对未知参数报错退出，M2-01/M2-02M 接入监督器前
   需在该 CLI（或 adapter-sdk 统一入口）接受并忽略该参数；本任务未改 M1-09 交付物以避免越界。
   **（2026-09-17 更新：已由 M1-09 增量修订关闭——Mock CLI 现接受 `--launch-token=<ULID>`
   并写入 stderr 启动日志；见 `docs/M1-09-证据.md` §1。）**

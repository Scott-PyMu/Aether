## 1. 测试口径

- **mock/单测**：先验证 capability/ack/version/fold/restart/失败，不写注入主路径（ADR-032 §D-032-4）。
- **真实 CLI**：使用本机真实 CLI 二进制 + 本地 mock 上游（Anthropic Messages / OpenAI Responses），验证**实际请求体**中的 system/developer 块；不使用真实凭据、不把密钥写入证据。
- 判定：`system_replace` 要求同块只出现最新；`message_append`/`origin_fork` 要求最新 version 有效、旧块标记 `superseded`、exactly once；`session.send` ack 必须含 `applied_context_version` + `applied_context_mode`，core 仅在 version/mode 匹配后置 `injected`。
- 真实模型输出冒烟（用真实供应商端点）**未执行**：严格 `system_replace` 的 Claude/Codex 限制已由请求体确定；v1.2 默认 `message_append`/`origin_fork` 的真实模型输出在 M10-02 E2E 补测；不消耗真实 token。

## 2. mock/单测（26/26 通过）

脚本：`node scripts/test/m10-02/context-spike.mjs`

| 组 | 检查 |
|---|---|
| capability | 缺失 → `hold`/`capability_missing`，不调用 adapter；pending 保留、不静默丢失 |
| ack | `ack >= version` → `injected`；`none`/`stale`/`lower` → 保持 hold；失败后重试成功 |
| version | 注入 bump 单调（1..10）；fold bump（10→11）；重启不倒退 |
| fold | 最近 8 条原文 + 1 条摘要；摘要 ≤2KiB；总量 ≤16KiB；旧行保留 `folded_at`/payload |
| 重启 | 重发当前快照；不重复注入行（8→8）；版本不变（11→11） |
| 上限 | 显式 >16KiB → 拒绝；快照自动裁剪旧原文后 ≤16KiB（实测 15,722B） |
| N→1 | 同 batch 一行；`reject > needs_changes > approve > info`；findings 按 `(title,path,line)` 去重 |

> 该脚本是**spike 模型**，不进入生产代码；M10-02 实现时按 `subagent_injections` 表与 core 状态机落地，并复用本组断言。

## 3. 真实 CLI 结果

### 3.1 Claude Code：strict `system_replace` 条件通过（默认 message_append）

命令：`claude -p --output-format json ... --append-system-prompt-file <file>`；不使用 `--bare`（生产适配器当前形态），同一 `--session-id` 下 `--resume` 下发新文件。

**A. 默认 `--system-prompt-snapshot on`（生产适配器当前未传该参数）**

| 步骤 | 请求体 system 中的标签 | 结果 |
|---|---|---|
| new v1 | `version="1"`（唯一） | 通过 |
| resume v2 | **`version="1"`（旧块保留，v2 未进入）** | **失败** |
| resume v2 repeat | `version="1"` | **失败** |

**B. 首轮与 resume 均传 `--system-prompt-snapshot off`**

| 步骤 | 请求体 system 中的标签 | 结果 |
|---|---|---|
| new v1 (off) | `version="1"`（唯一） | 通过 |
| resume v2 (off) | `version="2"`（唯一，v1 不出现） | 通过 |
| resume v2 repeat (off) | `version="2"`（唯一，无重复） | 通过 |
| resume v3 (off) | `version="3"`（唯一） | 通过 |

结论：Claude Code 2.1.304 默认的 system prompt snapshot 会在 resume 时复用首轮记录；`--append-system-prompt-file` **不是默认替换**。传 `--system-prompt-snapshot off` 后，每次请求重新渲染，`--append-system-prompt-file` 表现为**替换**（最新块唯一）。因此该 flag 仅用于可选 `system_replace` 严格模式（首轮与 resume 同口径）；v1.2 默认 `message_append` 不需要该 flag。

### 3.2 Codex：strict system_replace 不支持（v1.2 改用 message_append）

命令：`codex exec --json ... -c developer_instructions="<aether:subagent-results version=N>" -`；同一 thread 下 `codex exec resume <thread> -` 下发 v2。

| 步骤 | 请求体 developer 中的标签 | 结果 |
|---|---|---|
| new v1 | `version="1"` | 通过 |
| resume v2 | **`version="1"`（新 `-c` 覆盖未进入请求）** | **失败** |
| resume v2 repeat | `version="1"` | **失败** |
| fork v3 | **`version="1"`（fork 同样保留首轮）** | **失败** |
| fresh v3（新 thread） | `version="3"` | 通过 |

补充：`codex debug prompt-input` 仅能证明**新会话**使用最新 `developer_instructions`。结论：Codex 0.163.0 的 resume/fork 不会用新的 `-c developer_instructions` 替换已持久化的 developer 指令；旧块仍在模型输入中。

**处置（ADR-032 v1.2）**：

- 这是 strict `system_replace` 的诊断；Codex 不支持该 mode，返回 `subagent_context_rejected`/hold，不静默降级。
- v1.2 默认 `message_append` 不改 `developer_instructions`，Codex `subagent_context=true`，`auto_inject` 允许；后台用 `origin_fork`。
- 旧结果作为 append-only message 保留，带 `version`/`supersedes`，靠 fold/compact 收敛；不得把旧块当用户指令。
- 若后续 Codex 提供 system prompt 替换型参数，可另立 ADR 开启 `system_replace`。

### 3.3 DSH：通过

- 真实 CLI：`dsh --version` = `0.2.1-rc.2`；`dsh aether-q5-spike --from-default-profile headless --dump-config` 成功（自定义 profile 可启动）。
- 机制：`@deepseek-ai/dsh-system-prompt/lib/index.js` 的 `assemble()` 对 `section.text` 做 `typeof === "function" ? section.text(context) : section.text`，即**每次 assembly 重新求值**；生产插件 `aether-dsh-prompt` 的 `text: () => readPrompt(...)` 每次读取侧信道文件。
- 单测：`packages/adapter-dsh/src/subagent-context-spike.test.ts` 验证同一 section 在文件 v1→v2 后返回最新内容，不重新注册、不出现旧块；`@aether/adapter-dsh` 全量测试 **51/51** 通过（6 个测试文件），`typecheck` 通过。
- 结论：DSH 支持 section 热更新，`subagent_context=true` 可支持 `auto_inject`。

### 3.4 缓存影响与可选注入模式（2026-11-06 追加）

Claude `--system-prompt-snapshot off` 能实现替换，但**不能保证大 system prompt 缓存命中**：

- 实测请求体：`cache_control: ephemeral` 的大 system 块为 **5,558 B**，包含 CWD/date + subagent 块；v1/v2/v3 内容哈希分别为 `28095e…` / `13d8c9…` / `bab28c…`，随 version 变化 → 该断点 cache miss。
- 稳定命中的只有 **94 B** 的 Claude identity 块（`You are Claude Code…`）；对长 system prompt/预设/记忆注入（M7-09）场景，cache 损失可能更大。
- 因此“替换型参数”只能做到“功能替换”，不能做到“保证缓存命中”。

| 模式 | 机制 | 缓存 | 旧块 | 适用 |
|---|---|---|---|---|
| `system_replace` | 改 system prompt 块（Claude snapshot off / DSH section） | 大 system 块 miss | 不保留 | 严格 only-latest；可接受 cache 损失 |
| `message_append` | 把 compact envelope 作为 **user/tool message** 追加，带 `version` + `supersedes` 标记 | 前缀稳定，cache best-effort 命中 | 历史中保留，标记 superseded，靠 fold/compact 收敛 | 默认；要求缓存前缀不失效 |
| `origin_fork` | 后台 delegation boundary 冻结 origin fork；callback = fork + 结果；新 ephemeral provider context | 回调可 miss | 不进入 live history；输出追加 | 后台/长任务；隔离优先 |
| `new_session` | 新 thread/会话 + 摘要 + 最新块 | 无缓存 | 不保留（但丢连续性） | 严格隔离；不要求缓存 |

主流 Agent（Claude Code Task/子 Agent、Codex 多 Agent、OpenAI Agents SDK handoff、LangGraph/AutoGen/CrewAI 等）通常采用 **append-only message/tool result** 或 **独立子会话**，不要求在父会话中替换 system 块并保持缓存命中；Aether 的 `subagent_context` 严格替换模式比主流更苛刻。

**已批准（2026-11-06）**：新增 `subagent_context.mode=message_append`/`origin_fork`/`system_replace`（ADR-032 v1.2），Codex/Claude 均不再降级；Claude 默认保持 `--system-prompt-snapshot on` 以保缓存，只在严格 only-latest 时使用 `system_replace`（仅对 subagent 会话加 snapshot off）。

## 4. Gate 结论

| 运行时 | `subagent_context` | 默认交付 | 依据 |
|---|---|---|---|
| Claude Code 2.1.304 | **true** | `message_append`/`origin_fork`；`system_replace` 可选（需 snapshot off） | 父 system prompt 不变；append-only 前缀稳定；严格替换 cache miss 仅诊断 |
| Codex CLI 0.163.0 | **true** | `message_append`/`origin_fork` | 不改 `developer_instructions`；append-only tool/user message；resume/fork 限制不再阻塞 |
| DeepSeek Harness 0.2.1-rc.2 | **true** | `message_append` 或 `system_replace` | section text 每次 assembly 重读 + 单测；两种模式均可 |

- **Q5 硬门禁（v1.2）**：隔离矩阵、结果 exactly once、`message_append` 父前缀不被主动破坏、`origin_fork` 后台 callback 不含 intervening turns、权限/审计、ack/version/supersedes/fold/restart。**缓存非硬门禁**：允许 `origin_fork`/`system_replace` cache miss。表中 `true` 为设计/mock 结论；**真实 CLI `message_append`/`origin_fork` E2E 在 M10-02 验收执行（不阻塞开工/M10-03）**。
- M10-02 实现时必须：
  1. 默认 `message_append`：compact envelope 作为 tool result/合成 user message，带 version/supersedes，旧行 `superseded`；父 system prompt 不变；
  2. 后台 `origin_fork`：delegation boundary 冻结 origin fork，callback 使用新 ephemeral provider context；不读 live history；
  3. `system_replace` 仅可选严格模式：Claude 需 `--system-prompt-snapshot off`，DSH section；失败不阻塞默认交付；
  4. 三运行时 `subagent_context=true`；不支持的 mode 返回 `subagent_context_rejected`/hold，不静默降级；
  5. ack 必须含 `applied_context_version` + `applied_context_mode`；`injected` 仅在 version/mode 匹配后置位；重启重发当前快照，不重复交付；fold 保留 payload，按需 `subagent_result_get`。
- 真实供应商模型冒烟（用真实 key）未执行；建议在 M10-02 E2E 前按用户环境补一次 Claude/DSH 的“模型只看到最新块/append-only 结果”输出级验证；Codex 的 append-only 路径需在 M10-02 实现中验证。

## 6. 风险/待决

- Claude 默认保持 `--system-prompt-snapshot on` + `message_append`；`--system-prompt-snapshot off` 仅用于严格 `system_replace`，会关闭 system prompt 记录/复用并可能影响 prompt cache/成本；M10-02 只在显式严格模式会话加 flag。
- Codex 不再 `false`/hold；默认 `message_append`/`origin_fork` 不改 `developer_instructions`。旧结果留在历史中，必须带 `version`/`supersedes` 并靠 fold/compact 收敛；不得把旧块当用户指令。
- 后台 `origin_fork` 为进程内状态；重启不可恢复时观测性拒绝，不回退 live history；callback 可 cache miss（隔离优先）。
- DSH 的真实模型冒烟未执行；插件热更新是请求组装层结论，仍需在 M10-02 E2E 中验证最终模型输出。

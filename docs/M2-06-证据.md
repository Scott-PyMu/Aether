## 4. 边界与偏离记录

1. **应用级退出编排归 M2-08（承接关系）**：本任务交付 D2 关闭序列的**存储侧五步**与运行期
   checkpoint 纪律。适配器终止段（`shutdown` RPC → TERM/KILL → `TerminateJobObject`/`taskkill`
   兜底）在 M2-08「孤儿清理与退出可靠性」中与 T11（适配器无响应退出 ≤10s）一并接入应用退出路径；
   本任务不改变 `aether-tauri` 现有退出行为。
2. **读连接关闭后的惰性重开（边界声明）**：`ReadPool::close` 拆除全部读连接以释放 WAL 读锁
   （checkpoint 前置条件）；之后读取按需重开只读连接——满足 D4「降级期读查询/诊断/备份可用」，
   且关停后无读取时保持零残留句柄。关闭窗口内若仍有并发读，checkpoint 返回 busy 并由退避重试覆盖。
3. **checkpoint 退避阻塞单写者（语义声明）**：`checkpoint_truncate_with_backoff` 为同步退避
   （`std::thread::sleep`），在写任务内执行期间写队列积压但保持 FIFO——与单写连接串行语义一致，
   不引入额外并发；默认配置最坏情形 ≤ 5 次 × 400ms。该常量级参数已在本证据记录。
4. **成功 TRUNCATE 的 `frames=0/0` 解释**：`PRAGMA wal_checkpoint` 返回行反映完成后的状态；
   TRUNCATE 成功后 WAL 已归零，故 `frames=0/0`。字节级证据以 shadow 日志
   `wal_bytes N→0` 与 DoD2 的文件断言为准（busy 场景下返回 `frames=72/72` 可交叉印证）。
5. **drain 超时的兜底顺序**：超时后终止写任务（写连接先随任务释放），再以临时写连接执行
   checkpoint；shadow 日志步骤顺序不变（步骤 3 的 detail 显式标注「写任务已终止；临时写连接」），
   不影响 DoD1 的五步顺序判定。
6. **新增错误变体**：store 层新增两个内部配置错误码 `invalid_checkpoint_config` 与 `invalid_shutdown_config`（D7 命令面错误码表未登记、不经 IPC 暴露）；`error.rs` 的变体/错误码矩阵测试已同步更新（3 项自检全绿）。
7. **无新增依赖、迁移或事件类型**：仅复用既有 `rusqlite` 与 `tokio`；`store.rs` 中的 `open_read_write` 仅重命名为 `open_writer_connection` 并提升为 `pub(crate)`，行为不变。

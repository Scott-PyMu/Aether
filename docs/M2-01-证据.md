## 2. DoD 逐条证据

### DoD1 状态机全转移单测；非法转移拒绝

命令与输出：

```
$ cargo test -p aether-core --lib session_state
running 7 tests
test result: ok. 7 passed; 0 failed; 0 ignored; 0 measured; 2 filtered out; finished in 0.00s
```

覆盖断言（`session_state.rs` 单测）：19 条合法边逐对校验、终态（completed/failed/cancelled）
无出边、`creating→running` 等非法边拒绝且状态不变、`can_transition` 与 `transition` 一致、
`SessionStatusChange` 小写序列化与 Display。

集成侧（真实存储 + 管线）：`m2_01_lifecycle::session_state_machine_end_to_end`（创建 →
idle → running → 回 idle → dispose→completed → 终态拒绝新 run 收 `session_closed`）。

### DoD2 并行发送 3 条 → 1 执行 / 1 排队 / 第 3 条 `session_busy`（集成）

```
$ cargo test -p aether-control --test m2_01_lifecycle -- --nocapture
running 10 tests
test parallel_sends_serialize_one_executing_one_queued_third_busy ... ok
test result: ok. 10 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.50s
```

断言链（测试源码 `m2_01_lifecycle.rs`）：第 1 条 `queued=false` 且执行器被立即派发
（0 许可阻塞）；第 2 条 `queued=true`；第 3 条 `Err(session_busy)` **且消息行数仍为 2**
（拒绝先于持久化，不产生孤儿消息）；放行后第 1 条 `succeeded`、第 2 条被自动提升并
`succeeded`、会话回 `idle`；`readback` 事件含 `session.created/status_changed/run.started/
run.completed` 且 seq 严格单调（先日志后广播）。

### DoD3 同一 `client_msg_id` 重发不重复；重启核心后重放同值仍不重复（ADR-005）

```
test idempotent_send_survives_core_restart ... ok
```

断言链：首次发送 `duplicate=false`；同核心重放 `duplicate=true` 且 `message_id/run_id`
与首次一致、消息行数 = 1；关闭管线 + 存储（模拟核心退出）→ 同一 `aether.db` 重开核心
（新 `StoreRuntime`/`EventPipeline`/`SessionManager`）→ 重放同值仍 `duplicate=true`、
消息行数 = 1、`message_by_client_msg_id` 可读回既有行。持久化去重由
`messages UNIQUE(session_id, client_msg_id)`（0002 迁移，ADR-005）兜底。

### DoD4 ack 快路径：消息与 run 行提交后立即 ack，不等模型（时序断言）

```
test ack_returns_after_commit_without_waiting_for_model ... ok
```

断言链：执行器被 0 许可永久阻塞；`send` 返回耗时 `< 1s`（实测毫秒级）；返回后按幂等键
可读到消息行、run 行已提交（`queued|running`）、助手消息不存在（模型未完成）→ ack 不等模型。

### DoD5 断流超时：120s 无事件 → run failed 且可重试（时钟注入）

```
test run_stream_timeout_fails_run_and_allows_retry ... ok
test event_activity_resets_stream_timeout ... ok
test background_tasks_track_events_and_watchdog_timeout ... ok
```

断言链：
- `ManualClock` 注入；`watchdog_once` 在 119.999s 不判超时，**恰好 120s** 判超时；
- run 行 `status=failed`、`error=run_stream_timeout`、`finished_at` 非空、
  `run_is_retryable(status)=true`；会话回 `idle`；
- `run.failed` 事件 payload：`error.code=run_stream_timeout`、`recoverable=true`；
- 超时后新消息可受理（可重试），旧阻塞任务迟到结果被忽略（`detach_and_prepare` 不匹配即丢弃）；
- 活动重置：事件（或 `touch_run`）后 2×119s 不判超时；后台任务用例验证真实
  `spawn_background`（看门狗 + 事件监听 + 降级中断监听）在 120s 后自动落 `failed`。

### DoD6 `runtime_retry` / `runtime_enable` 接入 `IpcBackend`（契约 `docs/M1-10-证据.md` §6）

```
$ cargo test -p aether-tauri --test runtime_control -- --nocapture
test runtime_retry_and_enable_are_wired_and_transition_states ... ok
test runtime_control_commands_keep_m1_08_validation_regression ... ok
test untrusted_requires_remedy_before_enable ... ok
test runtime_control_returns_core_not_ready_when_unwired ... ok
test error_mapping_matches_frozen_contract ... ok
test result: ok. 5 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.01s
```

原始回执（--nocapture）：

```
[m2-01-ipc] 首次启动 outcome=Failed { reason: StartFailed, detail: "spawn 失败：无法启动适配器进程: 系统找不到指定的文件。 (os error 2)", stderr_tail: [] }
[m2-01-ipc] runtime_retry report={"detail":"start_failed：spawn 失败：无法启动适配器进程: 系统找不到指定的文件。 (os error 2)","outcome":"failed","runtime_id":"mock","status":"disabled","status_reason":"start_failed"}
[m2-01-ipc] runtime_enable report={"detail":"start_failed：spawn 失败：无法启动适配器进程: 系统找不到指定的文件。 (os error 2)","outcome":"failed","runtime_id":"mock","status":"disabled","status_reason":"start_failed"}
[m2-01-ipc] reject_untrusted outcome=Rejected { detail: "第三方 manifest" }
```

断言链：
- 白名单不命中 → `invalid_enum`；`cold` 上 retry → `invalid_value`；`untrusted` 上
  enable/retry → `invalid_value`（`NeedsRemedy`/`RetryNotAllowed`）；未接线 → `core_not_ready`；
- `disabled + start_failed` 上 retry：命令受理并完成
  `disabled → cold → starting → disabled(start_failed)` 转移（回执携带当前状态与原因）；
- M1-08 校验矩阵回归：未知字段 → `unknown_field`、非法 `runtime_id` → `invalid_format`、
  缺字段 → `missing_field`，且校验失败不触碰监督器状态（仍 `cold`）。

> 生产接线说明：`build_backend` 以空注册表监督器接线（M2-01 无真实适配器 spec）；
> M2-02 注册 Claude Code spec 后，同一命令路径即可驱动真实 `disabled→…→ready` 转移。

## 5. 边界与偏离记录

1. **`aether-control` 新增依赖 `aether-security`**：权限决策层（矩阵/路径/审批票据）保持
   在 `aether-security`（仅依赖 core 的纯模型）；审批持久化/超时/审计的编排在 control。
   依赖方向 `core → security/store → control → tauri`，无环、无反向依赖（AGENTS §2.1）；
   `Cargo.lock` 仅新增内部路径边，无新增外部 crate。
2. **M1-02 契约测试 schema 源扩展**：`columns_set` 由「仅 0001」改为「0001 + 0002 增量列
   （数据驱动解析 `ALTER TABLE ... ADD COLUMN`）」，以对齐 ADR-005 已批准的
   `messages.client_msg_id` 列；断言未放宽（仍要求实体字段与有效 schema 双向一致）。
3. **`WriteMessage::Command` 使用 `Box<StoreCommand>`**：`clippy::large_enum_variant`
   修复，仅尺寸优化，无行为变化。
4. **`runtime_retry`/`runtime_enable` 桥接**：async 服务 → 同步 `IpcBackend`，采用
   「spawn 到核心运行时 + `std::sync::mpsc` 等待 + 30s 硬超时」（M1-10 §6.2 授权 M2-01
   选择桥接方式）；不阻塞运行时线程。

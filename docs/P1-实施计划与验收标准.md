## 0. 阅读规则

- 任务 ID 格式：`M<里程碑>-<序号>`；`★` 标记关键路径任务。
- DoD 全部可执行验证，验证方式限定为：单测 / 集成 / E2E / 故障注入 / 脚本 / 检查；禁止「完成开发」类表述。
- 每个任务证据归档至 `docs/M5-xx-证据.md`…（编号随任务）；提交信息引用任务 ID。
- 门禁不通过时执行 §6 对应「回退动作」；回退动作均引用设计文档已定义的失效路径或范围纪律，不新增决策。
- **P0 回归基线**：P0 的 Gate 1–4、T1–T15 与 30 场景演练口径不变；P1 不修改 P0 验收语义，仅在 P1 代码基线上复跑（M8-01/M8-03）。
- **跨平台故障注入统一 helper**：沿用 P0 约定（Unix `SIGKILL`；Windows Job Object `TerminateJobObject` 优先 / `taskkill /T /F` 兜底；卡死用 Mock 不响应模式；不依赖 `SIGSTOP`）。
- **信任级边界**（设计 §2.1）：P1 仍为信任级安全模型，权限门仅约束经线协议上报的工具调用；任何 P1 文档与 UI 不得表述为「已隔离适配器内部行为」。

## 6. P1 门禁（阶段退出标准）判定与回退动作

**通过条件**

1. 设计文档 §5 P1 退出标准通过（证据归档；ADR-013 修订版）：
   - 三运行时一致性测试包全绿（ADR-008；M7-05）；
   - 加密备份恢复演练脚本通过（M5-03）；
   - 规则引擎误配率 <5%（抽查；M6-02）。
2. 本计划**门禁任务**（M5–M8 除 §8 直接实施项）全部 DoD 通过（含 P0 回归：T1–T15 在 P1 基线复跑）；**§8 直接实施项（M7-07/08/09）不构成门禁条件**（ADR-012 决策 7、ADR-014 决策 2）；数据事故按定义核查在测试执行窗口零记录（M8-03 核查，M8-01 夜跑日志与诊断包为证据源；非日历门槛）。
3. 门禁证据定义（ADR-012）：P1 进入时核对 P0 验收通过结果；P1 通过时归档本阶段验收报告与证据索引，作为 P2 进入证据。

**回退动作**

- 一致性未全绿 → 停止进入 P2；按运行时修复并归档复跑证据；不得按 ADR-008 §5 分层静默豁免（分层仅用于运行期隔离，门禁前必须全绿）。
- 加密备份演练失败 → 冻结发布路径；按 D13 恢复流程七步逐项审计定位；修复后重跑；两轮未过 → 评审加密方案（改 ADR 换方案）。
- 数据事故发生（含执行窗口台账记录）→ 立即修复 + 复盘；按 D3/D4 失效路径处理；涉及设计缺陷 → 另立 ADR；修复闭环前冻结对外发布路径（ADR-013 §7）。
- 误配率 ≥5% → 规则引擎降级（停用自动应用、保留固定矩阵 + 建议模式），修复后重新抽查。
- 同一项累计两次不通过 → 触发设计 §4 范围纪律（砍一项换一项）并重评 P1。
- **M5-06（已于 R16 延后至 P2）** 结论为「需分库」→ 另立 ADR 并作为 **P2** 交付输入（D3 失效条件路径）；**不影响 P1 门禁**。
- **§8 直接实施项（M7-07/08/09）若影响门禁主链**（占用关键路径或阻塞 M8-01/M8-03 资源）→ 按直接实施项性质降级为「P1 内不承诺」，**不得因它们推迟 P1 门禁证据归档**（ADR-014 §6-5）。
- **决策 3（权限模式）被单独否决** → 三档不落地，或按 v0.1 收紧口径重提（区外 `fs.write` = `ask`、`exec`/`net` 恒 `deny`）；**不得以 UI 兜底**（ADR-014 §6-2）。

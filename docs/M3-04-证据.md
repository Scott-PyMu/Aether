## 1. 契约登记（实现增量，非设计偏离）

### 1.1 `backup_create` 外部目标目录（D13 / ADR-003 决策 19）

| 项 | 值 |
|---|---|
| 请求 | `{ label?: string(≤128), target_dir?: string }`（`deny_unknown_fields`；DTO/校验矩阵沿用 M1-08 框架） |
| 来源 | 外部目录经系统目录选择器获取；**复用 `startup_pick_target`**（M1-06 `DirectoryPicker` 抽象的生产实现），未新增命令——D7 命令面保持 **35 条目 / 36 命令** 不变 |
| 校验 | `path::validate_backup_target_dir`：绝对路径 + Windows 特殊形态拒绝 + canonicalize + 存在目录；同步盘不拒绝（备份到云端目录是 D13 允许的合理用法） |
| 空间护栏 | 可写探针 + `可用空间 ≥ 当前 db+wal ×1.2`（常量 `SPACE_MARGIN_NUMERATOR/DENOMINATOR = 6/5`，与迁移共用 `disk` 探针）；不足拒绝（业务码 `backup_space_insufficient`） |
| 产物 | `VACUUM INTO <target>/aether-<ts>.db`（同毫秒冲突追加 id 尾缀）；登记 `backups` 台账（`kind=internal/external`）+ 保留最近 10 份（文件与行一并清理） |
| 降级期 | `VACUUM INTO` 经**只读连接**执行（D4：`persist_degraded`/安全模式备份入口可用；写队列关闭时跳过台账登记与审计，不阻断备份产物） |

### 1.2 `backup_list` 响应

`{ backups: [{id,path,size_bytes,encrypted,kind,created_at}], capacity: {db_bytes,wal_bytes,total_bytes,warn_bytes:2GiB,critical_bytes:5GiB,level:ok|warn|critical} }`（`backups` 按 `created_at` 降序）。容量等级口径 = D13 的 2GB 警告 / 5GB 强提示（M3-05 巡检复用同一阈值常量语义）。

### 1.3 `backup_restore` 流程与响应（D13 七步）

| 步 | 执行位置 |
|---|---|
| 1 输入 | 命令层：`source` = 内部备份 id（ULID 格式层）或外部 `.db`（canonicalize + 存在性 + 后缀） |
| 2 校验候选 | 后端（`validate_candidate`）：只读打开 + `quick_check` + `schema_migrations` 最大版本；高版本 → `backup_candidate_newer`（提示升级程序）；损坏 → `backup_candidate_invalid` |
| 3 停写 | **下次启动序列**：存储尚未打开，无写者（D13 语义天然满足；引擎保留 `stop_writes` 步回调并在报告中留证） |
| 4 现场保护 | 启动序列：`aether.db`/`-wal`/`-shm` 改名 `.pre-restore-<ts>`（先写现场日志再改名，kill 后可按日志回滚） |
| 5 就位 | 候选复制到同目录临时文件（写句柄 `sync_all`）→ 原子 `rename` |
| 6 验收 | `Store::open`（quick_check + 迁移到当前版本）；任一步失败 → 回滚现场三件套并清理日志 |
| 7 重启 + 审计 | 命令层 `request_restart()`（复用 M3-06 机制）；启动序列完成后写审计 `backup.restore`（`requested`/`completed`/`failed`/`rolled_back`） |

响应（命令回执）：`{ restoring:true, restart_required:true, source:"internal"|"external", candidate:{path,size_bytes,schema_version}, db_path }`。重启前命令**不修改数据库**；恢复失败时应用以旧库继续启动（错误进日志与审计）。

### 1.4 中断恢复（DoD4）

恢复现场日志 `<db>.restore-journal.json` 状态机：`requested → placing → done`。`kill -9` 中断后下次启动读取日志：`placing` → 按日志现场回滚（`InterruptedRolledBack`）；`requested` → 执行 3–6 步（`Applied`/`Failed`）；`done` → 仅清理日志。原位（`.pre-restore-*`）**保留不删除**（现场三件套可人工回退）。

### 1.5 存储错误码（aether-store 内部；IPC 码不新增）

`backup_not_found` / `backup_candidate_invalid` / `backup_space_insufficient` / `restore_journal_invalid`。IPC 面按 M3-03 口径以 `invalid_value` + 消息内稳定业务码呈现（`backup_candidate_newer` / `backup_candidate_invalid` / `backup_not_found` / `backup_space_insufficient` / `backup_target_not_writable` / `backup_restore_journal_invalid`），不扩展 `IpcErrorCode` 枚举（T14 错误码面不变）。

### 1.6 路径规范化（附带修正）

`ipc::path::canonicalize_checked` 返回值统一剥离 Windows `\\?\` verbatim 前缀（UNC 输入此前已被拒绝），保证「选择器原始路径 → canonicalize → 回传/落盘」闭环可序列化，与 `startup::detect` 既有口径一致。

### DoD2 恢复七步逐项断言（`-wal`/`-shm` 改名、`.pre-restore` 保留、失败回滚）

**验证方式**：`seven_steps_rename_scene_and_retain_pre_restore_files` + `failure_after_placement_rolls_back_scene`（故障注入 `FailAfter`）。

**输出**：见 DoD1 的 `m3_04_backup` 运行（两用例均 ok）。断言内容：

- 步骤序 `validate_candidate → stop_writes → place_candidate → verify`（含 `protect_scene`）全部 `ok=true`；停写回调被实际调用；
- 库/`-wal`/`-shm` 三件套全部改名至 `.pre-restore-<ts>` 且内容保留（`.pre-restore` 文件 3 个）；
- 验收后 journal 状态 `done`，由调用方 `finalize_restore` 清理；
- 注入失败后：错误消息含「已回滚现场」，旧库指纹与恢复前一致，`-wal` 内容还原，`.pre-restore` 无残留，journal 已清理。

## 4. 边界与偏离记录

1. **E2E 分层口径（与 M3-03 一致）**：DoD6 的「命令 → 恢复七步（含核心重启）」由两层证明——(a) 命令层 mock invoke：严格解析 / 路径 canonicalize / 下游零调用 / `restart_required` + 现场日志登记；(b) 真实存储链：恢复请求 → 关闭存储（退出序列）→ 清库 → `boot_apply_pending_restore` 执行 3–6 步 → 审计。`handle.request_restart()` 的真实触发依赖 `tauri::AppHandle`（Wry 运行时，mock 运行时不可注入），与 M3-06 `app_restart` 共用同一机制，真实 WebView2 重启链路由 M3-06 E2E 已覆盖；内存/WebView 级恢复冒烟归 M4-04/M4-05。
2. **`backup_create.target_dir` 为可选新增字段**（并入 D13 已定义能力，非新命令）：外部目录选择复用 `startup_pick_target`，D7 命令面计数不变（35 条目 / 36 命令，M4-04 口径可直接复核）。
3. **`label` 不落库**：`backups` 表（附录 C）无 label 列；标签仅用于命令校验与界面提示（若后续需持久化，走迁移 0003+ 与 ADR 流程）。
4. **恢复在重启后执行**（第 3–6 步移入启动序列）的原因：D13 第 3 步要求「关闭全部连接与写队列」；启动序列在存储打开前天然无写者，避免运行中拆库与双写风险，并将「恢复中断 → 回滚」收敛到同一入口（DoD4）。
5. **安全模式（`quick_check` 失败）启动失败路径**：`degraded_backend` 现有架构不含存储句柄，`backup_create` 回 `core_not_ready`；`Store::backup_to`（只读连接）的安全模式入口保持（M1-03）。运行期 `persist_degraded`（写队列关闭、读池在）经只读连接备份可用（D4）。启动失败态的备份 UI 接线随 M4-02（T8 演练）复核。
6. **`\\?\` 前缀剥离**：`ipc::path` 的 canonicalize 结果统一剥离 verbatim 前缀（§1.6）；影响面为所有路径类命令的返回值展示/回传，`validate_user_path` 的根目录比较同步按剥离后口径（ipc_validation 全量回归通过）。
7. **容量等级只在 `backup_list` 投影**：2GB/5GB 阈值常量在 `backup_control` 中导出；M3-05 巡检/横幅以同一语义实现（DoD2 容量模拟归 M3-05）。
8. **保留策略清理文件失败不阻断**：台账行删成功而文件删除失败时记录 `tracing::warn`（避免因外部文件权限导致备份动作整体失败；残留文件不参与清单）。
9. **装饰器链路委派修正（M3-04）**：`SessionBackend`（生产链路最外层）此前未覆写 `runtime_retry`/`runtime_enable`/`settings_*`/`workspace_set`/`export_diagnostics`/`backup_*`，会命中 trait 默认 `not_implemented` 而掩盖内层实现。本任务补齐显式委派（不改变任何内层语义），并以 `production_chain_delegates_backup_commands` 锁定；该修正同时使 M3-03 的运行面板重试/启用命令在真实链路可达（本任务只做透传，不改其语义）。

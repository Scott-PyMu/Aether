# 适配器接入指南

> 面向适配器开发者与维护者。所有适配器与核心之间只经 **JSON-RPC 2.0 over JSON-Lines**
> （Aether 线协议 1.0，设计 D6）；不得绕过线协议访问核心内部状态（AGENTS §2.6）。

## 1. 运行形态

- 一适配器一常驻进程，由核心监督器（D5）spawn：独立进程组（Unix `setsid` /
  Windows `CREATE_NEW_PROCESS_GROUP`），Windows 同时纳入 Job Object（仅进程树回收，
  非沙箱）。
- 进程启动 10s 内必须发出 `hello`（含 `protocol: "1.0"` 与 runtime 信息）；major
  不匹配 → 核心置 `disabled + status_reason=version_mismatch` 并给升级提示。
- stdout 只允许线协议帧；日志一律走 stderr（`stdout 混入日志`按无效帧计数）。
- 单帧硬上限 **2MiB**（超过立即断连记错，不缓冲）；附件一律以 `artifact_ref`
  引用帧上报（引用帧本身必须 <1MiB；数据体不进线协议）。
- JSON-RPC 外层未知成员被忽略；未知方法回 `-32601` 不**断连**；归一化后的
  事件信封顶层未知字段被拒绝。

## 2. 推荐接入方式（TypeScript SDK）

官方适配器基于 `packages/adapter-sdk` 与 Bun 单文件编译（目标机无需 Node）：

```
packages/adapter-sdk/src/adapter.ts    # 线协议宿主（读循环/写单写者/日志）
packages/adapter-sdk/src/envelope.ts   # EventEnvelope v1（9 字段）构造
packages/adapter-sdk/src/protocol.ts  # 方法/错误码常量（含 20 次无效帧阈值）
```

最小骨架（参考 `packages/adapter-mock/src/main.ts`）：

1. 继承/组装 `Adapter`，声明 `runtime`（id/name/version/capabilities）；
2. 实现方法表（核心→适配器）：

   | 方法 | 超时 | 说明 |
   |---|---|---|
   | `initialize` | 10s | 配置下发、能力上报（如 `thinking_depth`） |
   | `session.create` | 30s | 返回原生会话 id（`native_id` 用于 Mode R 恢复） |
   | `session.send` | 30s（ack 快返回） | `client_msg_id` 幂等；流式经由事件上报 |
   | `session.interrupt` | 5s | 中断当前 run（SIGINT/终止运行时子命令） |
   | `session.dispose` | 15s | 优雅关闭会话并清理派生资源 |
   | `tools.list` | 10s | 工具发现 |
   | `permission.resolve` | 5s | 下发审批结果 |
   | `health.ping` | 5s | 心跳（10s 周期，连续 3 次失败触发重启） |
   | `shutdown` | 5s | 优雅退出 |

3. 事件上报：`event` 通知，信封固定 9 字段 `v/id/session_id/run_id/runtime_id/
   seq/ts/type/payload`，类型只能取自设计附录 B（禁止自造事件类型）；
4. 权限回环：文件类/执行类工具调用必须发 `permission.request` 通知并等待核心
   `permission.resolve`（100% 回环、零直通；不得假装回环、不得绕过）；
5. 应用码：1001 崩溃 / 1002 超时 / 1003 版本不匹配 / 1004 能力缺失 / 1005 会话不存在。

## 3. 会话恢复与重放（Mode R / Mode N)

- `session.create` 返回的原生会话 id 由核心存于 `sessions.config.native_id`；
- **Mode R**（原生恢复）：运行时崩溃/重启后用 `native_id` 恢复原生会话续聊；
- **Mode N**（无原生恢复）：新建原生会话并重放输入，UI 明示「原生上下文可能丢失」。

## 4. 注册与分发（安装产物内注册）

- 官方运行时集合冻结为三：`claude-code` / `codex` / `deepseek-harness`（ADR-008）；
  `mock` 仅测试构建；
- 安装产物携带只读注册清单 `runtime-bundle/runtimes.json`（ADR-015 §2.2 schema）：

  ```json
  {
    "schema_version": 1,
    "runtimes": [
      {
        "id": "claude-code",
        "name": "Claude Code",
        "kind": "claude-code",
        "version": "0.1.0",
        "protocol": "1.0",
        "program": "aether-claude-adapter.exe",
        "args": []
      }
    ]
  }
  ```

- 加载校验（P0 子集）：严格 schema（未知字段拒绝）、官方 id 白名单、`program`
  相对路径 + canonicalize 不逃逸清单目录；条目失败跳过并告警，不阻塞应用启动；
- 构建期生成：`node scripts/ci/build-runtime-bundles.mjs`（含摘要 `digests.json`）。

## 5. 新增适配器检查清单

- [ ] manifest 命中官方白名单（仅官方运行时；第三方一律 `untrusted`）
- [ ] `hello` 10s 内发出且 `protocol: "1.0"`
- [ ] 一致性测试全用例（`m1_09_consistency` 口径：握手/流式/中断/dispose/工具）
- [ ] 健壮性注入 5 类（半行/坏 JSON/超长行/stdout 日志/版本不匹配）
- [ ] 权限回环（`permission.request` → `permission.resolve`）零直通
- [ ] 会话恢复模式结论（Mode R/N）与重放重试语义
- [ ] 单帧 2MiB / `artifact_ref` <1MiB 契约
- [ ] `cargo test` 全绿 + `pnpm verify:m1-09` / 对应任务验证入口通过

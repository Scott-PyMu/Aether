## 1. 总体结论

**文档完整性（较好）**：决策表 + 三段五段式（A/B/C）+ 影响/版本/未决项/回退条件/范围对价/变更记录齐备；附录 A–E 给出可直接施工的拟合入文本；§1.2 六处代码引用与实现事实**逐条核验全部准确**（见 §0）。

**一致性状态（不通过）**：发现 **1 P0 / 4 P1 / 7 P2**：

1. **P0（需求-设计-验收链路断裂）**：决策 1「不提供安装/卸载入口」与决策 4「用户可写清单一律不加载」，与需求 CP-01 验收口径（「可通过配置文件或插件动态添加」）及设计附录 A CP-01 行（「P1：安装/热插拔 UI」）冲突；ADR §3.2 仅留「如评审要求补注」的口，未闭环。
2. **P1（验证不可证明/边界未定义）**：①`runtimes.enabled` 迁移与 `verify:m1-03` 复跑责任在 M5-01/M7-01 之间自相矛盾；②在途定义含 `queued` run，但收口只登记了活跃 run 的断连语义；③注册清单与 P0 M4-05 注册产物的接口一致性义务未登记；④`program`「非用户可写位置」无判定口径。
3. **P2**：新命令 bindings/校验矩阵义务、`RuntimeControlReport.outcome` 取值域登记、合入文本与基线同步（AGENTS/ADR-006/设计文档头部）、P1-A03 双登记、UI-UX 拟合入目标与计数、归段对 `SessionId` 弱校验的依赖加注。

**最大风险**：**注册清单校验是官方运行时可用性的单点**——路径判定口径缺失 + 与 P0 产物（M4-05）接口未定界，任一不齐都会以「官方条目被拒 → 空注册表/不可用」（ADR 自列首要风险）的形式落地；其次是 CP-01 三方口径冲突将使 P1 验收无法唯一判定。

**结论**：**不通过**。ADR 主体（状态机增量、在途处置、归段口径、回退条件）方向可执行，但修订 P0-1 与 P1-1…P1-4 后方可合入；修订属文本改写与登记补充，无需新决策点（P0-1 的处置方式需产品裁定，见 §5）。
